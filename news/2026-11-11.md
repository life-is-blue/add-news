## 1. OpenHarness CLI 0.6.16 为多智能体 Swarm 加入超时回收与工作优先级

![OpenHarness CLI 0.6.16 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/autonomous-ai/openharness/releases/tag/v0.6.16_cli)

*图片来源：[OpenHarness 官方 GitHub 发布页](https://github.com/autonomous-ai/openharness/releases/tag/v0.6.16_cli)*

OpenHarness CLI 0.6.16 会对领取任务后闲置 20 分钟的智能体发出一次提醒，闲置满一小时则把任务退回队列。Swarm v4 现在优先处理智能体自己的拉取请求和待完成的读取，再分配下一项任务，并在当前回合结束时直接输入下一任务。Model Manager 的扫描范围也收窄为已配置引擎，不再遍历所有本地服务。

**为什么值得关注：** 多智能体协作最容易被“任务已领取但无人推进”拖死；明确的提醒、回收与优先级规则让 Swarm 更接近具备背压和故障恢复的生产级调度器。

- **原文：** [OpenHarness CLI v0.6.16 Release](https://github.com/autonomous-ai/openharness/releases/tag/v0.6.16_cli)
- **发布日期：** 2026-11-11
- **时间范围：** 过去 24 小时

## 2. Volcano Agent SDK 1.1.0 加入本地 MCP、保守并行工具调用与实时回调

![Volcano Agent SDK 1.1.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/Kong/volcano-agent-sdk/releases/tag/v1.1.0)

*图片来源：[Kong Volcano Agent SDK 官方 GitHub 发布页](https://github.com/Kong/volcano-agent-sdk/releases/tag/v1.1.0)*

Volcano Agent SDK 1.1.0 新增 stdio MCP 传输，可自动启动、复用和清理本地 MCP 子进程，并在同一工作流中混合使用 stdio 与 HTTP/SSE 服务。运行时会在判断资源相互独立时并行执行工具调用，存在潜在依赖时退回串行，同时提供逐 token 和逐工具完成回调。版本还为长时工作流加入 OAuth 自动刷新，并允许用自然语言查询执行结果、工具使用与错误。

**为什么值得关注：** 该版本把本地工具接入、并发安全、可观察性和长时认证放进同一个 SDK 控制面，正面覆盖生产智能体最常见的四类运行时问题。

- **原文：** [Volcano Agent SDK v1.1.0 Release](https://github.com/Kong/volcano-agent-sdk/releases/tag/v1.1.0)
- **发布日期：** 2026-11-11
- **时间范围：** 过去 24 小时
- **项目状态：** 官方仓库已标记为只读归档；本条依据其签名发布页记录

## 3. Browser Use 1.0.2 让 MCP 在未开启 Chrome 远程调试时自动接管 Chromium

![Browser Use 1.0.2 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/browser-use/browser-use/releases/tag/1.0.2)

*图片来源：[Browser Use 官方 GitHub 发布页](https://github.com/browser-use/browser-use/releases/tag/1.0.2)*

Browser Use 1.0.2 在 Chrome 未开启远程调试时，不再让 `browser-use --cli-mcp` 停在配置步骤，而是自动驱动自带 Chromium，并告诉智能体如何切换到用户 Chrome。CLI 与 MCP 的 CDP 调用统一等待 20 秒，遇到 JavaScript 对话框冻结页面时会快速失败并给出处理提示。版本还修复 Windows 中 `browser_exec` 的 UTF-8 文件读写，并加入脱敏后的反馈工具供智能体报告问题。

**为什么值得关注：** 浏览器智能体经常败在环境启动和页面阻塞，而非推理本身；自动回退到可控浏览器、统一超时和显式对话框错误能显著减少无人值守任务的假死。

- **原文：** [Browser Use v1.0.2 Release](https://github.com/browser-use/browser-use/releases/tag/1.0.2)
- **发布日期：** 2026-11-11
- **时间范围：** 过去 24 小时

## 4. Adobe 预告 Creative Cloud 本地 MCP，让第三方智能体直接编辑原生工程文件

![Adobe Creative Cloud 智能体与 MCP 官方公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://news.adobe.com/news/2026/11/adobe-powers-new-era-of-creativity)

*图片来源：[Adobe 官方公告](https://news.adobe.com/news/2026/11/adobe-powers-new-era-of-creativity)*

Adobe 宣布预览 Photoshop、Illustrator、Premiere 和 After Effects 的本地 MCP 集成，让第三方智能体在用户电脑上直接修改原生项目文件，同时保留图层、序列与合成的可编辑结构。Creative Agent 也扩展到 Illustrator、Premiere、InDesign、After Effects 和 Frame.io，用自然语言编排多步骤创作任务。Adobe 另行预览可在后台持续整理素材、检查质量和准备多渠道内容的常驻智能体。

**为什么值得关注：** MCP 正从读取企业数据转向操作高价值专业创作文件；“本地执行、原生结构可编辑”提供了一条兼顾智能体自动化与专业人员可逆控制的路径。

- **原文：** [Adobe Powers a New Era of Creativity](https://news.adobe.com/news/2026/11/adobe-powers-new-era-of-creativity)
- **发布日期：** 2026-11-10
- **时间范围：** 过去 24 小时
- **发布状态：** 本地 MCP 与常驻智能体为预览能力

## 5. Goose 1.58.1 修复 Opus 5.5 拒绝上下文压缩及 Databricks 凭据过期

![Goose 1.58.1 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/aaif-goose/goose/releases/tag/v1.58.1)

*图片来源：[Goose 官方 GitHub 发布页](https://github.com/aaif-goose/goose/releases/tag/v1.58.1)*

Goose 1.58.1 重写上下文压缩提示，避免 Opus 5.5 把压缩请求判定为不允许的“蒸馏”任务而拒绝执行。版本也会在 Databricks OAuth 令牌到期前主动刷新，减少长会话中途失去模型连接。该补丁紧随 1.58 系列发布，直接针对长程运行的连续性问题。

**为什么值得关注：** 长任务依赖压缩维持上下文预算，也依赖凭据持续有效；两处失败都会让智能体在最昂贵的执行阶段突然中断，因此这类修复比表面功能更新更影响实际完成率。

- **原文：** [Goose v1.58.1 Release](https://github.com/aaif-goose/goose/releases/tag/v1.58.1)
- **发布日期：** 2026-11-10
- **时间范围：** 扩展至过去 72 小时
