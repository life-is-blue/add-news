## 1. Claude Sonnet 5.5 发布：编码性能跃升，速度更快、成本更低

![Claude Sonnet 5.5 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.anthropic.com/claude-sonnet-5-5)

*图片来源：Anthropic 官方发布页*

Anthropic 发布 Claude Sonnet 5.5，称其比 Sonnet 5 快 30% 以上，并在多数任务中最多降低 30% 成本；模型提供 100 万 token 上下文，API 价格为每百万输入/输出 token 2/10 美元。官方评测显示，其 Terminal-Bench 4.0 得分从 Sonnet 5 的 10.3% 提升至 70.6%，CursorBench 4.0 达 55.5%；在 Claude Code 与应用中默认使用 Medium effort。GitHub 同日确认该模型已进入 Copilot，覆盖 IDE、CLI、Coding Agent、网页和移动端，但将分批开放。

**为什么值得关注：** Sonnet 5.5 把接近高端模型的编码能力下放到更低的单任务成本区间，可能直接改变团队在“架构模型 + 高频执行模型”之间的分工与预算配置。

- **原文：** [Introducing Claude Sonnet 5.5](https://www.anthropic.com/claude-sonnet-5-5)
- **交叉核验：** [Claude Sonnet 5.5 in GitHub Copilot](https://github.blog/changelog/2026-09-28-claude-sonnet-5-5-in-github-copilot/)
- **发布日期：** 2026-09-28

## 2. Claude Code 2.1.284：MCP 一键重连，并收紧插件预授权边界

![Claude Code 2.1.284 发布页](https://opengraph.githubassets.com/1/anthropics/claude-code/releases/tag/v2.1.284)

*图片来源：Anthropic / GitHub 官方发布页*

Claude Code 2.1.284 集成 Sonnet 5.5，并新增 `/mcp reconnect all`，可一次重试所有连接失败或需要重新认证的 MCP 服务。安全方面，第三方插件在托管策略 `allowManagedPermissionRulesOnly` 下不再能自行通过 `allowed-tools` 预授权工具；版本还修复 MCP 恢复会话时工具尚未连上导致的调用失败、过载错误不重试、压缩后仍持续报提示过长，以及沙箱和工作区信任等问题。新版本也为工作目录外的单次读取增加“本次允许、下次仍询问”的权限选项。

**为什么值得关注：** 这次更新同时改善了 MCP 的运行恢复能力与插件权限隔离，正好覆盖生产级编码智能体最容易出问题的两个边界：工具可用性和隐式授权。

- **原文：** [Claude Code v2.1.284 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.284)
- **发布日期：** 2026-09-28

## 3. Codex CLI 0.159.0：支持实时打断与转向，强化沙箱凭据保护

![Codex CLI 0.159.0 发布页](https://opengraph.githubassets.com/1/openai/codex/releases/tag/rust-v0.159.0)

*图片来源：OpenAI / GitHub 官方发布页*

OpenAI 发布 Codex CLI 0.159.0，新增可选的 `instant_interrupt`：用户在模型回复或长时间代码工具调用期间输入新指令时，可立即打断并转向当前任务。版本还加入更紧凑的新会话界面、原生 Mermaid 渲染改进和线程历史锚点分页；安全修复包括保留获批命令中的显式文件系统拒绝规则、默认保护可写根目录下的 `.aws`，并在重连时维持执行器 MCP 凭据边界。Windows 端也减少 MCP、代码模式宿主和管道命令产生的多余控制台窗口。

**为什么值得关注：** “执行中可转向”让人机协作从等待回合结束变成实时监督，而文件系统拒绝规则与云凭据目录保护则降低了高自主运行时的误操作半径。

- **原文：** [Codex CLI 0.159.0 Release](https://github.com/openai/codex/releases/tag/rust-v0.159.0)
- **发布日期：** 2026-09-29

## 4. OpenClaw 2026.8.33 扩展稳定版：安全回补与新模型支持进入 LTS 线

![OpenClaw 2026.8.33 发布页](https://opengraph.githubassets.com/1/openclaw/openclaw/releases/tag/v2026.8.33)

*图片来源：OpenClaw / GitHub 官方发布页*

OpenClaw 发布网关专用的 2026.8.33 `extended-stable` 版本，将其定位为当前等同 LTS 的稳定分支：基于 8 月底代码，回补关键安全、可靠性和性能修复，并加入最新模型支持。该版本把 GPT-6 Astra、Fable 5.1、Muse Spark 1.3 等纳入稳定线，补齐 GPT-5.6 家族的路由、迁移、视觉和推理行为；安全汇总则覆盖 Prometheus 指标授权、Discord 媒体与语音所有权，以及 Nodemailer 依赖漏洞。它还修复显式启用 Skills 在自动更新后丢失、生成图片因后续工具失败而消失等问题。

**为什么值得关注：** OpenClaw 正把快速演进与生产稳定性拆成两条发布轨道；对企业网关部署而言，可预测的安全回补和模型兼容性比追逐最新版更重要。

- **原文：** [OpenClaw 2026.8.33 Release](https://github.com/openclaw/openclaw/releases/tag/v2026.8.33)
- **发布日期：** 2026-09-29

## 5. NVIDIA 推出 Open Agent Safety Platform：把智能体控制下沉到运行时与硬件【扩展至过去 72 小时】

![NVIDIA Open Agent Safety Platform 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://nvidianews.nvidia.com/news/open-agent-safety-platform)

*图片来源：NVIDIA 官方新闻稿*

NVIDIA 发布 Open Agent Safety Platform，由开源运行时 OpenShell 与 BlueField-4 DPU 上的 Sentry 参考设计组成。OpenShell 在模型和 Harness 之外提供默认拒绝、可审计的沙箱与策略边界，并可扩展到 Arm、Intel 平台；Sentry 则在独立硬件信任域中持续监控，宣称可在毫秒级隔离越界智能体。NVIDIA 表示 Anthropic、Microsoft、OpenClaw、SpaceXAI 等逾 100 家组织参与，路透社也独立报道了 OpenShell、Sentry 及其面向多智能体绕过行为的控制设计。

**为什么值得关注：** 智能体安全正在从“让模型更听话”转向“即使模型不配合也无法越界”的外部强制执行；软件沙箱与独立硬件看门狗的组合，可能成为高权限自主智能体的新基础设施层。

- **原文：** [NVIDIA Launches Open Agent Safety Platform](https://nvidianews.nvidia.com/news/open-agent-safety-platform)
- **交叉核验：** [Reuters 报道](https://www.reuters.com/legal/litigation/nvidia-releases-ai-safety-software-it-says-could-have-stopped-hugging-face-hack-2026-09-28/)
