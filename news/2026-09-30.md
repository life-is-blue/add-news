## 1. GPT-6.1 Sol 发布：百万级上下文进入通用智能体主力档

![GPT-6.1 Sol 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://openai.com/index/introducing-gpt-6-1-sol/)

*图片来源：[OpenAI 官方发布页](https://openai.com/index/introducing-gpt-6-1-sol/)*

OpenAI 发布 GPT-6.1 Sol，定位为以更低成本提供接近 Astra 的复杂任务能力；官方模型文档给出 1,050,000 tokens 上下文窗口、128,000 tokens 最大输出，并要求带工具调用的工作流使用 Responses API。其工具面覆盖网页与文件搜索、代码解释器、托管 shell、apply patch、Skills、计算机操作、MCP 与工具搜索，输入/输出价格分别为每百万 tokens 2 美元和 10 美元。OpenAI 的部署安全说明将其网络安全能力列为 Critical、生化能力列为 High，同时称安全审查组已确认上线缓解措施足够；GitHub 也在同日宣布该模型开始向 Copilot 用户滚动开放。

**为什么值得关注：** 百万级上下文、原生工具链与较低推理成本组合在同一主力模型上，会直接改变长任务代码智能体的上下文管理、工具编排和单位任务成本。

- **原文：** [OpenAI：Introducing GPT-6.1 Sol](https://openai.com/index/introducing-gpt-6-1-sol/)
- **技术与安全资料：** [模型文档](https://developers.openai.com/api/docs/models/gpt-6.1-sol) · [部署安全说明](https://deploymentsafety.openai.com/gpt-6-1-sol/respecting-auto-review) · [GitHub Copilot 公告](https://github.blog/changelog/2026-09-29-gpt-6-1-sol-in-github-copilot/)
- **发布日期：** 2026-09-29

## 2. Codex Cloud 推出可复用环境，任务可跨设备持续运行

![Codex Cloud 使用说明](https://image.thum.io/get/width/1200/crop/675/noanimate/https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

*图片来源：[OpenAI Help Center](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)*

Codex Cloud 现在允许用户在桌面端或网页端创建并发布可复用的云环境，再从桌面、网页或移动端启动和继续任务；任务在本地电脑休眠后仍可运行。每个任务仍处于隔离环境，但团队可共享经批准的设置与权限，企业管理员还能预设模型、推理强度、速度和 Fast Mode。TechCrunch 的现场报道进一步确认，此次变化把 Codex 从一次性远程沙箱推进为可配置、可跨设备延续的开发工作区。

**为什么值得关注：** 可复用环境减少了智能体反复安装依赖、配置权限和重建上下文的成本，是把长时间自主开发从演示变成日常工作流的关键基础设施。

- **原文：** [OpenAI：Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)
- **交叉核验：** [TechCrunch：Codex reusable cloud environments](https://techcrunch.com/2026/09/29/openai-gives-codex-reusable-cloud-environments-that-work-across-devices/)
- **发布日期：** 2026-09-29

## 3. Codex Code Review 登陆桌面与网页，并预览 GitLab 支持

![Codex Code Review 官方说明](https://image.thum.io/get/width/1200/crop/675/noanimate/https://help.openai.com/en/articles/20001552-review-pull-requests-with-codex)

*图片来源：[OpenAI Help Center](https://help.openai.com/en/articles/20001552-review-pull-requests-with-codex)*

OpenAI 将 Codex Code Review 带到桌面端与网页端，把 pull request、代码差异、发现项、评论、测试、检查和冲突集中到同一界面。开发者可在提交、推送或合并前追问评审结果，并让 Codex 准备修复；GitLab merge request 评审以预览形式开放，但 GitLab 的云端代码评审目前尚不可用。相关 GitLab 连接器还能读取仓库、MR、issue、流水线、作业和日志，实际操作权限继续受工作区与用户授权约束。

**为什么值得关注：** 这把“生成代码”后的验证与修复闭环纳入同一个智能体界面，也让 Codex 的协作边界从 GitHub 向 GitLab 扩展。

- **原文：** [OpenAI：Review pull requests with Codex](https://help.openai.com/en/articles/20001552-review-pull-requests-with-codex)
- **补充资料：** [OpenAI：Connecting GitLab to ChatGPT and Codex](https://help.openai.com/en/articles/20001486-connecting-gitlab-to-chatgpt-and-codex)
- **发布日期：** 2026-09-29

## 4. Codex Security Cloud 进入研究预览，Daybreak Blue 纳入产品

![Codex Security 官方说明](https://image.thum.io/get/width/1200/crop/675/noanimate/https://help.openai.com/en/articles/20001107-codex-security)

*图片来源：[OpenAI Help Center](https://help.openai.com/en/articles/20001107-codex-security)*

Codex Security Cloud 面向 Enterprise、Edu、Business 和 Pro 进入研究预览：它会连接 GitHub、根据仓库及历史生成可编辑的威胁模型，并对完整仓库或单次提交执行扫描。系统在隔离环境中验证可疑漏洞、探索现实攻击路径并提出需人工审核的补丁 PR，而不会直接修改代码；官方强调其核心是模型推理、测试时计算、工具与上下文，而不是传统签名或模糊测试。此前独立展示的 Daybreak Blue 访问权限现被包含在 Cloud 产品内，企业与教育版还可通过 RBAC 管理使用范围。

**为什么值得关注：** 安全能力开始与编码智能体共享仓库上下文、执行环境和修复流程，意味着自主开发平台正在把“写—审—攻—修”合并为一条可治理的流水线。

- **原文：** [OpenAI：Codex Security](https://help.openai.com/en/articles/20001107-codex-security)
- **发布日期：** 2026-09-29

## 5. OpenAI Dots 发布：常驻智能体开始主动推进软件项目

![OpenAI Dots 官方页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://chatgpt.com/features/dots/)

*图片来源：[OpenAI Dots 官方页面](https://chatgpt.com/features/dots/)*

OpenAI 发布 Dots：由 GPT-6 Astra 驱动、拥有独立云计算机的常驻智能体，可持续观察授权应用并主动推进目标；官方给出的开发场景包括跟踪客户反馈，以及界定、构建和测试产品改进。用户可选择应用与权限，并用 Custom Rules 设置允许、需审批或禁止的动作；敏感账户和信息操作会经过 Auto-review，部分动作必须人工确认，密码修改仍只允许用户本人完成。Reuters 报道称 Dots 可跨 Slack 与 Teams 工作，并将其视为 OpenAI 面向企业常驻智能体市场的重要推进。

**为什么值得关注：** 与按提示启动的编码助手相比，常驻智能体会主动发现任务、跨应用协调并持续执行，也因此把权限、审批、审计和失控边界推到产品设计中心。

- **原文：** [OpenAI：Dots](https://chatgpt.com/features/dots/)
- **交叉核验：** [Reuters：OpenAI takes on Meta with always-on Dots agent](https://www.reuters.com/business/openai-takes-meta-with-always-on-dots-agent-enterprise-ai-push-2026-09-29/)
- **发布日期：** 2026-09-29
