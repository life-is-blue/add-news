## 1. Claude Code 2.1.328：Auto Mode 扩展至多云，MCP Hook 可失败即阻断

![Claude Code 2.1.328 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.328)

*配图来源：[Anthropic Claude Code 官方 GitHub Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.328)*

Claude Code 将 Opus 4.6 与 Sonnet 4.6 的 Auto Mode 扩展到 Amazon Bedrock、Google Cloud Agent Platform、Microsoft Foundry 和 Claude Apps Gateway，并为 `mcp_tool` hook 增加 `"onFailure": "block"`，使 hook 失败时可以阻止动作。新版还集中修复 Code Mode、远程会话、计划任务、自托管 Runner 与长会话恢复问题，包括计划任务文件读取失败时误删其他任务，以及重启后丢失权限提示、压缩摘要或工具结果。

**为什么值得关注：** 这次更新同时推进“更自主”和“可阻断”两条路线：多云环境更容易启用自动执行，而 MCP hook 的失败关闭机制与远程状态修复，让企业能够给这种自主性加上真正可执行的安全边界。

- **原文：** [Claude Code 2.1.328 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.328)
- **发布日期：** 2026-11-19（新加坡时间）
- **时间范围：** 过去 24 小时

## 2. Gemini CLI 0.69.0：修复恢复、无头执行与沙箱边界问题

![Gemini CLI 0.69.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/google-gemini/gemini-cli/releases/tag/v0.69.0)

*配图来源：[Google Gemini CLI 官方 GitHub Release](https://github.com/google-gemini/gemini-cli/releases/tag/v0.69.0)*

Gemini CLI 0.69.0 修复恢复会话时的模型轮次 400 错误和主线程 JSONL 卡死、网络失败导致的静默长时间加载，以及配额重试持续数小时的问题。它还改进 ACP 流式重试、无头中止时的子进程清理与取消结果记录、macOS Seatbelt 沙箱的目录信任顺序，并限制多段工具输出与多模态内联数据的内存占用。

**为什么值得关注：** 编码智能体的真实瓶颈往往不是单次生成质量，而是会话恢复、取消语义、资源上限和沙箱初始化是否一致；这批修复直接提高 CI、ACP 客户端和长时间无人值守任务的可预测性。

- **原文：** [Gemini CLI 0.69.0 Release Notes](https://github.com/google-gemini/gemini-cli/releases/tag/v0.69.0)
- **发布日期：** 2026-11-19（新加坡时间）

## 3. LangGraph 1.2.23：修正 Send 分发工具调用的状态语义

![LangGraph 1.2.23 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/langchain-ai/langgraph/releases/tag/1.2.23)

*配图来源：[LangGraph 官方 GitHub Release](https://github.com/langchain-ai/langgraph/releases/tag/1.2.23)*

LangGraph 1.2.23 让经 `Send` 分发的工具调用获得与普通图边一致的状态，并同步发布 langgraph-prebuilt 1.1.3，使 `wrap_tool_call` 的状态覆盖能够真正传递到工具。该版还修复动态 schema 中的告警竞态，并更新 OpenTelemetry API 依赖。

**为什么值得关注：** 多智能体图执行的核心是“同一份状态在不同分发路径下含义一致”；这项修复虽小，却能避免并行工具调用因调度方式不同而观察到不同状态，减少难以复现的编排错误。

- **原文：** [LangGraph 1.2.23 Release Notes](https://github.com/langchain-ai/langgraph/releases/tag/1.2.23)

## 4. MCP 官方服务器 2.5.0：一次修复 8 个漏洞

![MCP Servers 2.5.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/modelcontextprotocol/servers/releases/tag/v2.5.0)

*配图来源：[Model Context Protocol 官方服务器 GitHub Release](https://github.com/modelcontextprotocol/servers/releases/tag/v2.5.0)*

MCP 官方服务器 2.5.0 修复 Git、Filesystem 与 Everything 三个服务器中的 8 个漏洞，涉及 Git 自动维护和懒加载触发外部程序、恶意索引读取工作树外文件、子模块配置执行、目录与符号链接替换竞态，以及 NAT64 绕过私网地址检查。官方要求升级到 `mcp-server-git 2026.11.18`、`server-filesystem 2.4.0` 与 `server-everything 2.3.1`，并提醒旧的日期版本不会自动升级到数值更低的语义版本，需要显式安装。

**为什么值得关注：** 这些漏洞跨越“只读工具”到宿主命令执行和越界文件读取，说明 MCP 服务器不能把底层 Git、文件系统或网络库的默认行为视为安全；对让智能体直接操作仓库和本地文件的团队，这是需要尽快处理的基础设施更新。

- **原文：** [MCP Servers 2.5.0 Security Release](https://github.com/modelcontextprotocol/servers/releases/tag/v2.5.0)
- **发布日期：** 2026-11-18（新加坡时间）
- **时间范围：** 扩展至过去 72 小时

## 5. OpenAI Agents SDK 0.25.0：重做检查点恢复并升级 MCP 并发

![OpenAI Agents SDK 0.25.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/openai-agents-python/releases/tag/v0.25.0)

*配图来源：[OpenAI Agents Python SDK 官方 GitHub Release](https://github.com/openai/openai-agents-python/releases/tag/v0.25.0)*

OpenAI Agents SDK 0.25.0 调整 Pydantic 运行上下文的检查点格式，保留默认值、原地修改、嵌套工具审批与输出 guardrail，并为 handoff 增加可选失败恢复。该版还让 MCP v2 Streamable HTTP 支持并发请求，将会话压缩默认模型切换为 `gpt-6-luna`，同时移除 beta Runloop 沙箱 provider，官方要求相关用户先迁移工作区与快照。

**为什么值得关注：** 检查点不是普通序列化细节，它决定长程智能体在崩溃、审批暂停和跨 worker 恢复后是否仍保持原有决策；并发 MCP 与显式 handoff 恢复则进一步把 SDK 推向更复杂的生产编排。

- **原文：** [OpenAI Agents SDK 0.25.0 Release Notes](https://github.com/openai/openai-agents-python/releases/tag/v0.25.0)
- **发布日期：** 2026-11-18（新加坡时间）
- **时间范围：** 扩展至过去 72 小时
