## 1. Claude Code 2.1.314 将工作区外写入封锁提升为全权限模式规则

![Claude Code 2.1.314 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.314)

*图片来源：Anthropic Claude Code 官方 GitHub Release（页面截图）*

Claude Code 2.1.314 新增 `permissions.blockWritesOutsideWorkingDirectories`，使 Write、Edit 与 NotebookEdit 在所有权限模式下都拒绝写入工作目录之外；同时修复通过 `--resume` 或 `--continue` 进入 worktree 时沙箱保护未生效的问题。版本还为 Bedrock 网关增加不记录命中文本的 `guardrail_trace`，并让管理员可按 IdP 群组路由上游；超过 20 万 token 的空闲会话也可在 VS Code 与 Claude Desktop Code 标签中自动压缩。多项可靠性修复覆盖后台任务自重启导致自动续跑超过三次、MCP 登录失效、远程策略缓存过期后会话无策略启动等场景。

**为什么值得关注：** 这次更新把“文件写入边界、身份路由、云端护栏、长会话压缩”放进同一套运行时治理中，直接收紧了编码智能体最容易发生权限漂移的几个环节。

- **原文：** [Anthropic Claude Code v2.1.314 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.314)
- **发布日期：** 2026-10-30（新加坡时间；过去 24 小时）

## 2. Codex CLI 0.166.0 强化队列恢复、线程继承与安全阻断解释

![Codex CLI 0.166.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/codex/releases/tag/rust-v0.166.0)

*图片来源：OpenAI Codex 官方 GitHub Release（页面截图）*

Codex CLI 0.166.0 新增 `codex queue --resume`，可在向未加载线程排队消息后恢复该线程；TUI 也加入更清晰的安全阻断说明、可选的安全后续提示，以及仅检查网络配置、连通性与 WebSocket 的 `codex doctor --network-only`。新版在恢复或 fork 线程时保留已确认的审批与权限设置，解归档父线程时恢复其派生线程，并保留推理 token 计数以避免过早压缩。它还修复 app-server 线程启停竞态和 TUI 断线恢复问题。

**为什么值得关注：** 长程编码任务的可靠性取决于队列、恢复、fork 与审批状态能否保持一致；这些改动比单点功能更接近多线程智能体控制面的基础设施升级。

- **原文：** [OpenAI Codex 0.166.0 Release](https://github.com/openai/codex/releases/tag/rust-v0.166.0)
- **发布日期：** 2026-10-30（新加坡时间；过去 24 小时）

## 3. Qwen Code 0.26.4 为主会话隔离 worktree，并给自动修复设置轮次预算

![Qwen Code 0.26.4 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/QwenLM/qwen-code/releases/tag/v0.26.4)

*图片来源：Qwen Code 官方 GitHub Release（页面截图）*

Qwen Code 0.26.4 为托管主会话增加独立 worktree，使并发任务可在隔离代码状态上运行；自动修复接管流程新增轮次预算，避免无边界循环。PR 验证在代码更新后可由后续触发器重新运行，发布报告会记录模型、CLI 与 skill 版本，便于复现实验条件。版本还为生成式 UI 增加交互视图，并允许嵌入宿主选择工作区目录。

**为什么值得关注：** 独立 worktree、有限自动修复和带版本戳的验证报告共同构成更可审计的自治开发闭环：既减少并发污染，也限制失控成本，并让结果能够追溯。

- **原文：** [Qwen Code v0.26.4 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.4)
- **发布日期：** 2026-10-29 22:29（新加坡时间；过去 24 小时）

## 4. OpenCode 2.2.2 把条件调度与图像生成接入智能体工作流

![OpenCode 2.2.2 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anomalyco/opencode/releases/tag/v2.2.2)

*图片来源：OpenCode 官方 GitHub Release（页面截图）*

OpenCode 2.2.2 在连接支持图像模型的提供方后默认开放 `experimental_image_generate`，并在 fork 或导入会话时保留媒体；后台图像任务的提示也会关联到正确作业。SDK 的实验性调度接口新增 `if` 与 `until` 输入，以及检查结果和输出字段，使定时提示可按条件决定运行或终止。版本还拒绝工作目录已不存在的持久终端请求，并记录每个会话最近一次执行的开始时间。

**为什么值得关注：** 条件调度把智能体从“按时间触发”推进到“按状态持续运行”，而媒体保留、后台作业关联和失效目录拒绝则补齐了多模态长任务的状态一致性。

- **原文：** [OpenCode v2.2.2 Release](https://github.com/anomalyco/opencode/releases/tag/v2.2.2)
- **发布日期：** 2026-10-30 02:43（新加坡时间；过去 24 小时）

## 5. Amp 推出 macOS Satellites：Linux 智能体按需调用云端 Mac

> **时间范围：扩展至过去 72 小时**

![Amp macOS Satellites 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://ampcode.com/news/macos-satellites)

*图片来源：Amp 官方产品公告（页面截图）*

Amp 的 macOS Satellites 让主线程继续运行在 Linux orb 上，仅在构建、测试或操作 iOS/macOS 应用时自动启动一台带 Xcode 与模拟器的临时云端 Mac；代码在两台机器间同步，截图、日志、构建产物和录屏返回原线程。官方称 Mac 约 30 秒启动，任务结束后保留 20 分钟以复用构建缓存，之后自动删除；用户也可观看屏幕流或接管操作。该功能目前处于 beta 候补阶段。

**为什么值得关注：** 这种异构执行架构让自治开发智能体无需把完整工作流迁移到昂贵的 macOS 主机，却仍能完成苹果平台的真实构建与 UI 验证，是云端编码智能体走向多操作系统协作的重要模式。

- **原文：** [Amp：macOS Satellites](https://ampcode.com/news/macos-satellites)
- **发布日期：** 2026-10-29（过去 72 小时；官方未提供精确时刻）
- **状态：** Beta
