## 1. Slack Code 上线：团队可在频道内共同指挥编程代理

![Slack Code 相关新闻配图](https://platform.theverge.com/wp-content/uploads/sites/2/chorus/uploads/chorus_asset/file/23988538/acastro_STK060_slack_04.jpg?crop=0%2C0%2C100%2C100&quality=90&strip=all&w=1600)

*图片来源：[Alex Castro / The Verge](https://www.theverge.com/tech/982628/slack-code-vibe-coding-channels-launch)*

Slack 推出项目专属的 Slack Code 频道：团队在对话中召唤 Claude Code、Devin、Vercel Agent 或 GitHub Copilot，代理随后创建代码频道并执行任务。成员可以查看对话和代码差异、预览 HTML 输出、反馈并在发布前审批；任务完成后频道自动归档，同时保留审计记录。Slack Code 已面向所有 Slack 计划开放，并兼容 Marketplace 中的代理。

**为什么值得关注：** 这正面命中了“Slack 驱动自主开发协作”——需求、代理执行、代码审阅和人工批准第一次被收束到同一个多人可见的协作表面，减少了代理在私有终端里工作的不可见性。

- 原文：[Slack is launching collaborative vibe-coding channels](https://www.theverge.com/tech/982628/slack-code-vibe-coding-channels-launch)
- 官方功能背景：[Slack：Beyond chat—Slack Code](https://slack.com/blog/collaboration/beyond-chat-10-smart-ways-to-work-in-slack)
- 发布日期：2026-08-20

## 2. Anthropic 将 Computer Use、Skills API 与 Files API 正式 GA

![Anthropic 生产级代理能力](https://cdn.prod.website-files.com/68a44d4040f98a4adf2207b6/6903d229061abf091318fc81_6905c83d0735e1bc430025fdd1748d1406079036-1000x1000.svg)

*图片来源：[Anthropic](https://claude.com/blog/computer-use-skills-api-files-api)*

Anthropic 宣布 Computer Use、Skills API 和 Files API 在 Claude Platform 正式可用，并新增面向 Web 应用的 browser use 工具。新版 Computer Use 可在一次模型调用中连续执行多个动作；browser use 除截图外还读取页面结构，从而更可靠地定位控件。Skills API 支持上传、版本化并按需加载团队知识，Files API 则提供自动过期、提高 5 倍的速率限制，以及每个组织 1 TB 存储。

**为什么值得关注：** Anthropic 正把代理所需的“操作界面、加载组织方法、读写产物”组合成一套托管 API；这让 Claude Code 风格的能力更容易嵌入企业应用，也把技能版本与文件生命周期提升为生产基础设施。

- 原文：[Build production agents with computer use, the Skills API, and the Files API](https://claude.com/blog/computer-use-skills-api-files-api)
- 技术文档：[Claude Platform：Computer use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)
- 发布日期：2026-08-20

## 3. AWS 用四类智能体编排 300 多个应用的云迁移

![AWS 多智能体云迁移架构](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/08/12/ML-20875-1-1.png)

*图片来源：[AWS 官方架构图](https://aws.amazon.com/blogs/machine-learning/scaling-cloud-migrations-with-agentic-ai-on-amazon-bedrock-agentcore/)*

AWS Professional Services 公布一套覆盖 300 多个应用的多智能体迁移框架，分别设置 Intake、IaC、Migration Intelligence and Governance、SRE 四类代理，覆盖发现、基础设施代码生成、组合治理和迁移后运维。代理以 Strands Agents SDK 构建并运行在 Bedrock AgentCore，通过 Gateway 暴露的 MCP 工具执行动作，Identity 以最小权限 IAM 身份认证每次调用，Memory 则在代理间传递架构、依赖与迁移状态。AWS 表示，在该实现中，IaC 开发可由数周缩短至数分钟，但关键决策仍由人保留。

**为什么值得关注：** 这不是单个聊天机器人，而是一套把专用代理、共享状态、MCP 工具、身份和可观测性装配到大型工程项目中的参考实现，展示了自主开发协作如何跨越数百个工作负载。

- 原文：[Scaling cloud migrations with agentic AI on Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/scaling-cloud-migrations-with-agentic-ai-on-amazon-bedrock-agentcore/)
- 相关开源项目：[Strands Agents SDK](https://github.com/strands-agents/sdk-python)
- 发布日期：2026-08-20

## 4. AgentCore 可把自然语言制度转换为可执行 Dogwood 策略

![Dogwood 策略语言项目](https://opengraph.githubassets.com/20260821/dogwood-policy/dogwood)

*图片来源：[Dogwood 官方 GitHub 仓库](https://github.com/dogwood-policy/dogwood)*

AWS 扩展 AgentCore Policy Authoring，使其能把自然语言制度文档转换为经过语法与语义验证的 Dogwood 形式化策略。生成规则可约束工具参数、前置步骤、调用顺序、时间窗口、累计金额和速率，并由 AgentCore Gateway 中的 Dogwood monitor 在代理运行时执行；自由文本还可调用 Bedrock Guardrails 检查。官方示例包括“15 分钟内完成同一账户身份验证后方可转账”和“12 小时累计转账不得超过 5 万美元”。

**为什么值得关注：** 代理治理正从静态的单次 allow/deny 权限，升级为能够检查完整动作轨迹的状态化控制；把书面制度自动形式化，也缩短了合规团队与工程实现之间的距离，但生成结果仍需规则所有者复核。

- 原文：[Authoring Dogwood policies from natural language in Amazon Bedrock AgentCore](https://aws.amazon.com/blogs/machine-learning/authoring-dogwood-policies-from-natural-language-in-amazon-bedrock-agentcore/)
- 开源实现：[dogwood-policy/dogwood](https://github.com/dogwood-policy/dogwood)
- 发布日期：2026-08-20

## 5. OpenAI GPT-5.6 在 Amazon Bedrock 获得跨区域推理

![Amazon Bedrock 中的 GPT-5.6 跨区域推理配置](https://d2908q01vomqb2.cloudfront.net/f1f836cb4ea6efb2a0b1b99f41ad8b103eff4b59/2026/08/19/ML-21727-1.png)

*图片来源：[AWS 官方控制台截图](https://aws.amazon.com/blogs/machine-learning/introducing-cross-region-inference-for-openai-gpt-5-6-models-on-amazon-bedrock/)*

Amazon Bedrock 已在 25 个以上 AWS 区域提供 OpenAI GPT-5.6，并为 Sol、Terra、Luna 三个通用版本加入跨区域推理。地理推理配置可在指定地理边界内动态路由容量，全球配置则在所有支持区域间调度；三款模型均支持 100 万 token 上下文、推理模式、服务端工具调用和提示缓存。开发者可以继续使用 OpenAI Responses API、Chat Completions API，或改用 Bedrock Converse API。

**为什么值得关注：** 长时间运行、并发较高的编码与智能体任务对容量稳定性非常敏感；跨区域调度让企业能在吞吐、可用性和数据驻留之间做明确选择，也降低了 OpenAI 模型接入 AWS 现有身份与治理体系的门槛。

- 原文：[Introducing cross-Region inference for OpenAI GPT-5.6 models on Amazon Bedrock](https://aws.amazon.com/blogs/machine-learning/introducing-cross-region-inference-for-openai-gpt-5-6-models-on-amazon-bedrock/)
- 技术文档：[Amazon Bedrock cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)
- 发布日期：2026-08-20
