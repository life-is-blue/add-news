## 1. Prime Agent 开源：用递归子智能体与持久计算推进长周期编码

![Prime Agent 论文页面](https://image.thum.io/get/width/1200/crop/630/noanimate/https://arxiv.org/abs/2608.23552)

*图片来源：arXiv 论文页面截图。*

**事实摘要：** Prime Intellect 团队发布开源 Harness Prime Agent，以持久 IPython REPL、跨轨迹保留历史/记忆/技能的 Continual Harness，以及可直接通信的递归子智能体支持长周期编码和推理。论文报告其将 ARC-AGI-3 RHAE Best@1 从 30% 提升到 95.5%，并在长上下文编码、GPU 内核生成、模拟器构建和自主 nanoGPT 优化等任务上匹配或超过多种原生与流行 Harness；这些结果目前属于作者报告。

**为什么值得关注：** 它把“模型能力”与“执行 Harness 能力”明确分离，并把恢复、验证、资源核算和人工检查做成统一运行层，非常贴近多 CLI 编排与长任务自治的现实需求。

- **原文：** [Prime Agent: A Self-Improving RLM Harness](https://arxiv.org/abs/2608.23552)
- **代码：** [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)
- **发布日期：** 2026-08-24 17:54 UTC（过去 24 小时）

## 2. SkillAlchemy 让智能体从开放资料自动炼成可复用技能

![SkillAlchemy 论文页面](https://image.thum.io/get/width/1200/crop/630/noanimate/https://arxiv.org/abs/2608.23417)

*图片来源：arXiv 论文页面截图。*

**事实摘要：** SkillAlchemy 研究“开放世界技能创建”：智能体只获得不完整的技能说明和允许访问的资料源，需要自行发现隐含需求、判断操作流程的适用范围，再编译为受语法约束的技能包。作者在 SkillsBench v1.1 的 87 项任务上报告，相比无技能执行通过率提高 19.9 个百分点，相比最强自动化基线提高 8.6 个百分点，并达到接近人工整理技能的水平。

**为什么值得关注：** Agent Skills 正成为跨 Codex、Claude Code 等工具传递工作方法的轻量载体；如果技能能从一手文档自动生成并用证据约束适用边界，维护成本和“过时知识”风险都会显著下降。

- **原文：** [SkillAlchemy: Open-World Agent Skill Creation](https://arxiv.org/abs/2608.23417)
- **发布日期：** 2026-08-24 15:58 UTC（过去 24 小时）

## 3. Apodex 1.1 用异步 Agent Team 执行可验证的复杂工作

![Apodex 1.1 发布页面](https://image.thum.io/get/width/1200/crop/630/noanimate/https://www.apodex.com/blog/apodex-1.1-scaling-agentic-intelligence-for-complex-work)

*图片来源：Apodex 官方技术博客页面截图。*

**事实摘要：** Apodex 1.1 将文件处理、搜索、代码执行与工具调用纳入同一长任务工作台，并通过 AgentOS 保存跨工具和子智能体的状态与来源信息；异步 Agent Team 可拆分任务、并行委派、汇总结果和动态重规划。团队同步开放 35B 参数的 Apodex 1.1 Mini 与 FrontierAgent 执行 Harness，并在论文中报告其在专业工作、金融、科研、数学、编码与搜索任务上进入领先区间；基准结论仍需独立复现。

**为什么值得关注：** 这代表智能体竞争从“回答质量”转向持续执行、可介入、可追踪和可交付的工作能力，也提供了可本地部署模型与开放 Harness 的组合路径。

- **原文：** [Apodex 1.1 官方发布](https://www.apodex.com/blog/apodex-1.1-scaling-agentic-intelligence-for-complex-work)
- **技术报告：** [Apodex 1.1: Scaling Agentic Intelligence for Complex Work](https://arxiv.org/abs/2608.23283)
- **发布日期：** 2026-08-24 14:07 UTC（过去 24 小时）

## 4. AutoSaddler 自动从失败轨迹优化 Agent Harness

![AutoSaddler 论文页面](https://image.thum.io/get/width/1200/crop/630/noanimate/https://arxiv.org/abs/2608.23041)

*图片来源：arXiv 论文页面截图。*

**事实摘要：** AutoSaddler 把 Harness 优化表述为离线学习问题：从一批执行失败轨迹中进行深度诊断，把 Harness 当作代码生成定向补丁，再通过验证选择可持久保留的更新。作者报告在 GAIA2、SWE-Bench Pro 与 Terminal-Bench 2.0 上，相对各自基础 Harness 分别提升 9.0、9.6 和 10.0 个百分点，并发现深度调试、定向修改与面向泛化的选择缺一不可。

**为什么值得关注：** 这为“让智能体改进自己的编排层”提供了比自由改提示词更受控的工程方案，尤其适合持续收集失败样本、希望把修复沉淀为稳定运行规则的多智能体系统。

- **原文：** [AutoSaddler: Automatic Harness Optimization with Durable Updates from Agent Execution Traces](https://arxiv.org/abs/2608.23041)
- **发布日期：** 2026-08-24 09:45 UTC（扩展至过去 72 小时）

## 5. Vercel Sandbox 扩展至四个区域并支持故障转移

![Vercel Sandbox 全球区域发布](https://image.thum.io/get/width/1200/crop/630/noanimate/https://vercel.com/changelog/vercel-sandbox-is-now-globally-available)

*图片来源：Vercel 官方 Changelog 页面截图。*

**事实摘要：** Vercel Sandbox 现可运行在华盛顿、旧金山、克利夫兰和巴黎四个区域，所有计划均可选择靠近数据库与对象存储的区域；Pro 与 Enterprise 团队还能配置新沙箱的故障转移区域。快照保留在创建区域且不能直接迁移，但故障转移时平台会自动跨区域加载快照，区域与容灾设置可通过项目配置、CLI 或 SDK 管理。

**为什么值得关注：** 编码智能体越来越依赖隔离沙箱执行安装、编译和测试；区域选择与容灾能力会直接影响远程 Agent 的延迟、数据驻留设计和长任务恢复能力。

- **原文：** [Vercel Sandbox is now globally available](https://vercel.com/changelog/vercel-sandbox-is-now-globally-available)
- **发布日期：** 2026-08-24（扩展至过去 72 小时；官方仅提供日期）
