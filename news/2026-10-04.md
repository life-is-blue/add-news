## 1. Apple 将强化 macOS AI 智能体“完全磁盘访问”提示

![Apple 将强化 macOS AI 智能体数据访问提示](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.reuters.com/business/retail-consumer/apple-says-it-will-flag-ai-requests-mac-data-after-metas-muse-draws-complaints-2026-10-02/)

*图片来源：[Reuters 报道页面](https://www.reuters.com/business/retail-consumer/apple-says-it-will-flag-ai-requests-mac-data-after-metas-muse-draws-complaints-2026-10-02/)*

- **时间范围：**过去 72 小时（扩展）
- **发布日期：**2026-10-02
- **事实摘要：**Apple 表示将调整 macOS，使 AI 智能体申请“完全磁盘访问”（Full Disk Access）时的含义更醒目，并要求用户进行更明确的授权操作。此举发生在 Meta Muse 引发数据访问争议后；Meta 回应称，Messages 访问属于可选功能，需用户同时开启完全磁盘访问并连接 Messages。报道将平台方拟收紧授权界面的事实，与厂商对具体访问方式的解释分别呈现，尚不能据此认定存在未经授权的数据读取。
- **为什么值得关注：**桌面智能体正从“生成建议”走向“操作本机应用与数据”，操作系统级权限提示将直接决定这类产品的默认安全边界，也可能成为开发者必须适配的新交互规范。
- **原文链接：**[Reuters](https://www.reuters.com/business/retail-consumer/apple-says-it-will-flag-ai-requests-mac-data-after-metas-muse-draws-complaints-2026-10-02/)

## 2. GitHub Copilot 获得桌面应用操作能力

![GitHub Copilot desktop computer use](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps/)

*图片来源：[GitHub 官方更新页面](https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps/)*

- **时间范围：**过去 72 小时（扩展）
- **发布日期：**2026-10-01
- **事实摘要：**GitHub 将 computer use 以公开预览形式带入 Copilot CLI，以及 macOS、Windows 上的 Copilot 应用；智能体可读取可访问的应用内容或视觉上下文，并执行点击、输入、滚动与拖拽。功能启用前需要用户批准，用户可维护“始终允许”的应用清单；在 macOS 上还依赖辅助功能和屏幕录制权限，组织管理员可通过策略关闭该能力。
- **为什么值得关注：**Copilot 的执行面从终端与代码仓库扩展到 GUI 软件，意味着开发工作流可以跨越 IDE、浏览器和桌面工具；与此同时，允许列表和系统权限将成为新的最小权限控制点。
- **原文链接：**[GitHub Changelog](https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps/)

## 3. VS Code 把编码智能体推进到定时运行、合并与跨应用接力

![GitHub Copilot in VS Code September 2026 releases](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-01-github-copilot-in-vs-code-september-2026-releases/)

- **时间范围：**过去 72 小时（扩展）
- **发布日期：**2026-10-01

## 4. OpenAI API 公布 GPT-5.3-Codex 等模型退役时间表

![OpenAI API deprecations](https://image.thum.io/get/width/1200/crop/675/noanimate/https://developers.openai.com/api/docs/deprecations)

*图片来源：[OpenAI 官方弃用文档](https://developers.openai.com/api/docs/deprecations)*

- **时间范围：**过去 72 小时（扩展）
- **发布日期：**2026-10-01
- **事实摘要：**OpenAI 在 API 弃用文档中宣布，GPT-5.3-Codex、GPT-5.1 和 GPT-5.4-Nano 将于 2027-04-01 停止服务，提供六个月迁移期。官方给出的替代映射分别为 GPT-5.3-Codex → GPT-6-Sol、GPT-5.1 → GPT-6-Sol、GPT-5.4-Nano → GPT-6-Luna。
- **为什么值得关注：**编码智能体和自动化流水线常把模型 ID、工具行为与评测阈值绑定在一起；明确的停止日期使团队现在就能安排回归评测、成本重估和路由迁移，避免临近下线时被动切换。
- **原文链接：**[OpenAI Developers](https://developers.openai.com/api/docs/deprecations)

## 5. GitHub 开放安全公告评论 API，支持自动化协同处置

![GitHub repository security advisory comments API](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-02-repository-security-advisory-comments-api-in-public-preview/)

*图片来源：[GitHub 官方更新页面](https://github.blog/changelog/2026-10-02-repository-security-advisory-comments-api-in-public-preview/)*

- **时间范围：**过去 72 小时（扩展）
- **发布日期：**2026-10-02
- **事实摘要：**GitHub 为仓库安全公告推出评论 REST API 公开预览，可读取、新增和编辑评论，也覆盖私有漏洞报告；列表接口支持按更新时间增量获取，公告响应会返回非机密评论数量。机密评论不会由该接口返回，当前也不支持删除评论；公开预览适用于公开仓库的 Free、Pro、Team 与 Enterprise Cloud 用户。
- **为什么值得关注：**安全修复智能体终于能以结构化方式接入漏洞协作线程，构建自动分诊、审计和迁移流程；同时保留机密评论隔离，体现了可自动化协作与敏感信息边界之间的设计取舍。
- **原文链接：**[GitHub Changelog](https://github.blog/changelog/2026-10-02-repository-security-advisory-comments-api-in-public-preview/)
