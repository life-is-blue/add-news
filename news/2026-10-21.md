## 1. GitHub 推出包防火墙：为编码智能体增加依赖供应链隔离层

![GitHub Package Firewall 官方公告截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-20-github-package-firewall-in-public-preview/)

*图片来源：[GitHub 官方 Changelog](https://github.blog/changelog/2026-10-20-github-package-firewall-in-public-preview/)*

GitHub 面向 Enterprise Cloud 客户开放 Package Firewall 公测，让 Actions Runner、编码智能体和开发工作站通过受控代理访问上游包仓库。管理员可设置新包冷却期，结合 GitHub Advisory Database 检查恶意软件与漏洞，并检测证明（attestation）降级；被误拦截的包可走例外申请流程。当前仅支持 npm，公测期免费，正式可用后计划按用量计费。

**为什么值得关注：** 编码智能体会自主安装依赖，其权限和速度放大了投毒包、依赖混淆及凭据窃取风险；把防护放到仓库访问路径上，比依赖智能体自身判断更接近可审计、可强制的企业安全边界。

- **发布日期：** 2026-10-20（扩展至过去 72 小时；官方未标精确时刻）
- **原文：** [GitHub package firewall in public preview](https://github.blog/changelog/2026-10-20-github-package-firewall-in-public-preview/)

## 2. Claude Code 2.1.306：修复云端无头运行与多 MCP 工具会话误压缩

![Claude Code 2.1.306 官方发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.306)

*图片来源：[Anthropic Claude Code 官方 GitHub Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.306)*

Claude Code 2.1.306 修复了云端会话中以 `claude -p` 启动子进程时，因没有继承会话环境变量而错误报告“未登录”的问题。它还修复了包含大量 MCP 工具的会话中，真实 API 错误被替换成“prompt is too long”并触发不必要上下文压缩的问题。该版本于 2026-10-21 11:16（新加坡时间）发布。

- **发布日期：** 2026-10-21 11:16（过去 24 小时，新加坡时间）

## 4. Pydantic AI 2.59.0：修复 Web Fetch 高危阻塞漏洞并强化智能体沙箱

![Pydantic AI 2.59.0 官方发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/pydantic/pydantic-ai/releases/tag/v2.59.0)

*图片来源：[Pydantic AI 官方 GitHub Release](https://github.com/pydantic/pydantic-ai/releases/tag/v2.59.0)*

Pydantic AI 2.59.0 修复一项高危问题：`web_fetch` 处理含大量 HTML 元素的攻击者页面时，可能阻塞同进程内的其他工作；官方建议所有能抓取不可信网页的部署升级。新版本加入 DaytonaSandbox，使 Coder、Shell、FileSystem 等 Harness 能力在隔离工作区执行，并在每次 CodeMode 嵌套工具调用前检查调用上限。它还对压缩转录与 TrajectoryJudge 反馈进行转义和绑定，降低工具输出伪造高权限消息的风险。

**为什么值得关注：** 这是“联网内容 → 提示上下文 → 工具执行”整条智能体链路的纵深防御：既处理拒绝服务风险，也补上沙箱、调用预算与消息来源真实性，代表 Agent SDK 正从功能框架走向安全运行时。

- **发布日期：** 2026-10-21 12:36（过去 24 小时，新加坡时间）
- **原文：** [Release v2.59.0](https://github.com/pydantic/pydantic-ai/releases/tag/v2.59.0)

## 5. HarnessAdapt-RL：训练模型的同时让工具与 Hooks 自我演化

![HarnessAdapt-RL 论文页面截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2610.28069)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2610.28069)*

新论文 HarnessAdapt-RL 不再把智能体 Harness 当作固定外壳，而是在强化学习期间同时演化任务级机制技能、工具与 Hooks；只有当候选改动提高观察到的通过率或可训练率、且不降低另一指标时才保留。以 9B 基座模型实验时，相比 GRPO，其 pass@1 在 SWE-bench Verified、Multilingual 和 Pro 上分别提升 9.8、12.6 和 6.4 个百分点，平均从 35.3% 提高到 44.9%。部署时移除演化后的工具与 Hooks 会让成绩最多下降 7.7 个百分点，作者因此主张训练产物应被视为“模型—Harness 对”。

**为什么值得关注：** 结果直接支持一个重要工程判断：智能体能力不只由模型权重决定，工具接口、验证钩子和运行约束也应进入训练闭环；这为自主开发系统的“模型与脚手架共同进化”提供了可复现证据。

- **发布日期：** 2026-10-20 19:51（过去 24 小时，新加坡时间）
- **原文：** [Training the Whole Agent, Not Just the Model](https://arxiv.org/abs/2610.28069)
