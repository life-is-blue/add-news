## 1. OpenClaw 2026.10.2：修复升级链、压缩恢复与凭据脱敏

![OpenClaw 2026.10.2 发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.10.2)

*图片来源：[OpenClaw 官方 GitHub Release](https://github.com/openclaw/openclaw/releases/tag/v2026.10.2)*

OpenClaw 2026.10.2 修复了从 2026.10.1 首次升级时的失败，以及 Windows、私有 Node 安装和克隆目录中的路径问题。OpenAI 与 Anthropic 的 API-key 路由现在默认使用供应商原生压缩，主认证配置进入冷却期时也可恢复；长工具输出跨分块的凭据会被遮蔽，大文本脱敏不再卡死或栈溢出。版本还强化了 Anthropic 提示缓存的一致性，并修复 Codex 会话、ChatGPT WebSocket、子智能体截断、定时任务工具注册等多项运行时故障。

**为什么值得关注：** 这不是功能堆叠，而是一次面向长时间运行智能体的可靠性与安全收敛：升级、上下文压缩、认证切换、秘密处理和会话续接都属于生产环境最容易暴露的薄弱环节。

- **原文：** [OpenClaw v2026.10.2](https://github.com/openclaw/openclaw/releases/tag/v2026.10.2)
- **发布日期：** 2026-10-12 13:34（新加坡时间，GitHub 发布元数据）

## 2. Hermes Agent 0.21.7：稳定发布轨道覆盖桌面、云端与源码安装

![Hermes Agent 0.21.7 发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/NousResearch/hermes-agent/releases/tag/v0.21.7)

Hermes Agent 0.21.7 同步面向 macOS Apple Silicon、Windows、Microsoft Store、安装脚本、Docker 与 Hermes Cloud 发布。源码安装默认跟随带标签的稳定版本，而不是 main 分支每次提交；桌面端可在稳定版与“每次提交”通道间切换。此次更新还让签名思考内容在会话恢复与网关轮次中保留，修复 Bedrock Converse 推理模型续接、网络防火墙更新，并让插件安全调用由核心代持令牌的 Codex 请求。

**为什么值得关注：** Hermes 正把“开源智能体可用”推进到“跨分发渠道可维护”：可控更新轨道、状态续接和插件令牌隔离，决定了桌面智能体能否长期运行而不牺牲可审计性。

## 3. JetBrains 将 Air 多智能体工作台嵌入 IDE

![JetBrains Air in IDEs 公告截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://blog.jetbrains.com/ai/2026/10/air-in-ides-eap/)

*图片来源：[JetBrains 官方博客](https://blog.jetbrains.com/ai/2026/10/air-in-ides-eap/)*

JetBrains 发布 Air in IDEs EAP，把 Air 的多智能体编排界面作为插件带入 IntelliJ 系列 IDE，并支持 Codex、GitHub Copilot、Junie、Cursor、ACP 智能体及 Claude 订阅等既有代理。开发者可以跨项目并行运行会话、查看成本、用 worktree 隔离任务，并在本地或云端执行；智能体还可调用 IDE 的差异比较、代码检查、调试、性能分析、数据库探索和语义搜索能力。JetBrains 表示第三方模型数据直接发送给相应供应商，不经过 JetBrains 服务器。

**为什么值得关注：** AI 编程竞争正在从“哪个模型更强”转向“谁能把多个代理、隔离执行和 IDE 语义工具编排成统一工作流”；Air 让成熟 IDE 成为多智能体控制面，而不要求团队替换现有代理。

- **原文：** [Air in IDEs is now available in EAP](https://blog.jetbrains.com/ai/2026/10/air-in-ides-eap/)
- **发布日期：** 2026-10-12
- **时间范围：** 过去 24 小时

## 4. OpenCode 1.19.0：为 2.0 升级与远程终端安全铺路

> **扩展至过去 72 小时**

![OpenCode 1.19.0 更新日志截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://dev.opencode.ai/changelog)

*图片来源：[OpenCode 官方更新日志](https://dev.opencode.ai/changelog)*

OpenCode 1.19.0 新增 `opencode upgrade --major`，让用户显式升级到 OpenCode 2，并调整更新行为：终端界面的 `/update` 可执行更新，但版本不再自动安装。该版本也支持 OpenAI 的 `ultrafast` 选项，并在检查远程 PTY 会话是否存在之前先验证连接来源和票据，收紧终端控制面的边界。

**为什么值得关注：** 编码智能体的升级与远程终端都是高权限路径；显式的大版本迁移和“先验票、后查资源”体现了工具链开始把版本治理与连接安全当作核心产品能力。

- **原文：** [OpenCode Changelog — v1.19.0](https://dev.opencode.ai/changelog)
- **发布日期：** 2026-10-11
- **时间范围：** 扩展至过去 72 小时

## 5. GitHub Copilot for JetBrains：企业可设代理默认模型，并加强 MCP 控制

> **扩展至过去 72 小时**

![GitHub Copilot for JetBrains 更新公告截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-10-new-controls-and-chat-improvements-in-copilot-for-jetbrains/)

*图片来源：[GitHub 官方 Changelog](https://github.blog/changelog/2026-10-10-new-controls-and-chat-improvements-in-copilot-for-jetbrains/)*

GitHub 为 Copilot for JetBrains 增加企业级默认模型控制，管理员可为新代理会话指定任一可用模型，同时保留用户主动切换模型的能力。IDE 诊断现在可通过“Fix”动作直接把问题送入内联聊天，并在可用时采用代理模式修复。新设置还允许禁止 Copilot 与 Claude 自动启动 MCP 服务器，并改进模型切换、MCP、自定义指令和 worktree 的可靠性。

**为什么值得关注：** 企业部署 AI 编程助手的关键逐渐变成模型策略、自动化边界和 MCP 生命周期治理；这些控制把代理使用从个人偏好提升为可统一管理的工程制度。

- **原文：** [New controls and chat improvements in Copilot for JetBrains](https://github.blog/changelog/2026-10-10-new-controls-and-chat-improvements-in-copilot-for-jetbrains/)
- **发布日期：** 2026-10-10
- **时间范围：** 扩展至过去 72 小时
