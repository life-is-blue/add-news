## 1. Qwen Code 0.26.5 为自治 PR 修复增加重试预算与人工交接

![Qwen Code 0.26.5 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/QwenLM/qwen-code/releases/tag/v0.26.5)

*图片来源：Qwen Code 官方 GitHub Release（页面截图）*

Qwen Code 0.26.5 为 `/autofix-pr` 增加三次修复推送的重试预算，仍失败时自动转交人工，并把已尝试内容、阻塞原因和所需操作写入 PR 评论。PR watch 会先合并落后的基础分支再判断 CI 故障，`/verify-pr` 也改为逐轮独立发布状态，避免并发验证互相覆盖。新版还默认开启 Generated UI、显示后台智能体数量，并提供包含 Hosted Harness、MySQL、本地执行与认证网关的实验性 Helm 一键部署。

**为什么值得关注：** 这次更新把“发现失败—尝试修复—验证—有限重试—人工接管”做成更完整的自治开发闭环，明确限制了自动修复无限循环与并发状态污染。

- **原文：** [Qwen Code v0.26.5 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.5)
- **发布日期：** 2026-11-01 11:22（新加坡时间；过去 24 小时）

## 2. Microsoft Agent Framework 1.24.0 加入 MCP 默认审批与智能体主动压缩

> **时间范围：扩展至过去 72 小时**

![Microsoft Agent Framework 1.24.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/microsoft/agent-framework/releases/tag/python-1.24.0)

*图片来源：Microsoft Agent Framework 官方 GitHub Release（页面截图）*

Microsoft Agent Framework 1.24.0 为本地 MCP 工具和提示增加显式默认审批模式，并在 `never_require_approval` 未明确默认行为时给出警告。框架新增实验性的“智能体触发运行中压缩”和 Skill 卸载策略、异步工作流条件，以及跨 OpenAI、Anthropic、Gemini、Mistral 等客户端的资源所有权感知清理。版本同时修正 Redis 上下文作用域隔离，拒绝不兼容的旧索引，并把 Python 3.11 设为支持基线。

**为什么值得关注：** 审批默认值、上下文压缩与 Skill 生命周期是生产级智能体运行时的三条关键边界；这次发布把安全控制、长任务内存管理和多模型资源管理统一推进了一步。

- **原文：** [Microsoft Agent Framework Python 1.24.0 Release](https://github.com/microsoft/agent-framework/releases/tag/python-1.24.0)
- **发布日期：** 2026-10-31 05:52（新加坡时间；过去 72 小时）

## 3. Pydantic AI 2.64.0 为 Memory 与 Skills 增加工件安全扫描

> **时间范围：扩展至过去 72 小时**

![Pydantic AI 2.64.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/pydantic/pydantic-ai/releases/tag/v2.64.0)

*图片来源：Pydantic AI 官方 GitHub Release（页面截图）*

Pydantic AI 2.64.0 新增 `ArtifactScanner`，可对智能体的 Memory 与 Skills 工件执行安全扫描，并加入隔离运行 Coder、Shell、FileSystem 等能力的 `BoxdSandbox`。模型层面新增可保持会话黏性的 `ModelFallback`、首事件超时与逐次请求准备钩子，使流式请求迟迟不启动时能够受控切换。版本还让共享用量的子智能体继承父级 `usage_limits`，并确保后台工具结果在运行因延迟工具而暂停时仍保留在历史中。

**为什么值得关注：** 智能体供应链风险正从代码依赖扩展到记忆、Skill 和运行工件；扫描、沙箱、回退与继承式预算控制组合起来，构成了更完整的生产防线。

- **原文：** [Pydantic AI v2.64.0 Release](https://github.com/pydantic/pydantic-ai/releases/tag/v2.64.0)
- **发布日期：** 2026-10-31 07:27（新加坡时间；过去 72 小时）

## 5. Agno 3.1.12 将 Claude 与 Codex 原生审批接入 AgentOS

> **时间范围：扩展至过去 72 小时**

![Agno 3.1.12 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/agno-agi/agno/releases/tag/v3.1.12)

*图片来源：Agno 官方 GitHub Release（页面截图）*

Agno 3.1.12 将 Claude 和 Codex Harness 自身发出的权限请求路由到 AgentOS 审批界面，决策后可继续原执行而无需重放提示。带数据库的运行会以 `PAUSED` 状态持久化，支持同步或异步继续、取消、过期、进程丢失后的重新附着，并把审批等待和实际执行预算分开。CodexAgent 若未显式配置审批，现在默认采用原生 `on-request` 策略，并由默认 900 秒的 `hitl_timeout` 限制等待时间。

**为什么值得关注：** 这解决了多智能体平台集成 Claude/Codex 时常见的“底层需要批准、上层看不到也无法恢复”问题，为跨 Harness 的可靠人机协作提供了可持久化控制面。

- **原文：** [Agno v3.1.12 Release](https://github.com/agno-agi/agno/releases/tag/v3.1.12)
- **发布日期：** 2026-10-29 22:00（新加坡时间；过去 72 小时）
