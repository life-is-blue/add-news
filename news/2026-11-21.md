## 1. Claude Code 2.1.330：企业统一登录与自托管 Runner 进入可观测阶段

![Claude Code 2.1.330 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.330)

*配图来源：[Anthropic Claude Code 官方 GitHub Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.330)*

Claude Code 2.1.330 支持登录由 Anthropic Enterprise Admin Console 管理的组织，并自动应用组织设置、云提供商或网关；自托管 Runner 新增仓库内起始目录以及从工单发出到注册、首个会话交付的延迟指标。该版还修复长对话压缩后冻结、并发会话误删仍在使用的 worktree、并发保存丢设置、MCP 子智能体过早关闭共享服务器，以及任务依赖与元数据并发更新丢失等问题。

**为什么值得关注：** 这次更新同时补上企业治理、运行时指标和并发状态正确性，使 Claude Code 更接近可被平台团队规模化运营的开发基础设施，而不只是单人终端工具。

- **原文：** [Claude Code 2.1.330 Release Notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.330)
- **发布日期：** 2026-11-21（新加坡时间）

## 2. OpenAI Agents SDK 1.0.0 Alpha：Codex Core 可直接嵌入 Python 智能体

![OpenAI Agents SDK 1.0.0 Alpha 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/openai-agents-python/releases/tag/v1.0.0-alpha.1)

*配图来源：[OpenAI Agents SDK 官方 GitHub Release](https://github.com/openai/openai-agents-python/releases/tag/v1.0.0-alpha.1)*

OpenAI 发布 Agents SDK v1.0.0-alpha.1，首次把 Codex 作为可选模型提供商接入 Python SDK，可按运行选择 `CodexProvider`，并复用现有 Codex 登录或 API Key。预览轮子通过 PyO3 直接嵌入未经修改的 Codex Core，省去启动 app-server 与 JSON-RPC 的开销，同时保留 SDK 工具、交接、审批、类型化输出和 Codex 原生沙箱语义；官方称四个平台轮子均完成校验和及安装测试。

**为什么值得关注：** Codex 的执行内核不再只能通过 CLI 或外部进程使用，Python 团队可以把代码执行、审批和多智能体编排放进同一个运行时；但这是 Alpha，检查点格式与接口仍可能变化。

- **原文：** [OpenAI Agents SDK v1.0.0-alpha.1 Release Notes](https://github.com/openai/openai-agents-python/releases/tag/v1.0.0-alpha.1)
- **发布日期：** 2026-11-21（新加坡时间）
- **发布阶段：** Alpha 预览

## 3. Qwen Code 0.28.3：托管智能体打通 GitHub、Webhook 与跨会话协作

![Qwen Code 0.28.3 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/QwenLM/qwen-code/releases/tag/v0.28.3)

*配图来源：[Qwen Code 官方 GitHub Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.3)*

Qwen Code 0.28.3 为托管通道加入 GitHub、Microsoft Teams、企业微信与通用 Webhook 适配，并让 `/send` 可把消息发送到另一会话；受监控 PR 在 CI 失败、冲突或提交头变化时还能私下唤醒绑定的智能体。版本同时加入空闲会话挂起与冷启动、跨挂起保留 MCP 连接、Gateway 重启恢复收件箱、后台无头工作流，以及基于权威事件结算提交、取消、审批和提问状态的聊天生命周期控制器。

**为什么值得关注：** 这些能力把“编码助手”推进到面向仓库事件、企业消息通道和长期会话的控制平面；真正的自主开发协作依赖的正是唤醒、恢复、准入和幂等状态，而非单次生成代码。

- **原文：** [Qwen Code 0.28.3 Release Notes](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.3)
- **发布日期：** 2026-11-21（新加坡时间）

## 4. Cline CLI 3.0.75：无人在场的一次性任务默认自动执行，并移除本地配置注入面

![Cline CLI 3.0.75 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/cline/cline/releases/tag/cli-v3.0.75)

*配图来源：[Cline 官方 GitHub Release](https://github.com/cline/cline/releases/tag/cli-v3.0.75)*

Cline CLI 3.0.75 让命令参数或管道输入触发的一次性运行默认进入 yolo 模式，以避免无人值守任务卡在审批；显式关闭自动批准、指定模式、保存为计划模式或使用 `/team` 时仍保留原行为。它还让超时与 Ctrl+C 能中断首轮任务，停止从启动目录读取 `.env` 或 `bunfig.toml`，取消会把完整请求体写盘的调试变量，并加入实验性云会话切换与更完整的文件读取结果。

**为什么值得关注：** 默认自动执行提升 CI 和批处理可用性，也扩大了误操作半径；不再隐式读取当前目录配置则减少了仓库诱导智能体加载凭据或运行时设置的攻击面，二者应被一起评估。

- **原文：** [Cline CLI 3.0.75 Release Notes](https://github.com/cline/cline/releases/tag/cli-v3.0.75)
- **发布日期：** 2026-11-21（新加坡时间）

## 5. GitHub Copilot CLI 1.0.115 预览：ACP 表单澄清与长会话恢复改进

![GitHub Copilot CLI 1.0.115 预览发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/github/copilot-cli/releases/tag/v1.0.115-4)

*配图来源：[GitHub Copilot CLI 官方 GitHub Release](https://github.com/github/copilot-cli/releases/tag/v1.0.115-4)*

GitHub Copilot CLI 的 1.0.115-4 预览版为支持表单的 ACP 编辑器加入结构化澄清问题，并修复插件初始化竞态导致新会话无法启动或既有会话无法恢复，以及 Windows 上 Git、Hook 和语言服务器检查遗留子进程的问题。随后发布的 1.0.115-5 进一步降低长时间本地会话的磁盘占用、加快恢复，并修正排队切换到 Copilot Fusion 时仍显示旧路由配置的反馈错误。

**为什么值得关注：** 结构化澄清能让智能体在执行前收集可验证的选项，插件竞态、子进程回收和会话体积则决定 IDE 与终端集成能否稳定跑过长任务；不过两版均为预览，生产环境宜先灰度验证。

- **原文：** [Copilot CLI 1.0.115-4](https://github.com/github/copilot-cli/releases/tag/v1.0.115-4) · [Copilot CLI 1.0.115-5](https://github.com/github/copilot-cli/releases/tag/v1.0.115-5)
- **发布日期：** 2026-11-21（新加坡时间）
- **发布阶段：** Pre-release
