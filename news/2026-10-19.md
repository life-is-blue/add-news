## 1. OpenClaw 2026.10.5：更新与会话可跨重启自恢复

![OpenClaw 2026.10.5 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.10.5)

*图片来源：[OpenClaw 官方 GitHub Release](https://github.com/openclaw/openclaw/releases/tag/v2026.10.5)*

OpenClaw 2026.10.5 重做更新恢复路径，可处理不同文件系统、pnpm 12、Windows 提权、macOS 登录 shell，以及遗留 handoff lease 和包激活日志，避免安装停在半完成状态。会话层面，因 Gateway 重启中断的回合、工作树准备期首条消息、子智能体工作与延迟任务可继续执行，提交过的会话数据和用户输入也能抵抗并发写入与发布失败。版本还收紧工具审批钩子：插件若改写已批准参数，必须对最终参数重新取得批准，否则调用会被阻止。

**为什么值得关注：** 这次重点不是功能堆叠，而是把“更新、重启、并发写入、插件改参”这些生产故障路径纳入恢复与权限边界；对长期运行的自主智能体而言，这类能力比单次回答质量更决定可用性。

## 3. Letta Code 0.34.17：阻止无效上下文压缩，加入轻量 CodeMode

![Letta Code v0.34.17 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/letta-ai/letta-code/releases/tag/v0.34.17)

*图片来源：[Letta Code 官方 GitHub Release](https://github.com/letta-ai/letta-code/releases/tag/v0.34.17)*

Letta Code v0.34.17 会跳过不能实际缩短上下文的压缩，避免在长会话中付出成本却没有释放窗口；Reflection 提示也同步适配 MemFS v2 的记忆可见性。新版本为简单工具脚本增加 CodeMode，并在监听器连接时启动心跳、就绪前阻止输入，以减少初始化竞态。它还修复审批拒绝后的消息标识保留、恢复数据读取失败时的待审批判断，以及官方 Docker 镜像启动时误触发自动更新等问题。

**为什么值得关注：** 长程编码智能体的稳定性高度依赖“压缩是否真有效、记忆是否可见、审批状态能否恢复”；这些修复直接作用于连续运行和故障恢复，而不只是界面体验。

- **原文：** [Letta Code v0.34.17](https://github.com/letta-ai/letta-code/releases/tag/v0.34.17)
- **发布日期：** 2026-10-19（新加坡时间；GitHub 显示 2026-10-18 22:58 UTC）

## 4. MyAgents 0.5.4：Agent 可跨聊天交接上下文与附件

![MyAgents v0.5.4 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/hAcKlyc/MyAgents/releases/tag/v0.5.4)

*图片来源：[MyAgents 官方 GitHub Release](https://github.com/hAcKlyc/MyAgents/releases/tag/v0.5.4)*

开源 Agent 工作台 MyAgents v0.5.4 新增跨聊天消息交接：Agent 可把消息、背景说明和附件交给同一 Agent 连接的其他聊天，由目标会话结合既有上下文处理。渠道可选择自动回复或仅通过工具发送，并统一处理文本与附件；上下文只注入实际绑定的私聊或群聊信息，普通桌面对话不受渠道指令影响。版本还修复长历史重开、断线恢复、会话卡住、私聊命令授权以及 DSH 失效实例持续收取请求等问题。

**为什么值得关注：** 自主协作正在从“多个子智能体共享任务”走向“跨聊天、跨渠道传递带附件的工作上下文”；同时限定上下文注入范围，是避免渠道数据错误渗入其他会话的重要隔离措施。

- **原文：** [MyAgents v0.5.4](https://github.com/hAcKlyc/MyAgents/releases/tag/v0.5.4)
- **发布日期：** 2026-10-18

## 5. Codex 试验“子智能体消息唤醒已结束的主会话”

![Codex 多智能体唤醒机制提交](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/codex/commit/8c076942cb70fba8e5c4732c23f1faabc4aed484)

*图片来源：[OpenAI Codex 官方仓库提交](https://github.com/openai/codex/commit/8c076942cb70fba8e5c4732c23f1faabc4aed484)*

**【扩展至 72 小时】** Codex 主分支加入默认关闭的 `wake_on_agent_messages` 功能：当 worker 在父会话给出最终答案后才完成时，其消息可启动新的根会话回合，而不再依赖仍存在的 durable sleep。新回合复用上一轮上下文；自动唤醒不会用于已中断会话、Plan 模式或子智能体，以避免递归唤醒和越过交互边界。官方测试覆盖直接投递与主机邮箱两条路径、只唤醒一次，以及子智能体结束后唤醒父会话的完整场景。

**为什么值得关注：** 这补上了异步多智能体协作的关键缺口：主智能体不必为了等待慢 worker 而一直保持前台回合。由于功能仍处于开发阶段且默认关闭，它更像明确的架构方向，而不是已经稳定发布的用户能力。

- **原文：** [OpenAI Codex commit 8c07694](https://github.com/openai/codex/commit/8c076942cb70fba8e5c4732c23f1faabc4aed484)
- **发布日期：** 2026-10-18
