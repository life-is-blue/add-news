## 1. Anthropic 发布 MHS：让 AI 智能体安全操作实验室与工业设备

![Anthropic Model Hardware Standard：Claude 通过 MHS 控制物理设备](https://www.anthropic.com/_next/image?q=75&url=https%3A%2F%2Fwww-cdn.anthropic.com%2Fimages%2F4zrzovbb%2Fwebsite%2F2a5e4365820413ed405e122bfefb15d711f793d6-1760x790.png&w=3840)

*图片来源：[Anthropic 官方公告](https://www.anthropic.com/news/model-hardware-standard-research-preview)*

Anthropic 开放 Model Hardware Standard（MHS）研究预览，以统一驱动和一组简单原语，让智能体发现、读取和控制显微镜、液体处理器、机械臂及量子设备等可编程硬件。MHS 与模型无关，可通过 MCP、CLI 或代码 API 接入；首批合作方包括 Genentech、HHMI Janelia、QuEra、AWS、Universal Robots 和 Hugging Face，Anthropic 计划在完成安全评估后开源。官方案例称，QuEra 的智能体把激光失锁恢复成功率从 58% 提高到 99.3%，但 Anthropic 也明确指出空间与物理推理仍需要专家监督。

**为什么值得关注：** MCP 解决的是智能体如何调用软件工具，MHS 则把同一标准化思路推向物理世界；这会把权限边界、硬件联锁、人工审批和事故追踪从“最佳实践”升级为智能体基础设施的必备层。

- **原文：** [Anthropic：Previewing the Model Hardware Standard](https://www.anthropic.com/news/model-hardware-standard-research-preview)
- **交叉核验：** [Reuters 报道](https://www.reuters.com/technology/anthropic-unveils-new-framework-allowing-ai-agents-operate-physical-devices-2026-08-27/)
- **发布日期：** 2026-08-27
- **时间窗口：** 过去 24 小时

## 2. Codex 正测试“持续模式”：任务完成后还能主动生成后续工作

![WIRED 对 Codex Persistent mode 的报道配图](https://media.wired.com/photos/6a905cdd60f4c0fdadcc5237/master/w_2560%2Cc_limit/Model-Behavior-Illo-Template.jpg)

*图片来源：[WIRED](https://www.wired.com/story/openai-is-developing-persistent-ai-agent/)*

WIRED 检查 Codex 开源代码后发现，OpenAI 正测试 Persistent mode：智能体会“持续工作直到被休眠”，并可基于过往交互和用户知识主动创建跨会话后续任务、在必要时主动通知用户。OpenAI 产品负责人向 WIRED 确认该功能处于测试阶段，但表示目前没有立即发布计划；相关指令同时强调，持续模式不会扩大既有权限，对用户系统之外的修改仍须批准。由于功能尚未正式推出，这是一项经 OpenAI 确认的开发中实验，而不是产品发布。

**为什么值得关注：** 从“执行一次任务”转向“维持长期目标”是编码智能体能力边界的跃迁，也会放大任务漂移、预算失控和长期权限积累；尤其在本周多智能体越界事件之后，持续性与可停止性将成为产品设计的核心矛盾。

- **原文：** [WIRED：OpenAI Is Developing a ‘Persistent’ AI Agent](https://www.wired.com/story/openai-is-developing-persistent-ai-agent/)
- **代码证据：** [OpenAI Codex 开源仓库变更（由 WIRED 引用）](https://github.com/openai/codex)
- **发布日期：** 2026-08-28
- **时间窗口：** 过去 24 小时

## 3. GitHub 复盘 OpenClaw 爆发式增长：治理与供应链安全成为主线

![OpenClaw 爆发式增长与维护者团队](https://github.blog/wp-content/uploads/2026/08/OpenClaw-1.png?resize=1024%2C576)

*图片来源：[GitHub Blog](https://github.blog/open-source/maintainers/openclaw-went-viral-meet-the-maintainers-building-and-securing-it/)*

GitHub 发布对 Peter Steinberger 及 OpenClaw 维护者的访谈，称该项目截至 8 月 26 日约有 38.8 万 stars、8.1 万 forks 和超过 8 万次提交，并将其描述为 GitHub 历史上增长最快的项目。维护团队总结了高速增长下的现实问题：海量 PR、贡献者信任、代码审查瓶颈以及软件供应链风险，并分享参与 GitHub Secure Open Source Fund 后的安全改进经验。文章的重点不是新增功能，而是一个个人智能体项目如何在半年内被迫演化出正式的治理与安全机制。

**为什么值得关注：** OpenClaw 正好暴露了开放式智能体生态的双刃剑——插件、渠道和贡献者越多，能力增长越快，攻击面与维护成本也同步扩大；这对 Hermes 等快速成长的开源智能体同样具有直接参考价值。

- **原文：** [GitHub：OpenClaw went viral. Meet the maintainers building and securing it](https://github.blog/open-source/maintainers/openclaw-went-viral-meet-the-maintainers-building-and-securing-it/)
- **发布日期：** 2026-08-27
- **时间窗口：** 过去 24 小时

## 4. GitHub Copilot Code Review 开始完整评审智能体 PR 与超大变更

![Copilot Code Review 的评论解决原因界面](https://github.blog/wp-content/uploads/2026/08/642427460-c76a799a-c155-49c3-b440-8ec1a88ffc0d.jpg?resize=2064%2C1096)

*图片来源：[GitHub Changelog](https://github.blog/changelog/2026-08-27-copilot-code-review-resolution-reasons-and-expanded-capabilities/)*

GitHub 扩大 Copilot Code Review 覆盖面：自动请求评审时，它现在可完整评审机器人创建的 PR，包括 Copilot cloud agent 的 PR，而不再退化为受限体验。GitHub 同时取消此前每个 PR 最多 300 个文件或 20,000 行代码的评审上限，并允许用户把评论关闭原因标记为“已处理”“不修复”或“判断错误”。机器人 PR 的评审费用可在启用相应组织策略后直接计入组织账户。

**为什么值得关注：** 当编码智能体显著提高 PR 数量和改动规模时，评审能力必须同步自动化；而结构化记录“判断错误”也为后续校准 AI 评审器、衡量误报率提供了关键反馈数据。

- **原文：** [GitHub Changelog：Copilot code review—Resolution reasons and expanded capabilities](https://github.blog/changelog/2026-08-27-copilot-code-review-resolution-reasons-and-expanded-capabilities/)
- **发布日期：** 2026-08-27
- **时间窗口：** 过去 24 小时

## 5. Harness 推出面向智能体规模的代码仓库与 AI 审查层

![Harness 的智能体技能与软件交付工具链](https://opengraph.githubassets.com/c2015dc4d6c0bb2ceac512d741ab3ac5e60c0840c04392e729e7f7b766ff2855/harness/harness-skills)

*图片来源：[Harness 官方 GitHub 组织](https://github.com/harness/harness-skills)*

Harness 发布 Agent-Ready Code Repository 与 AI Code Review，目标是承受数千个并发 PR/提交，并为智能体提供继承自触发者、可进一步限制到仓库、分支或环境的权限；RBAC 与 OPA 策略负责在合并前强制执行边界。仓库与审查能力均可经 MCP 和 CLI 访问，AI Review 可按风险重组 diff、设置阻断合并的强制检查，并连接 Harness 的交付知识图谱获取生产上下文。Harness 声称内部每月节省超过 10,000 小时人工审查时间，这一数字属于厂商自报，尚无独立验证。

**为什么值得关注：** 这代表基础设施厂商开始假设“代码主要由智能体批量产生”，并据此重做源代码管理、身份权限和合并门禁；竞争焦点正从谁能写更多代码，转向谁能安全地接住、审查和交付这些代码。

- **原文：** [Harness：Agent-Ready Code Repository and AI Code Review](https://www.harness.io/press-and-news/harness-launches-code-repository-with-ai-code-review)
- **发布日期：** 2026-08-27
- **时间窗口：** 过去 24 小时
