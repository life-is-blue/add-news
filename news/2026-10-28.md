## 1. Codex CLI 0.165.0：接入 Vertex AI，默认启用跨智能体记忆导入

![Codex CLI 0.165.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/codex/releases/tag/rust-v0.165.0)

*图片来源：OpenAI Codex 官方 GitHub Release（页面截图）*

Codex CLI 0.165.0 新增内置 Google Cloud Vertex AI 提供方、GPT-6.1 Terra 模型目录，以及会话选择器的仓库筛选和 Agent Command Center 的目录分组。新版还默认启用 Memory v2，并支持导入外部智能体记忆；同时开放实验性的附着式线程 fork，并允许受支持模型在会话中途调整推理强度。可靠性方面，远程 MCP 请求会在本地等待方被释放时取消，排队消息也不会在中断或切换到 Plan 模式后意外重启任务。

**为什么值得关注：** 这次更新把多云模型接入、跨智能体记忆迁移、线程分叉和中断语义集中到同一版本，显示 Codex 正从单会话 CLI 继续向多任务、长程协作控制面演进。

- **原文：** [OpenAI Codex 0.165.0 Release](https://github.com/openai/codex/releases/tag/rust-v0.165.0)
- **发布日期：** 2026-10-28（新加坡时间；过去 24 小时）

## 2. Claude Code 2.1.312 修正超大指令文件覆盖与组织策略失效

![Claude Code 2.1.312 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.312)

*图片来源：Anthropic Claude Code 官方 GitHub Release（页面截图）*

Claude Code 2.1.312 修复了一项数据安全问题：当 `CLAUDE.md`、rules 或 `@include` 文件过大而只读取到开头时，Claude 不再直接覆盖该文件，Write 工具会要求先完整读取或改用局部编辑。版本还修复了从 VS Code 扩展登录后，托管设置与组织策略在后续会话中不再获取的问题，并恢复 Bash `cd` 深入仓库后对目录级和 `paths:` skills 的发现。企业网关另新增 `oidc.user_id_claim`，可用 Microsoft Entra ID 的 `oid` 等 claim 识别用户。

**为什么值得关注：** 指令文件决定编码智能体的行为边界，而企业策略决定其权限边界；两者一旦因截断或登录状态失效，都可能造成“看似正常、实际越界”的执行。

- **原文：** [Anthropic Claude Code v2.1.312 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.312)
- **发布日期：** 2026-10-28（新加坡时间；过去 24 小时）

## 3. Dapr Agents 1.1.0 修复工具调用 ID 复用导致的结果丢失

![Dapr Agents 1.1.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/dapr/dapr-agents/releases/tag/v1.1.0)

*图片来源：Dapr Agents 官方 GitHub Release（页面截图）*

Dapr Agents 1.1.0 修复了后续轮次复用同一 `tool_call_id` 时旧工具结果被丢弃的问题，避免长对话中的调用记录被错误覆盖。该版本还为 MCP 重连失败但继续保留旧配置的情况增加警告，并补齐向量存储可选依赖中的 `redisvl`。

**为什么值得关注：** 工具调用结果是智能体状态机的事实基础；如果 ID 复用破坏历史结果，模型可能基于不完整轨迹继续决策，而重连警告则让“运行中配置与预期配置不一致”变得可观测。

- **原文：** [Dapr Agents v1.1.0 Release](https://github.com/dapr/dapr-agents/releases/tag/v1.1.0)
- **发布日期：** 2026-10-28（新加坡时间；过去 24 小时）

## 4. Kilo Code 7.8.20 预发布：Agent Manager 可选择工作树基线分支

![Kilo Code 7.8.20 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/Kilo-Org/kilocode/releases/tag/v7.8.20)

*图片来源：Kilo Code 官方 GitHub Release（页面截图）*

Kilo Code 7.8.20 预发布版允许智能体在 Agent Manager 创建 worktree 会话时选择基线分支，使并行任务不必全部从固定默认分支派生。版本还将 VS Code 扩展中的 Zod 升级到修复版本，以缓解验证超大受限集合时可能触发的内存耗尽安全问题。

**为什么值得关注：** 让智能体显式选择基线分支，可减少并行开发从错误代码状态起步的风险；与此同时，输入验证层的资源耗尽修复提醒开发者，智能体环境的安全面也包括解析器和模式校验器。

- **原文：** [Kilo Code v7.8.20 Pre-release](https://github.com/Kilo-Org/kilocode/releases/tag/v7.8.20)
- **发布日期：** 2026-10-28（新加坡时间；过去 24 小时）
- **状态：** 预发布版本

## 5. Cline 4.1.26 分离本地与云端模型配置，强化托管任务可见性

> **时间范围：扩展至过去 72 小时**

![Cline 4.1.26 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/cline/cline/releases/tag/v4.1.26)

*图片来源：Cline 官方 GitHub Release（页面截图）*

Cline 4.1.26 为已启用云会话的用户增加 Local / Cloud 模型切换，并把新云任务使用的模型独立于本地配置保存。启动或恢复云端沙箱时，界面会展示仓库、分支以及“启动沙箱—克隆仓库—启动智能体”的进度卡；模型请求的最大重试次数也从 5 次降至 3 次。同期 CLI 更新还避免同一运行中任务被第二个客户端重复启动，并为 Hub 健康检查加入 3 秒超时。

**为什么值得关注：** 自主编码从本机迁移到托管沙箱后，模型选择、仓库状态、任务归属和故障超时都必须显式化；这次更新补齐的正是云端智能体协作中的运营控制面。

- **原文：** [Cline v4.1.26 Release](https://github.com/cline/cline/releases/tag/v4.1.26)
- **发布日期：** 2026-10-26（过去 72 小时）
