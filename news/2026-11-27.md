## 1. Qwen Code 0.28.7 切换 Harness 内核，并重构会话接管机制【过去 24 小时】

![Qwen Code 0.28.7 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/QwenLM/qwen-code/releases/tag/v0.28.7)

*图片来源：[Qwen Code 官方 GitHub Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.7)（发布页面截图）*

Qwen Code 0.28.7 新增基于 Harness 内核的 CLI 产品包，并允许兼容 Claude Code 2.1.332 的 Mods 加载命令与界面组件。托管会话现可在控制平面之间重新附着和接管，SQL 化的 Web Terminal 票据及跨副本事件同步则改善集群恢复能力。该版同时带来一项破坏性变化：不再检测模型循环或限制工具调用次数，而是把工具结果与错误原样交给模型处理。

**为什么值得关注：** 这不是普通界面更新，而是对编码智能体运行时、故障恢复和工具循环控制权的重新划分；取消工具调用上限提升模型自主性，也要求部署方用预算、超时和外部策略防止失控循环。

## 2. OpenCode 2.4.2 收紧网页授权，并让自动化从失败中继续【扩展至 72 小时】

![OpenCode 2.4.2 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anomalyco/opencode/releases/tag/v2.4.2)

*图片来源：[OpenCode 官方 GitHub Release](https://github.com/anomalyco/opencode/releases/tag/v2.4.2)（发布页面截图）*

OpenCode 2.4.2 将网页抓取的“始终允许”权限收窄到单一站点，而不再放行所有 URL；旧版本已保存的授权保持不变。自动化任务在一次运行失败后会记录失败并按原计划继续，超时的 Shell 命令也会被终止，而非转入后台继续执行。该版还为 GPT-6.2 Sol、Astra 与 `gpt-latest` 提供专用系统提示，并修复 Plan 模式压缩后反复注入提醒所造成的循环。

**为什么值得关注：** 更新同时触及权限最小化、定时任务容错和长会话循环三个生产级痛点，表明编码智能体的竞争焦点正从“能否写代码”转向“能否长期、受控地运行”。

- **原文：** [OpenCode v2.4.2 发布说明](https://github.com/anomalyco/opencode/releases/tag/v2.4.2)
- **交叉核验：** [OpenCode 官方 Changelog](https://opencode.ai/changelog)
- **发布日期：** 2026-11-26

## 3. Goose 1.61.1 清除导入会话的旧授权，避免自动执行工具【扩展至 72 小时】

![Goose 1.61.1 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/aaif-goose/goose/releases/tag/v1.61.1)

*图片来源：[Goose 官方 GitHub Release](https://github.com/aaif-goose/goose/releases/tag/v1.61.1)（发布页面截图）*

Goose 1.61.1 在导入会话时丢弃原有的工具审批状态，避免加载历史会话后自动执行此前获准的工具。导入流程仍保留本地扩展和 Goose 模式，但移除配方重试、配方值、容器与提供商会话 ID 等环境相关状态。桌面应用同时移除 dotenv，防止意外加载工作目录中的环境变量。

**为什么值得关注：** 会话迁移和恢复是长程智能体的基础能力，但授权与环境变量如果被无条件继承，会把历史信任错误地带入新机器或新上下文；这一修复体现了“可恢复”与“可安全恢复”之间的关键差别。

- **原文：** [Goose v1.61.1 发布说明](https://github.com/aaif-goose/goose/releases/tag/v1.61.1)
- **交叉核验：** [Goose 官方构建证明](https://github.com/aaif-goose/goose/attestations)
- **发布日期：** 2026-11-26

## 4. GitHub Copilot CLI 1.0.116 加强 MCP 启动、沙箱授权与长会话内存控制【扩展至 72 小时】

![GitHub Copilot CLI 1.0.116 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/github/copilot-cli/releases/tag/v1.0.116)

*图片来源：[GitHub Copilot CLI 官方 Release](https://github.com/github/copilot-cli/releases/tag/v1.0.116)（发布页面截图）*

Copilot CLI 1.0.116 可为其启动的 Shell、LSP、MCP、Hook 与扩展进程统一设置环境变量，并在插件与独立 MCP 服务连接同一端点时发出冲突警告。启动提示、仓库提示和恢复的定时任务会等待受信目录所启动的 MCP 服务最多 30 秒，使首轮请求就能获得完整工具集；ACP 客户端的 Shell 审批也改为展示实际命令。版本还修复流式回复文本缓存导致的长会话内存持续增长，并强化会话恢复、沙箱阻断提示和权限决定的后续撤回。

**为什么值得关注：** MCP 工具何时就绪、用户究竟批准了什么命令，以及长会话是否会耗尽内存，都会直接影响自主开发任务的可靠性；这次更新集中补强了这些“代理运行层”细节。

- **原文：** [GitHub Copilot CLI v1.0.116 发布说明](https://github.com/github/copilot-cli/releases/tag/v1.0.116)
- **发布日期：** 2026-11-26（新加坡时间；GitHub 发布于 2026-11-25 17:03 UTC）

VS Code 1.148 可让智能体从现有会话创建隔离的 Linux Dev Container，并在新会话中继续任务后回报结果，而无需预先编写容器配置。新的远程沙箱配置档可按主机保存网络和执行规则，组织级策略继续叠加生效；活跃智能体还可在支持的主机上阻止系统休眠。Agent Host Protocol 1.1.0 同期加入 TCP 端口转发、跨会话移动聊天、按聊天选择 Harness，以及通过 MCP 表示 SEP-2640 Skills 的能力。
