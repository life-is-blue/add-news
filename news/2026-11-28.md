## 1. Qwen Code 0.29.0：托管 Harness 可从 Broker 故障中恢复执行

![Qwen Code 0.29.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/QwenLM/qwen-code/releases/tag/v0.29.0)

*图片来源：[Qwen Code 官方 GitHub 发布页](https://github.com/QwenLM/qwen-code/releases/tag/v0.29.0)（页面截图）*

Qwen Code 0.29.0 为 Hosted Harness 增加了 Turn 中断恢复：Broker 故障转移后，系统会重新核验结果与检查点再继续执行。该版还让工作区记忆可跨任务 worktree 持久化，并强化了 PR 验证的主机选择、信任确认及 KVM／Apple Silicon 隔离能力；同时支持 OpenAI、Anthropic 兼容自定义端点自动获取模型列表。配套 TypeScript SDK 0.1.40 同日发布，进一步印证了 CLI 0.29.0 的版本落地。

**为什么值得关注：** 长任务能否在基础设施故障后可靠续跑，正是编码智能体从交互式助手走向托管式工程执行的关键门槛；跨 worktree 记忆和隔离验证也直接影响多任务并行的可用性与安全性。

- **原文：** [Qwen Code v0.29.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.29.0)；[TypeScript SDK v0.1.40](https://github.com/QwenLM/qwen-code/releases/tag/sdk-typescript-v0.1.40)
- **发布日期：** 2026-11-28（过去 24 小时）

## 2. GitHub Copilot CLI 1.0.117：收紧 MCP 与子智能体权限边界

![GitHub Copilot CLI 1.0.117 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/github/copilot-cli/releases/tag/v1.0.117)

*图片来源：[GitHub Copilot CLI 官方 GitHub 发布页](https://github.com/github/copilot-cli/releases/tag/v1.0.117)（页面截图）*

Copilot CLI 1.0.117 修复了 MCP 服务器名与内置权限类型重名时，审批结果可能外溢到内置工具权限的问题；自定义智能体与子智能体也会更严格地遵守声明的工具清单。该版还要求 Autopilot 在启动扩展前征得确认，使 worktree 设置保持只读，并让后台智能体在重启或恢复会话后继续运行。企业环境方面，沙箱 TLS 代理新增自定义 CA 支持。

**为什么值得关注：** 当 CLI 同时调度 MCP、扩展和子智能体时，“一次批准只对一个明确能力生效”是最小权限模型的核心；本次修复把工具编排的便利性与权限隔离拉回同一条安全边界。

- **原文：** [GitHub Copilot CLI v1.0.117](https://github.com/github/copilot-cli/releases/tag/v1.0.117)
- **发布日期：** 2026-11-27（过去 24 小时）

## 3. Hermes Agent 0.23.5：补齐会话恢复、后台压缩与插件生命周期能力

![Hermes Agent 0.23.5 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.5)

*图片来源：[Hermes Agent 官方 GitHub 发布页](https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.5)（页面截图）*

Hermes Agent 0.23.5 汇总了自 0.23.4 以来的大规模改动，并在 CLI／TUI 中实现 OSC 7577 程序恢复协议。网关聊天可在空闲时对各路由执行后台上下文压缩，`read_file` 支持负偏移读取文件尾部与目录列举；插件 API 则新增会话创建、定时调度、静默响应与 Turn 来源等接口。版本还加入插件 OAuth 回调地址固定、默认插件预检边界，以及多项 profile 绑定修复。

**为什么值得关注：** 这批变化并非单纯增加工具，而是围绕长会话的可恢复性、上下文治理和插件安全做系统性加固，为长期驻留型个人智能体减少状态丢失与扩展失控风险。

- **原文：** [Hermes Agent v0.23.5](https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.5)
- **发布日期：** 2026-11-28（过去 24 小时）

## 5. Pydantic 推出 Pax：把编码智能体拆成可替换的 Harness 插件

> **时间标注：扩展至过去 72 小时**

![Pydantic Pax 发布文章](https://image.thum.io/get/width/1200/crop/675/noanimate/https://pydantic.dev/articles/pax-harness-beta)

*图片来源：[Pydantic 官方 Pax 发布文章](https://pydantic.dev/articles/pax-harness-beta)（页面截图）*

Pydantic 发布 Pax（`pydantic-ai-pax`）测试版：一个构建在 Pydantic AI Harness SDK 上的终端编码智能体，编码器、沙箱、MCP、可观测性和交互组件均可通过插件替换。Pax 也能通过 `--agent` 直接运行任意 Pydantic AI agent；其底层 Harness 统一了本地与云端 workspace，并提供子智能体、记忆、上下文、文件／Shell 工具及 Agent Skills 等能力。官方公布了早期 SWE81 结果，但也明确完整方法、重复运行和最终评测将在 1.0 前后补充，因此现阶段不宜把该分数视为独立验证结论。

**为什么值得关注：** Pax 把“编码代理产品”改造成可组合的运行时：团队可以替换模型、沙箱、工具和界面而不重写整套智能体，有利于形成可审计、可复用的自主开发基础设施。

- **原文：** [Pax Harness Beta 官方文章](https://pydantic.dev/articles/pax-harness-beta)；[Pax 官方文档](https://ai.pydantic.dev/pax/)
- **发布日期：** 2026-11-25（扩展至过去 72 小时）
