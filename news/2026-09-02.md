## 1. Claude Fable 5.1 与 Mythos 5.1 发布：长任务更强，智能体成本下降

![Claude Fable 5.1 与 Mythos 5.1 发布页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.anthropic.com/claude-fable-and-mythos-5-1)

*图片来源：[Anthropic 官方公告](https://www.anthropic.com/claude-fable-and-mythos-5-1)*

Anthropic 发布基于同一底层模型、采用不同安全等级的 Claude Fable 5.1 与 Mythos 5.1：Fable 5.1 已普遍开放，Mythos 5.1 仅通过可信访问计划提供。官方测试中，Fable 5.1 在 Terminal-Bench 4.0 得分 55.8%，高于 Fable 5 的 42.0%；由于缓存读取降价，典型按量工作负载预计便宜约 25%，高度智能体化任务最高可节省约 45%。Claude Code 默认以 High effort 运行 Fable 5.1，新版网络安全防护的误拦截次数也预计减少约 60%，并允许模型用于发现软件漏洞，但仍限制漏洞利用生成。

**为什么值得关注：** 这不是单纯的榜单升级，而是同时改善长时编码能力、缓存成本与安全策略精度；对持续运行的 Claude Code 工作流，单位任务成本和误阻断率往往比单次推理分数更直接决定可用性。

- **原文：** [Claude Fable 5.1 and Mythos 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1)
- **交叉核验：** [GitHub Copilot 可用性与数据保留说明](https://github.blog/changelog/2026-09-01-claude-fable-5-1-generally-available-in-github-copilot)
- **发布日期：** 2026-09-01

## 2. OpenAI 确认 Astra 达到“关键级”网络安全能力

![OpenAI Astra 安全公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://openai.com/index/path-to-astra/)

*图片来源：[OpenAI 官方公告](https://openai.com/index/path-to-astra/)*

OpenAI 将即将发布的 Astra 认定为其首个达到 Preparedness Framework“关键级”网络安全能力门槛的模型：在合适工具与权限下，它能在缺少逐步人工指导时发现未知漏洞并构造利用方式。Astra 在公开 ExploitBench 上取得 100%，并在内部近期开源漏洞集上以更少输出令牌实现显著更高的任意代码执行率；评测期间还发现并利用了两个正向维护者披露的零日漏洞。OpenAI 表示已为此推迟部分开发与发布，加入推理链监控、自动停止可疑行为等措施，高级网络安全能力将先面向受控测试者和 Daybreak Blue 用户。

**为什么值得关注：** 编码模型已经越过“辅助审计已知缺陷”的边界，开始具备自主发现和串联未知漏洞的能力；这会同时放大防守效率与滥用风险，也让沙箱、权限审查和运行时监控成为模型发布的一部分。

- **原文：** [Path to Astra: critical capabilities and frontier safeguards](https://openai.com/index/path-to-astra/)
- **发布日期：** 2026-09-01

## 3. Harness-of-Harness：用迭代外层编排实现多日自主开发

![Harness-of-Harness 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.01481)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2609.01481)*

上海人工智能实验室等机构提出 Harness-of-Harness（HoH），在现有编码智能体外再加一层规划—编码—测试循环，并把修复、能力扩展、独立验收和版本化历史组织成可持续迭代。论文在 Codex + GPT-5.5、OpenCode + DeepSeek-V4-Pro、Pi + MiniMax-M3 三种组合及三个基准上报告平均相对提升 52.25%，三轮后的最高提升为 82.86%。在超过 70 次迭代的多日实验中，HoH 自主完成了一款包含剧情、核心机制、视觉和音频的可玩第一人称射击游戏。

**为什么值得关注：** 研究焦点从“选哪个模型”转向“如何设计模型外的开发控制循环”，与架构—实现—验收的三层协作思路高度一致；不过结果仍来自作者自报的新基准，需要后续独立复现。

- **原文：** [Harness-of-Harness: Multi-Day Autonomous Software Development with Continual Improvement](https://arxiv.org/abs/2609.01481)
- **发布日期：** 2026-09-01（UTC 16:17 提交）

## 4. AWS 给出智能体从 POC 到生产的权限隔离范式

![Amazon Quick 智能体生产安全实践](https://image.thum.io/get/width/1200/crop/675/noanimate/https://aws.amazon.com/blogs/machine-learning/securing-amazon-quick-from-poc-to-production-agents-flows-and-spaces/)

*图片来源：[AWS Machine Learning Blog](https://aws.amazon.com/blogs/machine-learning/securing-amazon-quick-from-poc-to-production-agents-flows-and-spaces/)*

AWS 发布 Amazon Quick 智能体生产化指南，强调不要只依赖提示词或界面权限，而应先按受众裁剪数据集、应用行级安全，再让每个 Agent 只连接一个与其权限匹配的数据源。指南进一步要求在共享知识库前排除敏感文档、用对抗查询验证边界，并在任何对外动作前设置人工审批。CloudTrail 审计、Secrets Manager 凭据管理和按资产划分的定期复核被纳入上线检查表。

**为什么值得关注：** 这套模式把安全边界下沉到数据结构和工作流，而不是寄希望于模型“自觉拒绝”；它为企业把原型智能体扩展到多部门、多数据域提供了可直接复用的工程模板。

- **原文：** [Securing Amazon Quick from POC to production: Agents, Flows, and Spaces](https://aws.amazon.com/blogs/machine-learning/securing-amazon-quick-from-poc-to-production-agents-flows-and-spaces/)
- **发布日期：** 2026-09-01

## 5. AIR 获 5000 万美元，瞄准 Skills、插件与 MCP 供应链安全

![AIR 智能体供应链安全报道](https://image.thum.io/get/width/1200/crop/675/noanimate/https://techcrunch.com/2026/09/01/air-raises-50m-to-help-companies-vet-the-skills-and-add-ons-ai-agents-use/)

*图片来源：[TechCrunch / Netanel Tobias](https://techcrunch.com/2026/09/01/air-raises-50m-to-help-companies-vet-the-skills-and-add-ons-ai-agents-use/)*

AI 安全初创公司 AIR 走出隐身阶段，并宣布通过两轮种子融资共获得 5000 万美元，分别由 Sequoia 与 Greenoaks 领投。其平台发现企业内运行的智能体，持续检查它们加载的 Skills、插件、MCP 服务器和外部内容，并在运行时阻断不符合策略的组件或行为。AIR 称其白名单目前会过滤约 27% 的公开扩展，已有 20 多家客户，需求主要来自金融与医药等强监管行业；相关数字仍属于公司自报。

**为什么值得关注：** 智能体扩展正在形成类似软件包与驱动程序的新供应链，而 Skill 或 MCP 依赖可在获准后被更新、接管或投毒；资本开始集中押注“持续复核”而非一次性扫描，说明智能体治理正成为独立基础设施层。

- **原文：** [TechCrunch 报道](https://techcrunch.com/2026/09/01/air-raises-50m-to-help-companies-vet-the-skills-and-add-ons-ai-agents-use/)
- **交叉核验：** [SiliconANGLE](https://siliconangle.com/2026/09/01/air-security-launches-with-50m-to-build-a-firewall-for-ai-agents/)
- **发布日期：** 2026-09-01
