## 1. Claude Code 2.1.292：子智能体可指定推理强度，插件与调度边界继续收紧

![Claude Code 2.1.292 发布页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.292)

*图片来源：[Anthropic Claude Code 官方 GitHub 发布页](https://github.com/anthropics/claude-code/releases/tag/v2.1.292)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-06
- **事实摘要：**Anthropic 为 Agent 工具加入 `effort` 参数，让主代理可按任务为子智能体指定推理强度；workflow agent 也进入 `agent.spawn` 插件钩子，使组织或插件能够在生成前拒绝特定工作流代理。版本同时修复自动权限模式不可用时子代理仍进入 auto mode、插件钩子重启期间工具绕过权限检查、UNC 网络路径读取绕过提示，以及恢复会话后计划任务与后台 `/loop` 丢失等问题。插件安装还新增 `--marketplace <source>`，但继续沿用 marketplace 的策略检查。
- **为什么值得关注：**推理预算、代理生成与工具授权开始进入同一套可编程控制面；这让多智能体编排更精细，也要求团队把插件重启、会话恢复和后台调度纳入安全与可靠性测试。
- **原文链接：**[Claude Code v2.1.292](https://github.com/anthropics/claude-code/releases/tag/v2.1.292)

## 2. GitHub 重构 Git 基础设施，为单仓库数千智能体并发做准备

![GitHub 面向智能体规模的 Git 基础设施文章](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/)

*图片来源：[GitHub 官方工程博客](https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-06
- **事实摘要：**GitHub 披露，2026 年 9 月开发者与智能体共产生 73.8 亿次提交，为一年前的五倍以上；月度 Git 活动也从 2182 亿增长到 4733 亿次，推动其重新设计存储与计算架构。新方案把权威仓库数据放在 Azure Blob Storage，将读取交给可弹性扩缩的缓存型计算节点，并把对象存储、连通性验证、密钥扫描和维护任务移出引用更新的关键路径。GitHub 称内部基准最高实现 35 倍写入吞吐，同时保留分支保护、审批、审计日志等治理控制。
- **为什么值得关注：**当代理频繁 checkpoint、并行推送并触发海量 CI 读取时，传统“多份完整仓库副本同时承担持久化与服务”的设计会先在写入端遇到上限；GitHub 正把智能体规模从产品功能问题提升为底层分布式系统问题。
- **原文链接：**[GitHub Engineering](https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/)

## 3. Anthropic 扩展 Cyber Verification Program，以三档权限开放高级网络安全能力

![Anthropic Cyber Verification Program 公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.anthropic.com/news/cyber-verification-program)

*图片来源：[Anthropic 官方公告](https://www.anthropic.com/news/cyber-verification-program)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-06
- **事实摘要：**Anthropic 将 Project Glasswing 与原 Cyber Verification Program 合并为 Defense、Red Team、Specialized 三档验证访问，向合资格安全团队提供 Opus 5.5、Sonnet 5.5、Mythos 5.1 等模型及不同程度降低的网络安全拦截。其 CyScenarioBench 测试显示，Defense 档 50 次试验中有 46 次在过程中被拦截；Red Team 档无拦截并完成 34 次，与无安全限制时 67.6% 的成功率接近。Anthropic 还称合作方在 2026 年 4–7 月发现至少 12.9 万个已验证漏洞，但该数字来自部分合作方报告，官方明确提示覆盖和修补数据不完整。
- **为什么值得关注：**这是把“高能力模型 + 身份验证 + 分级授权 + 持续监控”产品化的一次重要尝试；对自动漏洞发现与修复智能体而言，未来访问能力可能不再只由模型决定，还取决于组织资质、目标授权和数据治理。
- **原文链接：**[Anthropic 官方公告](https://www.anthropic.com/news/cyber-verification-program)

## 4. GitHub Stacked Pull Requests 正式可用，支持工作树与代理工作流

![GitHub Stacked Pull Requests 正式发布](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-06-stacked-pull-requests-generally-available/)

*图片来源：[GitHub 官方更新页面](https://github.blog/changelog/2026-10-06-stacked-pull-requests-generally-available/)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-06
- **事实摘要：**GitHub 宣布 Stacked Pull Requests 全面可用，可把大型变更拆成彼此依赖、可独立审查的多个 PR；预览期间，使用 stacks 的仓库相较同类仓库合并代码量提高 9%，头部 1% 仓库中超过三分之二已采用，合并时间改善 5%。正式版在基线前移时保留未变代码的审批、为 rebase 后提交签名、将整组 stack 作为一个 merge queue group，并让分支型 stack 自动重定向；`gh stack` 也加入 Git worktree 支持，`pull_request` webhook 新增 `stacked` 事件。
- **为什么值得关注：**依赖明确的小 PR 比超大补丁更适合多个编码智能体并行产出和人类逐层验收；工作树、Webhook 与合并队列支持使 stacked workflow 更容易被自动化编排器直接驱动。
- **原文链接：**[GitHub Changelog](https://github.blog/changelog/2026-10-06-stacked-pull-requests-generally-available/)

## 5. GitHub 为 AI Scan 增加企业级覆盖可视化与导出

![GitHub AI Scan 覆盖状态公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-06-code-scanning-ai-scan-enablement-status-in-security-overview/)

*图片来源：[GitHub 官方更新页面](https://github.blog/changelog/2026-10-06-code-scanning-ai-scan-enablement-status-in-security-overview/)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-06
- **事实摘要：**GitHub 的组织与企业管理员现在可在 Security Overview 的 coverage 视图中查看 AI Scan for pull requests 的启用情况，包括已启用/未启用仓库数量与每个仓库的有效状态。平台同时新增 `code-scanning-ai-scan-pr-scan:enabled` 和 `:not-enabled` 过滤器，并在 CSV 导出中加入对应状态列。此次更新不改变扫描引擎本身，重点是让管理员量化覆盖率并定位治理缺口。
- **为什么值得关注：**AI 代码安全能力若无法证明覆盖了哪些仓库，就很难进入受监管的软件交付流程；可查询、可导出的启用状态让智能体生成代码的安全门禁首次更接近可审计的企业控制项。
- **原文链接：**[GitHub Changelog](https://github.blog/changelog/2026-10-06-code-scanning-ai-scan-enablement-status-in-security-overview/)
