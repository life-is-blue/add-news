## 1. OpenClaw 2026.11.7：把长时运行智能体的“恢复能力”推到核心

![OpenClaw 2026.11.7 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.11.7)

*图片来源：[OpenClaw 官方 GitHub Release](https://github.com/openclaw/openclaw/releases/tag/v2026.11.7)*

OpenClaw 发布稳定版 2026.11.7，重点是 Gateway 重启后恢复被中断的回复与子智能体结果，并让自动化任务区分“已恢复”“有意跳过”和真正失败。该版本还减少慢文件系统、巨型恢复包和网页抽取对网关响应的阻塞，并修复 Codex 恢复会话、流式换行、Claude CLI 最终答案及子结果投递等问题。插件 SDK 同时包含会话控制、Gateway 方法和启动观察接口的破坏性变更，迁移时需对照官方指南。

**为什么值得关注：** 面向持续运行的智能体，故障后的状态恢复、结果归属和计划任务语义往往比单次基准分数更决定生产可用性；这次更新集中补齐了这条可靠性链路。

- **原文：** [OpenClaw 2026.11.7 Release](https://github.com/openclaw/openclaw/releases/tag/v2026.11.7)
- **发布日期：** 2026-11-23 09:33（新加坡时间）
- **时效：** 过去 24 小时

## 3. GitHub Copilot CLI 1.0.115-7：修复远程 UI 恢复与启动残留进程

![GitHub Copilot CLI 1.0.115-7 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/github/copilot-cli/releases/tag/v1.0.115-7)

*图片来源：[GitHub 官方 Copilot CLI Release](https://github.com/github/copilot-cli/releases/tag/v1.0.115-7)*

GitHub 发布 Copilot CLI 1.0.115-7 预发布版：使用 `--ui-server` 的客户端现在可在服务开始监听后立即接入恢复的 CLI 会话。版本还修复了 npm 安装的 CLI 在启动阶段被停止时仍遗留后台进程的问题。改动规模不大，但直接针对远程控制面与进程生命周期这两个容易造成“幽灵任务”的运行风险。

**为什么值得关注：** 当 CLI 智能体被接入浏览器 UI、远程工作台或自动化编排后，恢复时机和干净退出会直接影响会话一致性、资源占用与运维可观测性。

- **原文：** [GitHub Copilot CLI 1.0.115-7 Release](https://github.com/github/copilot-cli/releases/tag/v1.0.115-7)
- **发布日期：** 2026-11-22 19:40（新加坡时间）
- **时效：** 过去 24 小时；**预发布**

## 4. OpenAI Agents SDK 1.0 Alpha：Codex 成为可按运行选择的 Python Provider

![OpenAI Agents SDK 1.0.0 Alpha 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/openai-agents-python/releases/tag/v1.0.0-alpha.1)

*图片来源：[OpenAI 官方 Agents SDK GitHub Release](https://github.com/openai/openai-agents-python/releases/tag/v1.0.0-alpha.1)*

OpenAI 发布 Agents SDK 1.0.0-alpha.1，首次把 Codex 作为可选模型 Provider 接入 Python SDK，开发者可在每次运行中切换 Provider，并使用保存的 Codex 登录或 API Key。预览版通过 PyO3 嵌入未修改的 Codex Core（rust-v0.166.0），绕过 `codex app-server` 启动与 JSON-RPC，同时保留 SDK 工具、交接、类型化输出和审批流程；原生命令仍遵循 Codex 沙箱与审批设置。官方仅通过 GitHub Releases 提供四个平台的预构建 wheel，并公布校验和与安装测试结果。

**为什么值得关注：** 这把 Codex 从独立 CLI/服务进一步下沉为 Python 智能体运行时组件，使同一编排代码能按任务选择通用模型或 Codex，并共享 SDK 的工具与审批机制。

- **原文：** [OpenAI Agents SDK v1.0.0-alpha.1 Release](https://github.com/openai/openai-agents-python/releases/tag/v1.0.0-alpha.1)
- **发布日期：** 2026-11-21 04:51（新加坡时间）
- **时效：** **扩展至过去 72 小时；Alpha 预览**

## 5. Kilo Code 7.8.32：强化工作树删除保护，统一云端与本地任务面

![Kilo Code 7.8.32 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/Kilo-Org/kilocode/releases/tag/v7.8.32)

*图片来源：[Kilo Code 官方 GitHub Release](https://github.com/Kilo-Org/kilocode/releases/tag/v7.8.32)*

Kilo Code 7.8.32 阻止长按按键或重复关闭命令意外确认 Agent Manager 中的工作树删除，要求显式点击确认或重新按下删除键。此次聚合发布还统一了 JetBrains Agent Manager 的本地与云端任务入口，暴露带修订围栏的文件读取、工作区快照与关联 PR 差异，并修复 Gemini 在 MCP 工具声明 nullable enum 或多类型参数时请求失败的问题。自动补全默认模型转向 Codestral，旧 Mercury Edit/Next Edit 接口被移除，属于需要留意的兼容性变化。

**为什么值得关注：** 自主编码正从“生成补丁”走向管理多个云端工作区和并行任务；删除保护、可验证快照和 PR 差异接口是让这种协作模式可控、可追踪的基础设施。

- **原文：** [Kilo Code v7.8.32 Release](https://github.com/Kilo-Org/kilocode/releases/tag/v7.8.32)
- **发布日期：** 2026-11-20 22:45（新加坡时间）
- **时效：** **扩展至过去 72 小时**
