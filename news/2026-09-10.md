## 1. Codex CLI 0.154.0：隔离工作树进入实验阶段

![Codex CLI 0.154.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/codex/releases/tag/rust-v0.154.0)

*图片来源：[OpenAI Codex 官方 GitHub 发布页](https://github.com/openai/codex/releases/tag/rust-v0.154.0)*

OpenAI 发布 Codex CLI 0.154.0，新增实验性隔离工作树，可通过 `--worktree` 或 `/worktree` 启动，并支持浏览和恢复相关会话。版本还把 GPT-6-Astra 加入模型选择器及 Amazon Bedrock 目录，允许用户在 Codex 持续执行时插入问题而不丢失草稿。安全与运维方面，本次更新强化 MCP OAuth 刷新、启动信任检查和 macOS 沙箱，并让自动审批在收到新用户指令后拒绝已失效的许可。

**为什么值得关注：** 隔离工作树直接降低并行编码智能体相互覆盖改动的风险；与审批、认证和沙箱强化组合后，Codex 正从单会话助手进一步走向可并发、可治理的工程执行环境。

- **原文：** [Codex CLI 0.154.0 release](https://github.com/openai/codex/releases/tag/rust-v0.154.0)
- **发布日期：** 2026-09-09（UTC）

## 2. Claude Code 2.1.267：管理策略改为“读取失败即拒绝”

![Claude Code 2.1.267 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.267)

*图片来源：[Anthropic Claude Code 官方 GitHub 发布页](https://github.com/anthropics/claude-code/releases/tag/v2.1.267)*

Anthropic 发布 Claude Code 2.1.267，新增 `maxEffortLevel`，可在不同模型与 Bedrock、Vertex、Foundry 等提供方上统一控制推理强度，并提供关闭系统提示快照的选项。安全修复包括堵住 macOS/Linux 上利用反斜杠绕过 marketplace 路径边界的问题，以及让 HTTP Hook、环境变量和 Channel 插件白名单在无法读取时默认拒绝。版本还修复了组织强制沙箱下的 Cowork 定时任务、MCP/插件工具变化造成的提示缓存失效，以及超大转录恢复时遗漏并行工具调用等问题。

**为什么值得关注：** 这些改动集中解决企业落地最棘手的两类问题——跨模型行为一致性和策略失效时的安全默认值；“fail closed”也为可审计的智能体部署提供了更可靠的底座。

- **原文：** [Claude Code 2.1.267 release](https://github.com/anthropics/claude-code/releases/tag/v2.1.267)
- **发布日期：** 2026-09-09（UTC）

## 4. XAgent 用运行时行为增强代码定位与修复验证

![XAgent 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.09769)

*图片来源：[arXiv / XAgent 论文](https://arxiv.org/abs/2609.09769)*

XAgent 提出一种执行引导的软件工程智能体，把动态运行行为与代码上下文结合，用于问题定位、补丁生成和修复验证。作者报告其在 SWE-bench Lite 上达到 62.0% 的问题解决率与 72.8% 的函数定位率，并解决了领先基线未能处理的 7 个额外问题。该工作目前为预印本，指标来自作者评测。

**为什么值得关注：** 代码智能体常在“看起来相关”的静态文本上浪费上下文；将真实执行轨迹纳入定位与验证，有望减少误修，并把测试反馈更早地融入推理闭环。

- **原文：** [XAgent: An Execution-Guided Agent for Software Engineering](https://arxiv.org/abs/2609.09769)
- **发布日期：** 2026-09-10（arXiv 公告；v1 于 2026-09-09 UTC 上传）

## 5. TrajMark 为编码智能体轨迹加入归属与防篡改水印

![TrajMark 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.10416)

*图片来源：[arXiv / TrajMark 论文](https://arxiv.org/abs/2609.10416)*

TrajMark 提出无需训练、基于对称密钥且仅修改可见行动轨迹的水印方案，将所有权归属与局部完整性检查分开。其所有者层通过带密钥的读取动作编码 6 位身份，定位层则对关键轨迹片段加封；作者在 3 个编码智能体框架和 3 种大模型上报告，干净轨迹批次均可准确恢复身份。论文还报告对穷举式单点编辑的检测率为 95.5%–100%，对随机单动作破坏的定位率为 95.8%，同时 pass@1 与无水印基线接近（26.9% 对 26.3%）。

**为什么值得关注：** 自主开发逐渐变成多智能体、多供应商协作后，谁生成了哪段行动、轨迹是否被改写，将直接影响审计、责任划分和训练数据可信度；TrajMark 给出了一种开销较低的技术路径。

- **原文：** [TrajMark: Dual-Layer Watermarking for Coding Agent Trajectories](https://arxiv.org/abs/2609.10416)
- **发布日期：** 2026-09-10（arXiv 公告；v1 于 2026-09-09 UTC 上传）
