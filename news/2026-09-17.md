## 1. Google Home 开放 MCP：Claude、OpenClaw 等智能体可直接操控家庭设备

![Google Home MCP Server 官方文档](https://image.thum.io/get/width/1200/crop/675/noanimate/https://developers.home.google.com/mcp/home)

*图片来源：[Google Home Developers](https://developers.home.google.com/mcp/home)*

Google Home 推出早期访问版 MCP Server，让兼容客户端查询家庭结构、设备状态与历史事件，并执行设备控制；官方列出的客户端包括 Claude Cowork、OpenClaw 和 Google Antigravity。服务采用 OAuth，要求 Google Cloud 项目与 Home Premium Advanced 订阅，并明确禁止解锁门锁等敏感操作。Google 同时警告，连接真实家庭可能产生意外行为；《The Verge》报道该功能将于未来数周向美国用户推出，并点名 Hermes 也可通过 MCP 接入。

**为什么值得关注：** 这是开放智能体协议从“读写软件”走向物理环境的重要一步，也把权限、家庭成员知情同意、可撤销授权和动作级安全边界推到了产品前台。

- **原文：** [Google Home MCP Server 官方文档](https://developers.home.google.com/mcp/home)
- **交叉核验：** [The Verge 报道](https://www.theverge.com/tech/996310/google-home-mcp-integration-agentic-ai-smart-home-price-release-date)
- **发布日期：** 2026-09-16

## 2. Claude Code 2.1.274 修复凭据泄露与长时 MCP 超时

![Claude Code 2.1.274 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.274)

*图片来源：[Anthropic / GitHub](https://github.com/anthropics/claude-code/releases/tag/v2.1.274)*

Anthropic 发布 Claude Code 2.1.274，修复 MCP 配置错误消息可能暴露 `${VAR}` 环境变量值的问题，并收紧工作树隔离模式下对嵌套 shell 展开的处理。版本同时解决损坏会话记录触发无限重试、MCP 工具运行超过五分钟即超时，以及恢复会话时丢失目标等可靠性问题。新版还默认启用 v2 MCP 客户端与 MCP 2026-07-28 协议协商，并允许单独配置 MCP 启动等待时间。

**为什么值得关注：** 这些变化直接触及编码智能体的三条生产生命线：秘密不外泄、长任务不中断、隔离边界不被 shell 语法绕过；其价值高于单纯增加模型能力。

- **原文：** [Claude Code v2.1.274 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.274)
- **发布日期：** 2026-09-17

## 3. ProgramDistill：用完整应用行为评测编码智能体“复刻软件”

![ProgramDistill 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.18805)

*图片来源：[arXiv](https://arxiv.org/abs/2609.18805)*

ProgramDistill 不再只给智能体静态需求，而是要求其操作完整参考应用、观察行为，再在不完整应用中实现同等功能。研究者通过自动化的“发现—构造—补丁”流水线，从 26 个应用中挖掘出 1,975 个可重放验证的行为，并生成 4,063 个任务。对 9 个前沿编码智能体的评测显示，完整应用复刻中 GPT-6 Astra 达 49.2%、Claude Opus 5 达 28.8%；随着缺失层级从 1 增至 8，两者完成率分别由 100% 降至 64%、由 96% 降至 32%。

**为什么值得关注：** 它把评测从“修一个已描述清楚的 issue”推进到更接近真实逆向工程与迁移开发的场景，暴露了智能体在行为发现、跨页面状态和累积工作流上的能力断层。

- **原文：** [ProgramDistill: Evaluating Coding Agents on Full-App Reconstruction](https://arxiv.org/abs/2609.18805)
- **发布日期：** 2026-09-16

## 4. Affora 提出“智能体友好界面”设计系统

![Affora 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.19125)

*图片来源：[arXiv](https://arxiv.org/abs/2609.19125)*

Affora 面向同时服务人类与计算机使用智能体的界面，提供从组件到完整网站的设计原则、可复用实现和可执行检查。三组受控实验分别考察组件实现、视觉变化和交互原则，结果表明：只要界面表示保留清晰的交互语义，视觉自由度仍可维持。对独立作者界面的测试显示，Affora 能在其覆盖的语义缺口上提升智能体表现，但对不存在缺口或超出覆盖范围的问题作用有限。

**为什么值得关注：** 与其持续让模型猜按钮和状态，软件团队可以把“可供智能体理解和操作”做成前端质量属性；这可能像无障碍规范一样，逐步进入设计系统与自动化验收。

- **原文：** [Affora: A Design System for Agent-Friendly Interfaces](https://arxiv.org/abs/2609.19125)
- **发布日期：** 2026-09-16

## 5. AIJon：LLM 可生成专家级模糊测试注解，但不保证胜过 AFL++

![AIJon 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.18457)

*图片来源：[arXiv](https://arxiv.org/abs/2609.18457)*

AIJon 使用大模型自动生成 IJON 风格注解，为模糊测试器提供代码覆盖率之外的探索反馈，目标是替代难以规模化的人类领域专家标注。实验发现，大模型注解的效果可与人工注解相当；但在 Magma 基准上的大规模评测也显示，基于注解的模糊测试并不严格优于 AFL++。作者进一步分析了注解如何改变模糊测试器的能量分配，为后续自动化安全测试指出了更具体的优化方向。

**为什么值得关注：** 这是一项有价值的“负结果”：编码智能体确实能承担安全工程中的知识提取工作，但自动生成的提示信号只有经过系统级实验验证，才可能转化为更高的漏洞发现率。

- **原文：** [AIJon: Automated Generation of Annotations for Fuzzing](https://arxiv.org/abs/2609.18457)
- **发布日期：** 2026-09-16
