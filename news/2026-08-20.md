## 1. OpenAI 把 Computer Use 接入 Codex，推进“软件操作代理”闭环

![OpenAI 标识](https://upload.wikimedia.org/wikipedia/commons/4/4d/OpenAI_Logo.svg)

*图片来源：[OpenAI / Wikimedia Commons](https://commons.wikimedia.org/wiki/File:OpenAI_Logo.svg)*

**时间范围：过去 24 小时**

OpenAI 团队向 Business Insider 介绍了其计算机与浏览器操作能力的最新进展：2026 年已推出 Chrome 扩展、云端与应用内浏览环境，并把 Computer Use 接入 Codex。新方案不再只依赖逐帧截图，还会读取网页的内存结构、可访问性信息和链接关系；对 Codex 而言，这让代理能运行并检查自己生成的软件、发现问题后继续修正。报道同时指出，这类能力来自计算机任务数据、人工示范和强化学习的组合，而 OpenAI 仍建议采用最小权限及关键动作确认。

**为什么值得关注：** 编程代理正在从“修改源码”升级为“修改—运行—观察—修复”的完整闭环；浏览器与桌面控制会扩大可自动化任务的边界，也同步放大权限、隐私和提示注入风险。

- 原文：[Inside OpenAI's plan to make ChatGPT the way you use your computer](https://www.businessinsider.com/openai-chatgpt-automates-tasks-computer-use-data-2026-8)
- 相关技术文档：[OpenAI Computer Use 工具指南](https://platform.openai.com/docs/guides/tools-computer-use)
- 发布日期：2026-08-20

## 2. Cursor 推出 Origin：为 AI 代理规模重新设计代码托管

![Cursor 标识](https://cursor.com/favicon.svg)

*图片来源：[Cursor](https://cursor.com/)*

**时间范围：扩展至过去 72 小时**

Cursor 宣布 Origin 代码托管进入早期测试，向付费计划逐步开放仓库、Pull Request、代码浏览和 GitHub 同步。同步自 GitHub 的仓库仍以 GitHub 为事实来源，评论与回复可双向同步；代理则能在同一界面理解代码、提交修改、更新 PR 或推送分支。Origin 还已接入 Vercel、Depot 和 Buildkite，覆盖预览部署与 CI 工作流。

**为什么值得关注：** AI 编程工具正从 IDE 插件向代码托管与协作基础设施上移；如果代理、PR、CI 和部署位于同一控制面，软件交付的主要工作单元可能从“人的提交”转向“可审计的代理任务”。

- 原文：[Origin Code Hosting](https://cursor.com/changelog/origin-code-hosting)
- 交叉核验：[ITPro 对 Origin 功能与定位的报道](https://www.itpro.com/software/development/vibe-coding-startup-cursor-just-launched-a-github-alternative-heres-what-users-can-expect)
- 发布日期：2026-08-17

## 3. Fortinet 收购 Virtue AI，补齐自主代理运行时防护

![Fortinet 标识](https://upload.wikimedia.org/wikipedia/commons/6/62/Fortinet_logo.svg)

*图片来源：[Fortinet / Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Fortinet_logo.svg)*

**时间范围：扩展至过去 72 小时**

Fortinet 宣布收购 AI 安全公司 Virtue AI，交易金额未披露，并计划把其能力并入 AI-Native Security Fabric。Virtue AI 的 Guardian Agent 可发现未授权代理、扫描 MCP 工具与源代码、监测行为并在执行前阻断恶意工具调用；其红队系统覆盖 50 多个沙箱环境、14 个高风险领域及提示注入、MCP 攻击等场景。该技术也提供模型更新后的持续验证、审计证据和覆盖文本、图像、音视频及生成代码的实时策略护栏。

**为什么值得关注：** 自主代理把安全边界从模型输入输出扩展到工具、凭据、代码和连续动作；收购显示“代理运行时安全”正在从独立新创能力进入大型网络安全平台。

## 4. A2A 协议迁入 Agentic AI Foundation，与 MCP 汇聚治理

![Agentic AI Foundation 标识](https://cdn.sanity.io/images/8m3angk4/production/bc19584a9da572a1a0bb5e2e8ae9413256f791eb-1920x800.png?auto=format&w=1600)

*图片来源：[Block：Agentic AI Foundation 发布公告](https://block.xyz/inside/block-anthropic-and-openai-launch-the-agentic-ai-foundation)*

**时间范围：扩展至过去 72 小时**

Google 创建的 Agent2Agent（A2A）协议将从 Linux Foundation 的通用项目组合迁入专注代理技术的 Agentic AI Foundation。A2A 负责不同供应商、框架与平台之间的独立代理通信，而 MCP 主要规范 AI 应用与工具、数据源的连接；迁移后两项关键开放标准进入同一基金会治理范围。A2A 已在 Google、Microsoft 和 AWS 等云平台形成支持，目标是减少多代理系统之间逐一编写专用连接的成本。

**为什么值得关注：** 代理生态的竞争焦点开始从单一模型能力转向互操作标准；A2A 与 MCP 的治理汇聚，有望降低跨云、跨模型协作的集成成本，也会让身份、授权和审计成为下一阶段基础设施重点。

- 原文：[Google-backed agentic A2A protocol gets a new home](https://www.axios.com/2026/08/17/a2a-agentic-ai-foundation-open-ai-standards)
- 背景核验：[Linux Foundation：A2A 一周年采用情况](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
- 发布日期：2026-08-17

## 5. Google Cloud 提出双层代理编排，用于受监管系统的韧性调查

![Deutsche Bank 代理韧性架构示意](https://storage.googleapis.com/gweb-cloudblog-publish/images/deutsche-bank-operational-resilience-agent.max-2500x2500.png)

*图片来源：[Google Cloud](https://cloud.google.com/blog/topics/financial-services/building-operational-resilience-with-agentic-ai-in-financial-services)*

**时间范围：扩展至过去 72 小时**

Google Cloud 与 Deutsche Bank 介绍了一套面向金融系统运营韧性的代理架构：用 LangGraph 执行可重复、可验证的监管流程，同时用 Google Agent Development Kit（ADK）处理需要动态调查的开放式任务。代理从系统架构、日志和代码等来源收集上下文，再生成可追溯的调查结果与审计证据；确定性编排和自适应推理被明确分层。该设计将人工审批与证据留存放在高风险工作流内，而不是把调查完全交给自由运行的代理。

**为什么值得关注：** 这是自主代理进入强监管生产环境的一种可复用模式：把确定性控制面与非确定性调查面拆开，兼顾自动化效率、恢复能力和审计要求。

- 原文：[Building operational resilience with agentic AI in financial services](https://cloud.google.com/blog/topics/financial-services/building-operational-resilience-with-agentic-ai-in-financial-services)
- 技术背景：[Google ADK 文档](https://google.github.io/adk-docs/)
- 发布日期：2026-08-18
