## 1. Codex CLI 0.157.0 加入 GPT-6，并强化后台会话与网络策略

![Codex CLI 0.157.0 发布页](https://opengraph.githubassets.com/1/openai/codex/releases/tag/rust-v0.157.0)

*图片来源：[OpenAI / Codex 官方 GitHub Release](https://github.com/openai/codex/releases/tag/rust-v0.157.0)*

OpenAI 发布 Codex CLI 0.157.0，新增 GPT-6 Sol 与 Luna，并支持通过 Amazon Bedrock 使用这些模型及旧模型迁移提示。交互会话现在可自动启动后台服务器，远程与本地后台会话均可使用 `/import`，还可从其他应用占用的对话派生分支并保留草稿与排队提示。安全侧则强化了重定向、持续 HTTP/WebSocket 流量的网络限制：策略变化撤销权限时会取消既有连接，同时修复代理路由与临时文件上传失败。

**为什么值得关注：** 这次更新把模型升级、跨应用会话和后台执行放进同一条工程链路，并开始对“连接建立之后”的网络访问继续施加策略，适合长期运行的编码智能体。

- **原文：** [Codex CLI 0.157.0](https://github.com/openai/codex/releases/tag/rust-v0.157.0)
- **发布日期：** 2026-09-25

## 2. Claude Code 2.1.282 修复恢复会话、托管策略与技能越权问题

![Claude Code 2.1.282 发布页](https://opengraph.githubassets.com/1/anthropics/claude-code/releases/tag/v2.1.282)

*图片来源：[Anthropic / claude-code 官方 GitHub Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.282)*

Anthropic 发布 Claude Code 2.1.282，集中修复 `--continue`、`--resume`、模型切换和上下文压缩时丢失或变形历史推理的问题，并为短暂 Postgres 故障增加网关就绪宽限期。权限方面，版本修复了仓库、用户及插件技能通过 `allowed-tools` 自行预批准工具、托管设置因单个无效值而整块失效，以及恢复后的远程权限提示导致已批准命令执行两次等问题。它还阻止通过仓库符号链接读取 macOS `/Network` 等目录下的 CLAUDE.md 或规则文件。

**为什么值得关注：** 对企业部署而言，恢复会话的语义完整性与托管权限是否真正生效同等关键；这些修复直接收紧了技能、规则文件和远程执行之间的信任边界。

- **原文：** [Claude Code v2.1.282](https://github.com/anthropics/claude-code/releases/tag/v2.1.282)
- **发布日期：** 2026-09-24

## 3. Agent Skill 迁移评测显示：高分不等于满足版本契约

![插件迁移 Agent Skill 研究论文页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.30120)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2609.30120)*

研究团队回溯分析一个已发布的插件升级 Skill，覆盖 16 个静态迁移任务、64 份报告和 328 个判定；使用 Skill 后记录的平均奖励由 93.83 升至 98.75。进一步追踪却发现增益主要集中在一个任务，且评分标准会同时偏向实验组或对照组；修正已复核判定后，估计增益的置信区间移动到零或跨过零。研究还用可执行探针确认一项评分缺陷，并公开代码、数据与评测工件。

**为什么值得关注：** Skills 正成为编码智能体复用维护知识的核心机制，但这项研究说明，必须把总分追溯到版本契约与可执行修复，不能仅凭模型裁判的高分决定上线。

- **原文：** [Evaluating Agent Skills for Version-Specific Plugin Migration](https://arxiv.org/abs/2609.30120)
- **发布日期：** 2026-09-24

## 4. 纯 AI 编写的 2.1 万行代码库暴露错误与事实可靠性缺口

![纯 AI 代码库可靠性研究论文页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.29744)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2609.29744)*

一项案例研究公开并分析了一个完全由 Claude 编写、约 2.1 万行的 Python 工具及其完整开发历史，其中代码与测试均无人类直接编写。论文报告，14.3% 的 AI 代码生成事件包含后来被 AI 自己编写的测试捕获的真实错误；约每 4–5 条交互响应就有一条包含至少一项事实错误。作者同时提供代码溯源工具，以及针对指令意图、提交来源和响应可靠性的三套分类法。

**为什么值得关注：** 这组数据把“智能体最终交付了多少代码”与“过程中的错误率、事实陈述和自我验证能力”分开衡量；虽然只是单个代码库案例，但对自主开发审计比单看最终测试通过率更有价值。

- **原文：** [Between the Commits: Process, Error, and Claim Reliability in a Wholly AI-Authored Codebase](https://arxiv.org/abs/2609.29744)
- **发布日期：** 2026-09-24

## 5. 83 个审计 Skills 实测：模型能力与正确触发比 Harness 更关键

![智能合约审计 Agent Skills 研究论文页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.29454)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2609.29454)*

研究者收集了真实生态中的 83 个智能合约审计 Skills，并在 EVMBench 上测试七种智能体—模型组合，比较其设计、漏洞检测效果与执行轨迹。论文报告，效果主要由模型而非 Agent Harness 决定，其中 Codex/GPT-5.5 的检测分数提高 22.8%、捕获奖励提高 43.2%。不过 Skill 能否被正确触发是主要瓶颈；一旦触发，不同组合大体遵循相同的六阶段审计流程，但加载方式和行为影响仍有差异。

**为什么值得关注：** 结果提示团队优化智能体时，应把 Skill 发现与触发、模型选择和领域覆盖放在更高优先级，而不是仅替换编排框架；这也为安全审计类 Skills 的可复现实测提供了公开语料。

- **原文：** [Demystifying Agent Skills for Smart Contract Auditing](https://arxiv.org/abs/2609.29454)
- **发布日期：** 2026-09-24
