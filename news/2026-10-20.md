## 1. Vercel AI SDK 7.0.146：决策调用可独立控制推理预算

![Vercel AI SDK 7.0.146 官方发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/vercel/ai/releases/tag/ai@7.0.146)

*图片来源：[Vercel AI SDK 官方 GitHub Release](https://github.com/vercel/ai/releases/tag/ai%407.0.146)*

AI SDK 7.0.146 为实验性 decision calls 增加 `maxOutputTokens` 与 `reasoning`，并将这些设置传递给由语言模型驱动的决策器。版本同时修复工具调用裁剪后遗留孤立 reasoning 内容的问题，以及可选工具让多类 TypeScript 事件类型错误混入 `undefined` 的问题。官方发布记录显示该版本于 2026-10-20 04:12 发布。

**为什么值得关注：** 智能体在“是否执行、选哪个工具、何时停止”等控制面决策上，终于能与主生成步骤分开配置推理强度与输出上限；这有助于在可靠性、延迟和成本之间做更细粒度的工程权衡。

- **发布日期：** 2026-10-20（过去 24 小时）
- **原文：** [Release ai@7.0.146](https://github.com/vercel/ai/releases/tag/ai%407.0.146)

## 2. Claude Code 2.1.304：加强自动模式、权限判定与子智能体可靠性

![Claude Code 2.1.304 官方发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.304)

*图片来源：[Anthropic Claude Code 官方 GitHub Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.304)*

Claude Code 2.1.304 新增 `/auto-mode-setup`，可读取项目和近期会话来引导配置自动模式，并将工具调用历史纳入压缩摘要。权限接口新增 `decider: "person"` 与只读标记，明确某些请求只能由人类对话框或宿主回调批准。该版还修复子智能体在刚结束后被消息唤醒时遗忘近期工作、插件让无头运行越过 `--max-turns`，以及 worktree 退出时可能误删分支并丢失提交等问题。

**为什么值得关注：** 这次更新不是单纯加功能，而是同时收紧“谁能批准工具调用”、改进长会话压缩并修补多智能体生命周期故障，直接触及自主编码代理进入生产环境时最关键的安全与状态一致性。

- **发布日期：** 2026-10-19 21:34（过去 24 小时）
- **原文：** [Release v2.1.304](https://github.com/anthropics/claude-code/releases/tag/v2.1.304)

## 3. Mistral Vibe 3.0.0：统一执行、多智能体工具与企业 MCP 治理同步升级

![Mistral Vibe 3.0.0 官方发布页截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/mistralai/mistral-vibe/releases/tag/v3.0.0)

*图片来源：[Mistral Vibe 官方 GitHub Release](https://github.com/mistralai/mistral-vibe/releases/tag/v3.0.0)*

Mistral Vibe 3.0.0 让 app-server 报告模型压缩阈值，Desktop 可在首次使用时导入其他编码智能体的项目与会话，Rust CLI 也支持分支会话与后台任务等待。子智能体工具统一改名为 `agents.*`，插件不得占用内建的 `agents`、`agent` 和 `collaboration` 命名空间；管理员还可通过托管配置全面禁用面向用户的 MCP 操作。无头模式现在遵循统一运行契约，带回合、令牌、价格和时间限制，并以结构化 JSON 导出结果。

**为什么值得关注：** 这是编码智能体从单一 CLI 向“跨桌面、编辑器、无头运行与企业策略”统一平台演进的典型版本，尤其把会话迁移、子智能体命名空间和 MCP 管理纳入同一治理面。

- **发布日期：** 2026-10-19 16:01（过去 24 小时）
- **原文：** [Release v3.0.0](https://github.com/mistralai/mistral-vibe/releases/tag/v3.0.0)

## 4. OpenAI 发布低资源编程语言评测：从 SQLite 重建到 COBOL 迁移

![OpenAI 低资源编程语言研究页面截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://openai.com/index/low-resource-programming-languages/)

*图片来源：[OpenAI 官方研究文章](https://openai.com/index/low-resource-programming-languages/)*

OpenAI 发布 MultiLangBench，以 20 种语言从头实现兼容 SQLite 的数据库引擎，并公开评测设置与测试套件；GPT-6 Astra 的平均测试通过率为 87.4%，对比 GPT-5.6 Sol 的 26.8%。另一项 COBOL 迁移评测要求模型在 C++、Java、Kotlin、Python 或 Rust 中保持字节级可观察行为一致，GPT-6.1 Sol 在低推理强度下达到 86.6%，高推理强度下达到 97.9%。官方也强调，生产迁移仍需专家复核以及针对业务规则和依赖的测试。

**为什么值得关注：** 这把编码模型评估从主流语言上的短补丁扩展到遗留系统迁移、长程实现与行为保持，对银行、政务和关键基础设施的现代化更有现实意义；公开测试套件也使外部复现和针对性改进成为可能。

- **发布日期：** 2026-10-19（扩展至过去 72 小时；官方未标精确时刻）
- **原文：** [Advancing coding in low-resource programming languages](https://openai.com/index/low-resource-programming-languages/)

## 5. GitHub Copilot 模型策略 API 正式开放：企业可分层自动治理模型

![GitHub Copilot 模型策略 API 官方公告截图](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams/)

*图片来源：[GitHub 官方 Changelog](https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams/)*

GitHub 已将 Copilot 模型策略的 GET 与 PATCH REST 端点正式开放，覆盖企业、企业团队、企业应用和组织四个层级。企业可读取或更新模型可用性，并在组织模式中把控制权委托给组织，或在 enterprise teams 模式下委托给团队与应用。这使模型上架、退役与合规限制可以进入自动化配置和审计流程，而不再只依赖管理界面中的人工操作。

**为什么值得关注：** 当 AI 编程工具同时接入多家模型、模型版本快速变化时，模型选择本身已经成为安全和治理策略；API 化让大型组织能把它纳入基础设施即代码、变更审批与持续合规。

- **发布日期：** 2026-10-19（扩展至过去 72 小时；官方未标精确时刻）
- **原文：** [Copilot model policy API for enterprise, orgs, and teams](https://github.blog/changelog/2026-10-19-copilot-model-policy-api-for-enterprise-orgs-and-teams/)
