## 1. Codex CLI 0.163.0：运行中可即时引导，代理与网络边界同步加固

![Codex CLI 0.163.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openai/codex/releases/tag/rust-v0.163.0)

*图片来源：[OpenAI / Codex GitHub Releases](https://github.com/openai/codex/releases/tag/rust-v0.163.0)*

- **发布日期：** 2026-10-16（新加坡时间，过去 24 小时）
- **原文：** [Codex CLI 0.163.0](https://github.com/openai/codex/releases/tag/rust-v0.163.0)

Codex 0.163.0 允许用户在智能体仍在响应时发送 follow-up 立即调整方向，主动中断也会停止 Code Mode 单元及其嵌套工具调用；新版还可从 `/daemon` 重启托管后台服务并自动重连，并行执行互不依赖的只读工具。安全方面，网络代理会在 DNS 查询前检查权限，拒绝重复 `Host` 标头，并阻止凭据别名绕过检查钩子；恢复会话时也会恢复权限和网络批准，同时继续服从当前托管策略。配置搜索、快捷键、side conversation 返回与远程命令尾部输出的可靠性也得到改进。

**为什么值得关注：** 这次更新把“运行中控制”与“执行前授权”放在同一版本里，说明成熟编码智能体的关键不只是自主性，而是用户能否及时改向、停止、恢复并审计执行。

## 2. OpenClaw 2026.10.4 修复休眠失联、身份冒用与压缩中断

![OpenClaw 2026.10.4 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.10.4)

*图片来源：[OpenClaw GitHub Releases](https://github.com/openclaw/openclaw/releases/tag/v2026.10.4)*

- **发布日期：** 2026-10-16（过去 24 小时）
- **原文：** [OpenClaw 2026.10.4](https://github.com/openclaw/openclaw/releases/tag/v2026.10.4)

这是针对 2026.10.3 的稳定性补丁，不引入新配置：Gateway 在电脑休眠或系统时钟跳变后不再误判所有权心跳过期并重启，关闭与重启也不会被卡住的 transcript worker 拖死。Tlon 群组私信不再把其他参与者当作 owner，封堵一条身份冒用途径；手动 `/compact` 会先让当前运行稳定落盘，而不是中止并丢弃待处理请求。该版本还修复 Claude CLI 会话跨消息路由分叉、OpenAI reasoning 模型工具轮次报 400、MCP OAuth 回调端口兼容等问题。

**为什么值得关注：** OpenClaw 同时处理进程所有权、会话一致性和身份边界，体现了常驻型智能体真正的生产难题：它必须在跨休眠、跨渠道和跨工具的长期运行中保持“谁在控制、状态是否完整”都不含糊。

## 3. Claude Code 2.1.301：为无人值守重试设上限，补齐权限决策遥测

![Claude Code 2.1.301 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.301)

*图片来源：[Anthropic / Claude Code GitHub Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.301)*

- **发布日期：** 2026-10-16（新加坡时间，过去 24 小时）
- **原文：** [Claude Code v2.1.301](https://github.com/anthropics/claude-code/releases/tag/v2.1.301)

Claude Code 新增无人值守 retry watchdog 的最长用量限制等待时间，避免智能体遇到很久以后才重置的配额时无限等待。OpenTelemetry 的 `tool_decision` 事件现在包含分类器结论、权限模式及可选分类类别，可区分自动分类阻断与显式权限规则。版本还修复 workflow agent 跳过步骤却仍报告成功、退出时误删可能含未推送提交的 worktree、工具调用在权限检查中被截断后被误报为用户拒绝，以及反复压缩会话等问题。

**为什么值得关注：** “无人值守”不能等于“无限等待或静默成功”；超时边界、权限来源和真实步骤完成状态，是长程编码智能体能够被团队信任的基础。

## 4. GitHub Agentic Autofix 正式 GA：从安全告警走到验证后的修复 PR

![GitHub Agentic Autofix GA 公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-15-agentic-autofix-for-code-scanning-alerts-general-availability/)

*图片来源：[GitHub Changelog](https://github.blog/changelog/2026-10-15-agentic-autofix-for-code-scanning-alerts-general-availability/)*

- **发布日期：** 2026-10-15（扩展至过去 72 小时；官方仅标注日期）
- **原文：** [Agentic autofix for code scanning alerts general availability](https://github.blog/changelog/2026-10-15-agentic-autofix-for-code-scanning-alerts-general-availability/)

GitHub 的 Agentic Autofix 已正式可用：Copilot 会围绕 CodeQL 告警探索相关文件、生成修复、重新运行 CodeQL 验证告警是否关闭，必要时迭代后创建待人工审查的草稿 PR。管理员可一次把最多 25 个告警交给同一个修复 PR，也可通过 REST API 指派 `copilot-swe-agent[bot]`；目前仅支持默认分支上的告警。功能需要企业管理员启用策略，并消耗 Code Security AI Credits 与 GitHub Actions 分钟。

**为什么值得关注：** 安全智能体开始形成“发现—修复—验证—PR—人工复核”的闭环，价值比单次代码建议更高；同时，适用分支、预算和最终合并权仍被明确留在人类与组织策略手中。

## 5. Google 重构 ADK Recipes：让编码智能体直接发现、安装和验证代理模板

![Google ADK Recipes 架构文章](https://image.thum.io/get/width/1200/crop/675/noanimate/https://developers.googleblog.com/en/three-layers-one-repo-a-tour-of-googleadk-recipes/)

*图片来源：[Google Developers Blog](https://developers.googleblog.com/en/three-layers-one-repo-a-tour-of-googleadk-recipes/)*

- **发布日期：** 2026-10-15（扩展至过去 72 小时；官方仅标注日期）
- **原文：** [Three layers, one repo: a tour of google/adk-recipes](https://developers.googleblog.com/en/three-layers-one-repo-a-tour-of-googleadk-recipes/)

Google 将 `adk-samples` 重构为 `google/adk-recipes`，以 `core/`、`plugins/`、`contrib/` 三层分别承载参考架构、可安装行业技能和端到端可部署服务，并作为 Agents CLI、Agent Garden 与 Gemini Enterprise app 的统一内容来源。每个 recipe 配有经过验证的 `manifest.yaml` 和面向编码智能体的 `AGENTS.md`；插件还包含 `SKILL.md`、`EVAL.yaml`、容器与可运行性测试，可被 Claude Code、Codex、Cursor 等工具发现和安装。Google 明确提醒这些 recipes 是示范与起点，并非正式支持的生产产品。

**为什么值得关注：** 这把“示例仓库”升级成机器可读的智能体供应链：架构模式、行业技能、评测和部署工件能在同一治理管道内复用，但生产采用者仍需自行承担版本、依赖与安全验证。
