## 1. Copilot CLI 1.0.115-6：修复组织插件重试与 Unix 孤儿进程

![GitHub Copilot CLI 1.0.115-6 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/github/copilot-cli/releases/tag/v1.0.115-6)

*配图来源：[GitHub Copilot CLI 官方 GitHub Release](https://github.com/github/copilot-cli/releases/tag/v1.0.115-6)*

GitHub Copilot CLI 1.0.115-6 修复了组织强制插件在安装过程中遇到临时策略变化后无法立即重试的问题，并让未登录用户调用 `/delegate` 时得到明确提示。该预览版还会在 Unix 上取消 Shell 命令时清理同一进程组内的孤儿子进程，并让 Sessions 侧栏在 Copilot Fusion 后台选择模型期间持续显示会话正在运行。

**为什么值得关注：** 组织策略、插件安装与子进程清理是企业级编码智能体最容易出现“表面停止、实际仍运行”或会话不可恢复的环节；修复虽小，却直接改善托管执行的可控性。

- **时间范围：** 过去 24 小时

## 5. SWE-Recreation：用真实应用复刻检验编码智能体的探索与实现能力

![SWE-Recreation 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2611.26311)

*配图来源：[arXiv 论文页面](https://arxiv.org/abs/2611.26311)*

SWE-Recreation 提出一个黑盒软件复刻基准：智能体只能观察渲染像素并使用鼠标与键盘探索应用，无法访问 DOM、源代码、日志或后端，然后需要自行重建并验证产品。基准包含 54 个真实应用（28 个网站、26 个 Android 应用）和 1,446 条隐藏需求；五个前沿系统的最高加权保真度仅为 0.530，完整复现的需求比例最高为 22.9%。

**为什么值得关注：** 传统 SWE-bench 更偏向给定问题后的修复能力，而该基准同时考验需求发现、交互探索、实现和自验收，更接近“从陌生产品中理解并重建”的自主开发任务，也暴露出现有智能体在证据收集与实现完整性上的双重短板。

- **原文：** [SWE-Recreation: Benchmarking Coding Agents for Software Recreation](https://arxiv.org/abs/2611.26311)
- **发布日期：** 2026-11-20（新加坡时间；arXiv v1 提交于 2026-11-19 16:00 UTC）
- **时间范围：** 扩展至过去 72 小时
