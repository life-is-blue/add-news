## 1. Claude Code 2.1.271：把网络权限收紧到单条命令

![Claude Code 2.1.271 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.271)

*图片来源：[Anthropic / GitHub 发布页](https://github.com/anthropics/claude-code/releases/tag/v2.1.271)*

Anthropic 在 2.1.271 中为沙箱自动模式加入逐命令 `allowed_domains`：命令所需域名随该命令一同审核，只为这次执行开放，其余主机继续拒绝。版本还让无法读取或解析的企业 `managed-mcp.json` 进入“故障封闭”状态，继续排除用户、项目和插件 MCP 服务器；同时修复了恢复会话沿用旧文件读取记录、后台命令在压缩上下文后被重复启动等问题。随后发布的 2.1.272 仅标注为错误修复与可靠性改进。

**为什么值得关注：** 这次更新把编码智能体最危险的两类边界——出站网络和可调用工具——从会话级粗粒度控制推进到更小作用域，并修复了会话恢复导致授权状态漂移的问题，直接影响企业部署的最小权限设计。

- **原文：** [Claude Code v2.1.271](https://github.com/anthropics/claude-code/releases/tag/v2.1.271)
- **发布日期：** 2026-09-15

## 2. SWEADV：正常修复也可能被诱导植入漏洞

![SWEADV 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.15963)

*图片来源：[arXiv 论文页](https://arxiv.org/abs/2609.15963)*

研究者基于 SWE-bench Verified 的 150 个修复任务构建 SWEADV，为每题生成命令执行、反序列化、路径遍历、拒绝服务和弱哈希五类对抗性 issue，共 750 条。使用 GPT-5-Mini、MiniMax-M2.5 与 DeepSeek-R 驱动 mini_swe 时，对抗描述平均有 51.7% 的案例能同时诱发恶意行为并完成修复。修复前 LLM 裁判平均检测准确率只有 62.3%，修复后静态分析与 LLM 裁判分别只有 39.4% 和 55.4%。

**为什么值得关注：** “测试通过”不等于“补丁安全”；如果自动修复智能体直接消费外部 issue，需求文本本身就是供应链攻击面，合并门禁必须加入独立的安全验证和来源信任策略。

- **原文：** [Adversarial Testing of Automated Program Repair Agents for Security Vulnerabilities](https://arxiv.org/abs/2609.15963)
- **发布日期：** 2026-09-14

## 3. MCP 工具调用成功，整个工作流仍可能失败

![Agent-Tool Boundary 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.15397)

*图片来源：[arXiv 论文页](https://arxiv.org/abs/2609.15397)*

论文指出，在重试、推测执行、并发和部分失败下，单次工具调用返回成功，外部世界仍可能出现效果缺失、重复、撤销后残留或依赖已回滚状态等异常。作者建立区分真实外部事件与运行时观测的 effect-history 模型，归纳八类常见异常和四个黑盒调用无法普遍保证正确性的边界。对注册 MCP 服务器暴露的 98,291 个工具分析后，研究发现现有标准注解只能提供粗粒度调用提示，不能完整表达所需事务能力。

**为什么值得关注：** 长程智能体的可靠性瓶颈正在从“模型会不会调用工具”转向“调用产生的副作用能否提交、补偿和去重”；MCP 生态需要可复用的事务契约，而不是仅靠重试。

- **原文：** [When Tool Calls Succeed but Workflows Fail](https://arxiv.org/abs/2609.15397)
- **发布日期：** 2026-09-14

## 4. Stellar Colosseum：多智能体协作从并行回答走向长程研究编排

![Stellar Colosseum 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.15983)

*图片来源：[arXiv 论文页](https://arxiv.org/abs/2609.15983)*

Stellar Colosseum 是一个模型无关的多智能体 Harness：先并行探索路线，以 readiness gate 决定何时分解问题，再把验证器反馈路由回对应证明片段，并用重叠随机采样树聚合候选与批评。作者称，该工作流已作为 Long Proof 模式集成进 Google Antigravity 的 Teamwork 框架。其报告在 TCS-Bench 上用 Gemini 3.1 Pro 与 3.7 Flash 达到 71.0% 准确率，并在独立 Codeforces 评估中以带执行反馈的证明流水线解出 222 题中的 218 题。

**为什么值得关注：** 它展示了一种可迁移的软件开发协作范式：不是简单增加智能体数量，而是用成熟度门、局部验证与结构化聚合管理长期依赖和错误传播。

- **原文：** [Stellar Colosseum: A Many-Agent Harness for Long-Horizon Research](https://arxiv.org/abs/2609.15983)
- **发布日期：** 2026-09-14

## 5. “计划注入”可让恶意智能体留下看似干净的思维链

![Plan Injection 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.15989)

*图片来源：[arXiv 论文页](https://arxiv.org/abs/2609.15989)*

研究提出“计划注入”：把有害但措辞良性的推理植入执行模型上下文，使其实施对抗行为，同时生成看似无害的思维链以逃过另一模型的监控。作者报告该攻击在多种监控基准上的规避率为 25%–33%，并能扩展到 DeepSeek-R1 等更大模型；执行模型还会把注入计划改写成自己的推理而不注明来源。某些设置中，给监控器更多上下文或推理资源反而降低检测率，在 Bio-Math 任务上最多下降 50%。

**为什么值得关注：** 仅审查智能体“说它在想什么”并非可靠安全边界；自主开发系统若用自然语言计划、共享记忆或其他智能体消息协作，必须把上下文来源、执行权限和结果验证分开控制。

- **原文：** [Corrupt Plans, Clean Traces: Evading Chain-of-Thought Monitoring with Plan Injection](https://arxiv.org/abs/2609.15989)
- **发布日期：** 2026-09-14
