## 1. Claude Code 2.1.319 为 MCP 后台任务和无提示权限策略补齐控制面

![Claude Code 2.1.319 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.319)

*图片来源：[Anthropic Claude Code 官方 GitHub 发布页](https://github.com/anthropics/claude-code/releases/tag/v2.1.319)*

Claude Code 2.1.319 支持终端中的 MCP Task：当服务器把工具调用作为任务运行时，客户端会立即将其转入后台，完成后再把结果通知 Claude；也可通过环境变量改回同步等待。新版本加入 `permissions.denyInsteadOfPrompting`，让终端、子智能体和团队成员遇到本应等待人工确认的工具调用时直接拒绝并继续当前回合。它还在 `/tasks` 中保留本会话已结束的子智能体，并修复恢复会话后长时 MCP 调用不回传结果、长对话 `/diff` 空白及旧握手 MCP 兼容性等问题。

**为什么值得关注：** MCP 工具越来越多地执行长任务，而无人值守或批处理环境不能无限等待权限对话框；“后台执行、完成回传、无提示即拒绝”让长程智能体更适合自动化，同时把失败默认值放在更安全的一侧。

- **原文：** [Claude Code v2.1.319 Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.319)
- **发布日期：** 2026-11-06
- **时间范围：** 过去 24 小时

## 2. OpenHands 1.37.0 用 Mermaid 解释自动化，并修复会话恢复竞态

![OpenHands 1.37.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/OpenHands/OpenHands/releases/tag/v1.37.0)

*图片来源：[OpenHands 官方 GitHub 发布页](https://github.com/OpenHands/OpenHands/releases/tag/v1.37.0)*

OpenHands 1.37.0 为每个自动化流程生成 Mermaid 图，把事件触发、步骤和依赖关系以可视方式呈现。版本修复了恢复会话排序、启动交接时生成标题消失，以及会话回放尚未完成就展示空白建议等竞态问题。实时更新期间不再反复扫描完整历史记录，降低长对话界面的额外开销。

**为什么值得关注：** 自主开发流程不仅要能运行，还要让人理解“为什么会运行、下一步做什么”；可视化自动化加上正确的会话回放顺序，有助于审查复杂工作流并减少恢复后的误操作。

- **原文：** [OpenHands v1.37.0 Release](https://github.com/OpenHands/OpenHands/releases/tag/v1.37.0)
- **发布日期：** 2026-11-06
- **时间范围：** 过去 24 小时

## 3. Hermes Agent 0.23.0 以单一 Gateway 统一所有智能体会话

![Hermes Agent 0.23.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.0)

*图片来源：[Nous Research Hermes Agent 官方 GitHub 发布页](https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.0)*

Hermes Agent 0.23.0 “Hearth”让 CLI、TUI、Desktop、编辑器、消息机器人和定时任务都连接到同一个 Gateway，由它独占每个会话的队列与历史，避免多个前端各自运行智能体造成重复写入或消息丢失。完整 Desktop 工作区可由自有 Gateway 提供为浏览器应用，并支持同一窗口连接多台机器、终端内联图片和从旧消息分叉或回退会话。版本还加入可插拔委派、付费 MCP 工具的价格与消费上限，以及自动更新插件；插件目录从约 600 项扩大到 1,050 余项。

**为什么值得关注：** 多入口智能体最棘手的问题是会话所有权和并发一致性；Hermes 把各客户端降为同一会话服务的视图，为跨终端、桌面、机器人和远程主机协作提供了更清晰的状态模型。

- **原文：** [Hermes Agent v0.23.0 — The Hearth Release](https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.0)
- **发布日期：** 2026-11-05
- **时间范围：** 扩展至过去 72 小时

## 4. OpenClaw 2026.11.1 强化中断恢复与子智能体审批传递

![OpenClaw 2026.11.1 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.11.1)

*图片来源：[OpenClaw 官方 GitHub 发布页](https://github.com/openclaw/openclaw/releases/tag/v2026.11.1)*

OpenClaw 2026.11.1 让 Telegram、Discord 与 webhook 对话在请求处理器或上一回合结束后仍能持续送达智能体，并改善超大回合及首次 Claude CLI 回合被中止后的历史保留。子智能体在模型或会话切换后会保留后续消息，父会话即便使用自定义会话存储也能收到子任务审批。版本同时修复配置保存失败覆盖秘密、Tailscale 暴露关闭时破坏 Gateway 认证，以及更新器崩溃或取消后恢复卡住等问题。

**为什么值得关注：** 长程自主任务的真正可靠性取决于中断、恢复、跨渠道投递和审批链是否保持一致；这些修复直接覆盖“任务还在，但控制面丢了”的常见故障模式。

- **原文：** [OpenClaw 2026.11.1 Release](https://github.com/openclaw/openclaw/releases/tag/v2026.11.1)
- **发布日期：** 2026-11-05

## 5. Multi-step SWE 显示编码智能体在连续演进任务上仍大幅失速

![Multi-step SWE 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2611.07166)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2611.07166)*

Multi-step SWE 提出 69 个长程软件工程任务，每个任务由 5–15 个相互依赖的步骤组成，后续步骤直接建立在智能体自己此前产出的代码上；任务覆盖九种语言、四类工程工作，并为每一步提供独立验证器。研究评估九个前沿模型，最强模型的整任务成功率仅 18.5%，69 项中有 38 项没有任何模型完成。论文还发现，智能体常能通过单个步骤，却会在累计错误、过早停止以及只依据自身预期检查后错误宣称完成等环节失败。

**为什么值得关注：** 现实开发是连续修改同一代码库，而不是一次性解决孤立问题；该基准把架构债务和错误传播纳入评估，为多智能体交接、阶段验收及独立验证提供了更接近生产的衡量方式。

- **原文：** [Multi-step SWE: Can Coding Agents Keep Building on Their Own Code Over Long Horizons?](https://arxiv.org/abs/2611.07166)
- **项目与数据：** [Multi-step SWE 官方网站](https://multistepswe.com/)
- **发布日期：** 2026-11-04
- **时间范围：** 扩展至过去 72 小时
