## 1. OpenAI 发布 GPT-6.1 Terra：把计算机操作能力推向高吞吐场景

![OpenAI GPT-6.1 Terra 发布页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://openai.com/index/introducing-gpt-6-1-terra/)

*图片来源：OpenAI 官方发布页（页面截图）*

OpenAI 发布 GPT-6.1 Terra，并同步向 ChatGPT Work、Codex 与 API 开放；模型面向视觉推理、精确计算机操作及日常专业任务，API 标识为 `gpt-6.1-terra`。官方称其在 Terminal-Bench 4.0 的最高推理档解决率为 50.3%，高于 GPT-5.6 Terra 已公布的 21.5%，标准价格则为每百万输入/输出 token 1/5 美元。官方模型文档还列出 105 万 token 上下文、12.8 万最大输出，以及 computer use、MCP、hosted shell、skills 等工具支持。

**为什么值得关注：** Terra 把“能操作软件”的智能体能力与更低推理成本结合，可能显著扩大批量办公自动化和中等复杂度编码任务的可部署范围；但 OpenAI 仍明确建议最复杂的编码任务使用 Sol 或 Astra。

- **原文：** [OpenAI：Introducing GPT-6.1 Terra](https://openai.com/index/introducing-gpt-6-1-terra/)
- **交叉核验：** [OpenAI API 模型文档](https://developers.openai.com/api/docs/models/gpt-6.1-terra)
- **发布日期：** 2026-10-26（过去 24 小时）

## 2. Claude Code 披露高危 TOCTOU 漏洞：可越过工作区写入限制

![Claude Code 安全通告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/security/advisories/GHSA-5xjx-9qx6-jcrv)

*图片来源：Anthropic Claude Code 官方 GitHub 安全通告（页面截图）*

Anthropic 披露 Claude Code Edit 工具中的竞态条件漏洞 CVE-2026-88968，评级为 High、CVSS 7.7：路径验证与实际写入未绑定同一目录 inode 或文件描述符，攻击者可在验证后把工作区内父目录替换为符号链接，从而将写入重定向到工作区外。官方通告称该问题在 macOS 上可由沙箱内的恶意仓库或依赖脚本触发，影响低于 2.1.251 的版本，2.1.251 已修复；自动更新用户已获得修复，手动安装者应升级。

**为什么值得关注：** 编码智能体的安全边界不仅取决于模型是否“守规矩”，还取决于文件系统操作是否具备原子性；这类验证—使用时差漏洞能把受限工具变成跨边界写入原语。

- **原文：** [Anthropic：GHSA-5xjx-9qx6-jcrv](https://github.com/anthropics/claude-code/security/advisories/GHSA-5xjx-9qx6-jcrv)
- **发布日期：** 2026-10-26（过去 24 小时）

## 3. Pydantic AI 2.62.0 强化后台子智能体、压缩与错误语义

![Pydantic AI 2.62.0 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/pydantic/pydantic-ai/releases/tag/v2.62.0)

*图片来源：Pydantic AI 官方 GitHub Release（页面截图）*

Pydantic AI 2.62.0 允许子智能体委托以后台任务运行，并通过 `task_control` 进行引导、答复或取消；同时加入模型主动请求的自然断点压缩、可追踪的 `CompactionPart`，以及 Anthropic 消息压缩接口。版本还增加鉴权失败、请求拒绝、模型不存在等类型化错误，为 hosted MCP 工具默认添加服务前缀，并支持在工具调用中启动 Temporal 子工作流。

**为什么值得关注：** 这些变化集中解决长程智能体落地时的三个难点——后台并发可控、上下文压缩可审计、失败类型可编排——比单纯新增模型适配更接近生产级运行时能力。

- **原文：** [Pydantic AI v2.62.0 Release](https://github.com/pydantic/pydantic-ai/releases/tag/v2.62.0)
- **发布日期：** 2026-10-27（过去 24 小时）

## 4. Stately Agent 修复 fork 身份继承，阻断父任务缓存串线

> **时间范围：扩展至过去 72 小时**

![Stately Agent 2.0.0-alpha.32 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/statelyai/agent/releases/tag/%40statelyai%2Fagent%402.0.0-alpha.32)

*图片来源：Stately Agent 官方 GitHub Release（页面截图）*

Stately Agent 2.0.0-alpha.32 为 fork 后的执行分配新的 `metadata.executionId`，并记录 `metadata.forkedFrom`；此前 fork 沿用父执行 ID，可能生成相同的调用键，导致缓存返回父任务结果。新版还禁止 fork 恢复时错误采用父快照的快速路径，并拒绝与 fork 线程不匹配的父日志。

**为什么值得关注：** 分支探索、回滚和并行方案比较都依赖可靠的执行身份；若 fork 与父任务共享缓存或日志，智能体可能在表面成功的情况下消费错误结果，这正是长程协作中最隐蔽的状态一致性风险之一。

- **原文：** [Stately Agent 2.0.0-alpha.32 Release](https://github.com/statelyai/agent/releases/tag/%40statelyai%2Fagent%402.0.0-alpha.32)
- **发布日期：** 2026-10-26（新加坡时间；过去 72 小时）

## 5. Sim 0.9.33 将定时任务升级为持久化无人值守对话轮次

> **时间范围：扩展至过去 72 小时**

![Sim 0.9.33 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/simstudioai/sim/releases/tag/v0.9.33)

*图片来源：Sim 官方 GitHub Release（页面截图）*

Sim 0.9.33 的核心新增是让定时作业以“持久化、无人值守的对话轮次”运行，使计划任务不再只是一次性触发器，而能沿用智能体工作流的会话与执行语义。该版本同时升级 Bun 运行时至 1.4.4，并包含围绕调度与部署文档的一批配套更新。

**为什么值得关注：** 自主开发协作要从交互式助手走向持续运营，必须让周期性任务具备可恢复、可追踪的持久执行语义；这类底层能力直接影响夜间测试、监控、维护和自动修复流程的可靠性。

- **原文：** [Sim v0.9.33 Release](https://github.com/simstudioai/sim/releases/tag/v0.9.33)
- **发布日期：** 2026-10-26（新加坡时间；过去 72 小时）
