## 1. [过去24小时公开] Repository SKILL 优化研究：真实历史任务上的收益仅 4.9 个百分点

![Skill Issue 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.12742)

*图片来源：[arXiv / Skill Issue](https://arxiv.org/abs/2609.12742)*

论文研究如何为编码智能体自动优化随代码仓库版本化的 SKILL Markdown 文档，并指出普通仓库没有现成评测集、简单合成任务又容易被强模型“裸跑”做满。作者把已合并 PR 回退到同一冻结基线，构造更困难的真实任务；在三个 Kotlin 仓库中，GEPA 生成的文档平均提升 4.9 个百分点，而 SkillOpt 仅比种子文档高 0.1 个百分点。作者同时警告，单仓库历史提供的样本不足以把这 4.9 个百分点与智能体运行方差可靠区分，但维护者确实在生成文档中发现了需要项目经验才能掌握的知识。

**为什么值得关注：** 这项工作直击 AGENTS.md、SKILL.md 一类“仓库知识文件”是否真的有效的问题，并给出更接近真实开发的评测方法，而不是只比较文档看起来是否完整。

- **原文：** [Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents](https://arxiv.org/abs/2609.12742)
- **发布日期：** 2026-09-14（进入 arXiv 当日公开列表；v1 提交于 2026-09-11 11:41 UTC）

## 2. [过去24小时公开] CoTT：只在低置信度时追加测试生成，降低代码候选重排成本

![CoTT 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.12489)

*图片来源：[arXiv / CoTT](https://arxiv.org/abs/2609.12489)*

CoTT 面向 LLM 生成多个程序后的测试与重排：先用成本较低的归纳式流程生成测试，只有在预期输出置信度不足时才启用更昂贵的传导式生成。作者称，这种“置信度闸门”在所报告的代码重排基准上优于既有基线，同时比对所有输入一律执行传导式生成更省成本。方法只需单个高效 LLM，把额外推理预算集中到真正不确定的样本。

**为什么值得关注：** 编码智能体的瓶颈正从“能否生成代码”转向“如何经济地验证并挑出正确实现”；按置信度动态分配测试计算，是可直接迁移到多候选、自修复流水线的设计。

- **原文：** [Confidence-Gated Transductive Test Generation for Code Reranking](https://arxiv.org/abs/2609.12489)
- **发布日期：** 2026-09-14（进入 arXiv 当日公开列表；v1 提交于 2026-09-11 06:38 UTC）

## 3. [过去24小时公开] 智能体越狱防御应覆盖规划、记忆与工具链，而非只过滤最终回答

![Agentic AI Jailbreaking SoK 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.12413)

*图片来源：[arXiv / Agentic AI Jailbreaking SoK](https://arxiv.org/abs/2609.12413)*

这篇系统化综述把越狱攻击与防御重新映射到完整智能体执行链：用户交互、规划推理、持久记忆、工具调用和智能体间通信。统一实验显示，较强的原生安全对齐并不等于能抵抗对抗性越狱，而且防御效果高度依赖模型、攻击和组件，常伴随误拒、效用与延迟代价。更关键的是，最终回答看似安全仍可能掩盖中间状态已被攻陷，规划、记忆或工具动作依然可能产生危险结果。

**为什么值得关注：** 对 Codex、Claude Code、OpenClaw 等可执行外部动作的系统，安全验收不能只检查聊天输出；必须记录并约束状态转移、工具参数和副作用。

- **原文：** [SoK: Rethinking Jailbreaking in the Era of Agentic AI](https://arxiv.org/abs/2609.12413)
- **发布日期：** 2026-09-14（进入 arXiv 当日公开列表；v1 提交于 2026-09-11 04:04 UTC）

## 4. [过去24小时公开] 人机协作新框架：用六项条件判断 AI 是否真正“增强”完整工作流

![When Does AI Augment Work 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.12482)

*图片来源：[arXiv / CIVIC-AI Collaboration](https://arxiv.org/abs/2609.12482)*

CIVIC-AI Collaboration 认为，仅以当前自动化能力或采用率衡量 AI 价值，会忽略人机协作对完整工作流的重构。白皮书提出六项“真正增强”条件，涵盖可持续净价值、有意义的人类控制、问责与恢复，以及长期学习、职业路径和工作目的。作者以 AI 辅助社会调查为案例，并建议组织、研究者和政府用这套框架评估未来工作设计。

**为什么值得关注：** 对自主开发团队而言，吞吐量并不是唯一指标；可恢复性、责任归属和工程师能力是否被长期增强，决定了智能体协作能否持续扩展。

- **原文：** [When Does AI Augment Work? A Workflow-Level Framework for Human-Agent Collaboration](https://arxiv.org/abs/2609.12482)
- **发布日期：** 2026-09-14（进入 arXiv 当日公开列表；v1 提交于 2026-09-11 06:29 UTC）
