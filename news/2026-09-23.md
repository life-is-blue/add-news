## 1. Claude Opus 5.5 发布：编码能力、成本与安全同时推进

![Claude Opus 5.5 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.anthropic.com/claude-opus-5-5)

*图片来源：[Anthropic 官方发布页](https://www.anthropic.com/claude-opus-5-5)*

Anthropic 发布 Claude Opus 5.5：官方称其在多数任务上达到 Fable 5.1 水平，相比 Opus 5 的典型运行成本降低 40%，输出速度提升超过 30%；定价为每百万输入／输出 Token 4 美元／20 美元，缓存读取降至 0.20 美元。官方报告其 Terminal-Bench 4.0 得分为 66.4%，并称自动行为审计与提示注入防御均有改善；Frontier Design、METR 在发布前参与了外部评测。Reuters 与 The Verge 对价格、安全机制及外部测试信息进行了交叉报道，但基准和“降低 85% 越界尝试”等核心数字主要来自 Anthropic 自测。

**为什么值得关注：** 长时间运行的编码智能体越来越受制于推理成本、缓存费用和越权风险；这次更新把三者放在同一产品设计中，也让企业更容易把高阶模型用于整库迁移、审计和多智能体协作。

- **原文：** [Introducing Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)
- **交叉核验：** [Reuters](https://www.reuters.com/business/anthropic-unveils-claude-opus-55-2026-09-22/)；[The Verge](https://www.theverge.com/ai-artificial-intelligence/998868/anthropic-claude-opus-5-5-cybersecurity)
- **发布日期：** 2026-09-22 16:30 UTC（过去 24 小时）

## 2. Claude Code 2.1.280：修补符号链接越权与后台子智能体丢消息

![Claude Code 2.1.280 发布页](https://opengraph.githubassets.com/1/anthropics/claude-code/releases/tag/v2.1.280)

*图片来源：[Anthropic 官方 GitHub 发布页](https://github.com/anthropics/claude-code/releases/tag/v2.1.280)*

Claude Code 2.1.280 将 Opus 5.5 纳入并设为默认 Opus，同时允许通过环境变量调整所有 MCP 服务器 2,048 字符的工具描述上限。安全方面，它修复了经符号链接写入时只按“仓库内路径”判断、从而可能把实际落在仓库外的写操作误认为已授权的问题；自动模式被安全检查拒绝后也不再无限重复动作。可靠性修复还覆盖后台子智能体临近结束时消息丢失、对话压缩后子智能体报告消失，以及恢复未完成后台任务时意外自行启动模型回合。

**为什么值得关注：** 这批修复集中在“代理实际写到哪里、拒绝后是否停止、并行结果会不会丢”三条生产级边界，比新增 UI 功能更直接决定自动编码是否可信。

- **原文：** [Claude Code v2.1.280 官方发布说明](https://github.com/anthropics/claude-code/releases/tag/v2.1.280)
- **发布日期：** 2026-09-22 16:38 UTC（过去 24 小时）

## 5. CliffCompaction：长程编码智能体压缩成本最高降低 50%

![CliffCompaction 论文页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://arxiv.org/abs/2609.26779)

*图片来源：[arXiv 论文页面](https://arxiv.org/abs/2609.26779)*

新论文提出 CliffCompaction，用于跨会话、百万 Token 级长程编码任务的自动上下文压缩。其核心约束是只截断或删除原文、不改写内容，且每次都从原始上下文重新压缩，以避免“压缩再压缩”造成语义漂移。作者报告该方法在受限上下文下最高降低 50% 成本，同时维持或提升 Terminal-Bench 表现；其与 Harness 无关的 API 代理实现可用于 Claude Code、Codex 等工具。

**为什么值得关注：** 上下文压缩已成为长程智能体的关键系统组件；如果“只删不改”的策略能被独立复现，它可能比摘要式记忆更容易审计，也更适合持续数百步的工程任务。

- **原文：** [CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents](https://arxiv.org/abs/2609.26779)
- **发布日期：** 2026-09-22 17:55 UTC（过去 24 小时）
