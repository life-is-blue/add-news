## 1. Hermes Agent 0.22.2 修正错误构建，并加固休眠恢复

![Hermes Agent v0.22.2 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.2)

*图片来源：[NousResearch / hermes-agent GitHub Releases](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.2)*

- **发布日期：** 2026-10-15（过去 24 小时）
- **原文：** [Hermes Agent v0.22.2](https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.2)

Nous Research 表示，0.22.1 误由错误提交构建，夹带了尚未发布的 gateway 代码，并可能令 Microsoft Store 版本卡在 “Connecting”；0.22.2 才是预期的正式构建。新版以启动纪元和主机锁处理重启后 PID 被复用的问题，同时让长时间运行的本地模型任务在笔记本休眠后继续：读取提示时持续报告进度、暂停休眠期间的停滞计时，并在本地推理服务恢复后重试。官方也提醒，曾在 0.22.1 gateway 下运行的会话暂时无法在 0.22.2 删除。

**为什么值得关注：** 这不是单纯的版本号修补，而是暴露了自主智能体发布链与长任务生命周期的两个核心风险：构建可追溯性，以及跨重启、休眠和本地推理故障的状态恢复。

## 2. Claude Code 2.1.300 强化可观测性与会话持久化

![Claude Code v2.1.300 发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.300)

*图片来源：[Anthropic / claude-code GitHub Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.300)*

- **发布日期：** 2026-10-15（新加坡时间，过去 24 小时）
- **原文：** [Claude Code v2.1.300](https://github.com/anthropics/claude-code/releases/tag/v2.1.300)

Anthropic 在 2.1.300 中加入 OpenTelemetry 的生成式 AI 语义属性、缓存创建 token 指标，以及供扩展读取智能体执行记录的接口。版本同时修复智能体与子智能体持久化、云端重启后重复执行、worktree 引用、MCP 工具 schema 与重连，以及后台 runner 卡死等问题。为提高复现能力，本地 transcript 现在会记录每次 API 请求使用的 system prompt、工具和参数。

**为什么值得关注：** 编码智能体进入生产环境后，真正稀缺的不只是模型能力，而是能否审计、复现并恢复一次多工具执行；本次更新直接补齐了这条工程链路。

## 3. OpenCode 2.0.29 支持跨设备接管与截断自动续跑

![OpenCode 2.0.29 更新日志](https://image.thum.io/get/width/1200/crop/675/noanimate/https://opencode.ai/changelog)

*图片来源：[OpenCode 官方更新日志](https://opencode.ai/changelog)*

- **发布日期：** 2026-10-14（扩展至过去 72 小时；官方仅标注日期）
- **原文：** [OpenCode Changelog — v2.0.29](https://opencode.ai/changelog)

OpenCode 2.0.29 通过 OpenTunnel 提供二维码或链接配对，使桌面会话可以由移动设备远程接管，并新增 provider 账号管理。运行时会在输出 token 达到上限时自动续写，以有界重试处理截断的工具调用；终端界面也会区分“工作中”和“等待授权”。插件侧新增 `ctx.permission.assert`，可复用项目既有权限规则或调用原生审批提示。

**为什么值得关注：** 远程控制、自动续跑和权限断言同时出现，说明终端智能体正在从单机交互工具转向可持续、可接管、可治理的执行服务。

## 4. OpenAI 披露 Amp 如何让编码智能体走出代码编辑器

![OpenAI Amp 案例页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://openai.com/index/amp-beyond-coding/)

*图片来源：[OpenAI 官方案例](https://openai.com/index/amp-beyond-coding/)*

- **发布日期：** 2026-10-14（扩展至过去 72 小时；官方仅标注日期）
- **原文：** [Amp puts AI agents to work beyond code with OpenAI models](https://openai.com/index/amp-beyond-coding/)

OpenAI 的官方案例称，Amp 将 GPT-6 Astra 用于编程、写作和设计，并让名为 Puck 的助手通过 GPT-Live-1 启动、管理和查找其他智能体会话，包括语音与可穿戴设备入口。Amp 还接入 “Sign in with ChatGPT”，试图降低用户逐 token 管理模型成本的摩擦，并测试更低延迟的 Ultrafast 模式。上述效果来自厂商与客户案例陈述，并非独立基准测试。

**为什么值得关注：** 智能体产品的竞争焦点正从“补全代码”转向“调度多个执行者”；身份、计费、语音入口和低延迟由此成为自主开发协作的重要基础设施。

## 5. FSB 发布 12 项 AI 采用原则，点名高自主智能体的人类控制

![FSB AI 采用原则发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.fsb.org/2026/10/fsb-finalises-sound-practices-for-the-responsible-adoption-of-artificial-intelligence-ai/)

*图片来源：[Financial Stability Board 官方发布](https://www.fsb.org/2026/10/fsb-finalises-sound-practices-for-the-responsible-adoption-of-artificial-intelligence-ai/)*

- **发布日期：** 2026-10-15（过去 24 小时）
- **原文：** [FSB finalises sound practices for the responsible adoption of AI](https://www.fsb.org/2026/10/fsb-finalises-sound-practices-for-the-responsible-adoption-of-artificial-intelligence-ai/)
- **交叉核验：** [Reuters：全球金融监管协调机构要求加强对 agentic AI 的人类监督](https://www.reuters.com/legal/government/global-financial-watchdog-calls-more-human-oversight-agentic-ai-2026-10-15/)

金融稳定理事会发布最终报告，提出 12 项 AI 负责任采用实践，覆盖董事会与高管责任、全生命周期风险评估、数据治理、解释与评估、人类监督、网络与 ICT 风险，以及第三方依赖。文件把 “human-in-command” 与高自主性的 agentic AI 联系起来，强调组织必须保留干预、暂停或降级系统的实际能力。Reuters 对正式文件的报道亦将加强银行智能体人类监督列为核心信息。

**为什么值得关注：** 这是智能体治理从原则走向操作控制的明确信号；对编程和企业智能体团队而言，权限分级、停机机制、第三方模型依赖与董事会问责将越来越像上线前的硬要求。

## 今日观察

今天最重要的共同趋势不是“模型再快一点”，而是智能体系统开始围绕 **构建来源、状态恢复、执行可观测性、权限审批与最终人类控制** 建立工程边界。Hermes、Claude Code 与 OpenCode 从运行时侧补齐可靠性，FSB 则从治理侧把同一问题制度化；Amp 的多智能体入口扩张进一步说明，这些边界很快会从最佳实践变成产品竞争力。
