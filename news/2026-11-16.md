## 1. OpenClaw 2026.11.4：大规模会话、消息恢复与隐私边界同步加固

![OpenClaw 2026.11.4 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.11.4)

*图片来源：[OpenClaw 官方 GitHub 发布页](https://github.com/openclaw/openclaw/releases/tag/v2026.11.4)*

OpenClaw 2026.11.4 降低了大型 transcript 裁剪、分页记忆导出与 Doctor 修复对 worker 内存的压力，并调整启动顺序，避免在大规模存储中为孤儿扫描加载无关会话摘要。Gateway 重启后未答复提示可继续保留，WhatsApp 最终回复与 Signal 缓冲消息的交付也得到修复。版本还将 Side chat 限定在已认证查看者范围内，默认保护配对节点的照片与截图，并阻止内部模型提示投影进入显示输出。

**为什么值得关注：** 这是一次面向长期运行的系统性更新，重点不在单个新功能，而在会话规模扩大后仍能维持可恢复性、数据隔离和可预测升级。

- **原文：** [OpenClaw 2026.11.4 Release](https://github.com/openclaw/openclaw/releases/tag/v2026.11.4)
- **发布日期：** 2026-11-16（过去 24 小时）

## 2. Goose 1.59.2：修正 Databricks Gemini 的思考块串线

![Goose 1.59.2 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/aaif-goose/goose/releases/tag/v1.59.2)

*图片来源：[Goose 官方 GitHub 发布页](https://github.com/aaif-goose/goose/releases/tag/v1.59.2)*

Goose 1.59.2 修复 Databricks provider 的兼容性问题：当 thinking block 绑定到不同前缀时，系统会将其丢弃，而不是继续混入当前响应。该补丁紧接 1.59.1 对 Gemini 工具调用 ID 的修正，说明这一轮维护集中在 Databricks Gemini 响应流的关联与解析可靠性。

**为什么值得关注：** 推理块与工具结果一旦错误归属，智能体可能在表面正常的对话中携带错误上下文；及时丢弃不匹配数据比让污染继续传播更安全。

- **原文：** [Goose 1.59.2 Release](https://github.com/aaif-goose/goose/releases/tag/v1.59.2)
- **发布日期：** 2026-11-16（过去 24 小时）

## 3. Qwen Code 0.27.4：托管智能体接入本地目录、Web Terminal 与企业群聊

![Qwen Code 0.27.4 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/QwenLM/qwen-code/releases/tag/v0.27.4)

*图片来源：[Qwen Code 官方 GitHub 发布页](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.4)*

Qwen Code 0.27.4 允许 Managed Agent 会话通过临时授权访问指定本地目录，并提供使用短期 ticket 鉴权的交互式 Managed Web Terminal，授权信息和路径不会持久化。新版本加入飞书与企业微信群机器人输出、定时任务结果投递和长回复分段，同时恢复 CLI 的 `/memory` 控制与跨重启工作区设置。Auto Mode 对破坏性或批量操作要求显式授权，并在快速分类器超时时增加一次模型复核。

**为什么值得关注：** 该版本把本地文件、远程执行、团队消息与定时工作流接入同一个托管智能体表面，同时明确强化授权边界，接近企业自主开发协作所需的完整闭环。

- **原文：** [Qwen Code 0.27.4 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.4)
- **发布日期：** 2026-11-15（扩展至过去 72 小时）

## 4. Coding Agent Index v2.1：用更难的代码任务与更稳健的验证器重排智能体

![Artificial Analysis Coding Agent Index v2.1](https://image.thum.io/get/width/1200/crop/675/noanimate/https://artificialanalysis.ai/agents/coding-agents)

*图片来源：[Artificial Analysis 官方编程智能体榜单](https://artificialanalysis.ai/agents/coding-agents)*

Artificial Analysis 将 Coding Agent Index 升级至 v2.1，改用包含 132 个真实开源仓库任务的 FrontierCode-AA 2.0，并把 Terminal-Bench 更新至 4.1；SWE-Atlas-QnA-AA 继续衡量仓库理解能力。综合分采用三项基准等权平均，且每项任务运行三次。Terminal-Bench 4.1 保留 66 项任务，但修订验证器以减少误判并提高对 reward hacking 的抵抗力。

**为什么值得关注：** 榜单开始更明确地同时衡量“代码是否值得维护者合并”、终端执行和仓库理解，也暴露出模型与 harness 必须作为整体评估，而不能只看模型名称。

## 5. Agweb 0.3.0：为并行编码智能体打造独立 WebKit 工作区

![Agweb 0.3.0 官方发布页](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/paul-nameless/agweb/releases/tag/v0.3.0)

*图片来源：[Agweb 官方 GitHub 发布页](https://github.com/paul-nameless/agweb/releases/tag/v0.3.0)*

Agweb 是面向编码智能体的 macOS WebKit 浏览器，0.3.0 新增命名工作区与 profile，并让 `agweb list` 或 `agweb tree` 展示各 profile 下的工作区和标签页。被其他元素遮挡的点击现在会失败并报告遮挡对象，只有显式使用 `--force` 才会继续；内置 agent skill 也改为只关闭自己的工作区。当前版本要求 macOS 26 或更高版本。

**为什么值得关注：** 多个编码智能体同时操作网页时，独立工作区、可观察标签树和避免抢占前台焦点，比单纯包装浏览器自动化 API 更贴近实际并发开发流程。

- **原文：** [Agweb 0.3.0 Release](https://github.com/paul-nameless/agweb/releases/tag/v0.3.0)
- **发布日期：** 2026-11-15（扩展至过去 72 小时）
