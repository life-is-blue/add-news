## 1. Google 发布 Gemini 通用工作智能体：可持续执行、动态组建子智能体并运行代码

![Google Gemini agent 官方公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026/)

*图片来源：[Google Cloud 官方博客](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026/)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-08
- **事实摘要：**Google Cloud 发布面向企业的 Gemini agent，可在单一界面和 API 中处理知识工作、生成内容、编写并运行代码，也能按计划或事件启动任务。它在云端保留统一记忆与上下文，可让小时级或多日任务在用户离线后继续运行，并动态创建带独立身份的临时子智能体，组合并行或串行流程。底层模型与智能体分离，可在 Gemini、Anthropic Claude 等模型间路由；工具层支持 Git、Jira、Slack、Microsoft 365、数据库及 MCP 服务器。

- **原文链接：**[Google Cloud 官方公告](https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026/) · [Reuters 交叉报道](https://www.reuters.com/business/google-cloud-introduces-gemini-agent-work-ai-race-heats-up-2026-10-08/)

## 2. Claude Code 2.1.295：Hook 可“失败即阻断”，远程 MCP 与后台会话大幅加固

![Claude Code 2.1.295 发布页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/anthropics/claude-code/releases/tag/v2.1.295)

*图片来源：[Anthropic Claude Code 官方 GitHub 发布页](https://github.com/anthropics/claude-code/releases/tag/v2.1.295)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-08
- **事实摘要：**Claude Code 2.1.295 为命令与 HTTP hooks 新增 `onFailure: "block"`：钩子无法启动、超时或异常退出时，可阻止动作继续执行，而不是默认放行。版本还为网关加入按上游模型路由、首字节超时、请求 ID 对齐与审计能力，并修复远程 MCP 长时间中断后无法恢复或紧密重连、子智能体后台化引发竞态、恢复会话后计划任务丢失等问题。另有多项安全边界修复，包括迟注册内置工具绕过 `--tools`/`--restricted`、守卫钩子收到截断输入，以及插件重载期间调用绕过其他 guard hook。
- **为什么值得关注：**在前一日修复“钩子只被当成指令”后，Anthropic 进一步加入明确的 fail-closed 语义；这说明生产级编码智能体的关键不只是授权规则，还包括规则引擎自身失效时必须安全地停下来。
- **原文链接：**[Claude Code 2.1.295](https://github.com/anthropics/claude-code/releases/tag/v2.1.295)

## 5. GitHub 将草稿 PR 纳入并发上限，堵住低质量贡献绕过限流的入口

![GitHub 草稿 PR 限流公告](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.blog/changelog/2026-10-08-draft-pull-requests-count-toward-pull-request-limits/)

*图片来源：[GitHub 官方更新页面](https://github.blog/changelog/2026-10-08-draft-pull-requests-count-toward-pull-request-limits/)*

- **时间范围：**过去 24 小时
- **发布日期：**2026-10-08
- **事实摘要：**GitHub 允许维护者配置 PR 上限时把 draft pull requests 一并计入；此前用户即使触及普通 PR 限额，仍可无限创建草稿。新设置用于减少仓库垃圾、通知噪声和无效 CI 运行，回应维护者面对低质量贡献增加的治理压力。GitHub 没有把问题直接归因于 AI，因此“与编码智能体规模化提交相关”属于行业背景下的推断，而非官方因果结论。
- **为什么值得关注：**随着人类与智能体都能低成本并行提交变更，协作平台必须从事后关闭垃圾 PR 转向入口配额、身份信誉和计算资源治理；草稿也纳入限流，是这一转向的具体信号。
- **原文链接：**[GitHub Changelog](https://github.blog/changelog/2026-10-08-draft-pull-requests-count-toward-pull-request-limits/)
