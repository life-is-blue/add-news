## 1. OpenClaw 2026.8.1：把跨设备执行、协作可见性与权限控制推入稳定版

![OpenClaw 2026.8.1 发布页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://github.com/openclaw/openclaw/releases/tag/v2026.8.1)

*图片来源：[OpenClaw 官方 GitHub Release](https://github.com/openclaw/openclaw/releases/tag/v2026.8.1)*

**过去 24 小时｜发布日期：2026-08-31**

OpenClaw 2026.8.1 正式发布，新增跨配对设备或云端 worker 运行任务、迁移会话工作区并复用预热机器与项目种子的能力；Web 与原生客户端现在还能持续显示子智能体活动和累积修改。新版本也加入私密凭据请求、精确到操作的自动化授权、团队角色、共享凭据库及会话级权限模式，并把原有 Codex/OpenAI 路由统一迁移到 `openai/*`。官方发布记录使用签名标签，并提供 Docker、依赖及 ClawHub 镜像验证材料。

**为什么值得关注：** 这不是单点功能升级，而是 OpenClaw 从个人智能体向可恢复、可协作、可治理的自主工作平台迈进；对 Codex 等编码运行时的托管与迁移也直接影响组合式开发工作流。

**原文：** [OpenClaw 2026.8.1 Release Notes](https://github.com/openclaw/openclaw/releases/tag/v2026.8.1)

## 2. Codex 正式停用 GPT-5.4 系列的 ChatGPT 登录入口

![Codex 模型可用性更新](https://image.thum.io/get/width/1200/crop/675/noanimate/https://developers.openai.com/codex/changelog)

*图片来源：[OpenAI Codex 官方更新日志](https://developers.openai.com/codex/changelog)*

**过去 24 小时｜发布日期/生效日期：2026-08-31**

OpenAI 从今天起不再向使用 ChatGPT 账号登录的 Codex 会话提供 GPT-5.4 与 GPT-5.4 mini，并建议分别迁移到 GPT-5.6 Terra 和 GPT-5.6 Luna。API 以及使用 API key 认证的 Codex 会话不受影响，因此这次调整主要针对订阅登录路径。官方同时提醒用户更新工作区默认值、保存的模型设置、托管配置和自动化任务。

**为什么值得关注：** 固定模型名的长周期自动化可能直接失败或悄然改变成本与能力；团队应把模型选择视为可迁移配置，并为不同认证路径建立明确的兼容性检查。

**原文：** [ChatGPT & Codex Changelog](https://developers.openai.com/codex/changelog)

## 3. Claude Sonnet 5 保留每百万 token 2/10 美元定价

![Claude Sonnet 5 官方定价页面](https://image.thum.io/get/width/1200/crop/675/noanimate/https://platform.claude.com/docs/en/about-claude/pricing)

*图片来源：[Anthropic Claude Platform 官方定价文档](https://platform.claude.com/docs/en/about-claude/pricing)*

**过去 24 小时｜发布日期/生效日期：2026-08-31**

Anthropic 确认，原计划仅持续到 8 月 31 日的 Claude Sonnet 5 优惠价将转为标准价：每百万输入 token 2 美元、输出 token 10 美元。原定 9 月 1 日上调至 3/15 美元的安排取消；提示缓存仍按文档列出的独立倍率计费。该价格也决定了以 Sonnet 5 为默认模型的 Claude Code 与代理 API 工作负载的长期单位成本。

**为什么值得关注：** 对高频工具调用、长上下文和多智能体并行任务而言，取消 50% 的计划涨价会显著改变预算模型，也减轻了团队在 Claude Code 与其他编码代理之间因短期优惠而反复迁移的压力。

**原文：** [Claude Platform Pricing](https://platform.claude.com/docs/en/about-claude/pricing)

## 4. Grok Build 1.0.13：补齐长响应、瞬时故障与断电恢复

![Grok Build 1.0.13 更新日志](https://image.thum.io/get/width/1200/crop/675/noanimate/https://x.ai/build/changelog)

*图片来源：[xAI Grok Build 官方更新日志](https://x.ai/build/changelog)*

**扩展窗口｜发布日期：2026-08-28**

Grok Build 1.0.13 会自动续接因长度限制而截断的响应，并对停滞、连接中断和 5xx 等瞬时推理故障自动重试，而不是直接结束当前 turn。Hooks 现在可在工具调用前请求用户确认；版本还改进了提示后及断电时的会话持久化，并修复 Windows 下 `~/.grok` 与 worktree 会话打开问题。上述变化均来自 xAI 官方 changelog。

**为什么值得关注：** 自主编码任务的真实瓶颈经常不是模型不会写代码，而是长运行过程被瞬时错误或状态丢失打断；这次更新集中修复了编码智能体能否“持续把任务做完”的工程基础。

**原文：** [Grok Build Changelog](https://x.ai/build/changelog)

## 5. 麦肯锡调查：32% 组织曾因编码智能体改为内部自建软件

![麦肯锡 2026 年 AI 状态调查](https://image.thum.io/get/width/1200/crop/675/noanimate/https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai)

*图片来源：[McKinsey《The State of AI 2026》](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai)*

**扩展窗口｜新闻发布日期：2026-08-30；原始报告：2026-08-25**

据 8 月 30 日发布的报道，麦肯锡《The State of AI 2026》调查显示，32% 的受访组织曾放弃购买至少一项软件产品或功能，转而借助智能体编码工具内部构建；科技行业这一比例为 41%。医疗服务、专业服务、能源与材料及金融等行业也都出现相同趋势。该数字已与麦肯锡原始报告页面交叉核验，但仍属于受访组织的自报决策，而非经审计的实际采购支出。

**为什么值得关注：** 编码智能体正在影响“买还是造”的企业架构决策，竞争对象不再只是传统开发工具，也包括 SaaS 产品本身；这会推动内部平台、代码治理和智能体验收能力成为新的基础设施。

**原文：** [Mint/ANI 报道](https://www.livemint.com/technology/nearly-32-of-organizations-decide-to-build-in-house-software-using-ai-coding-agents-over-purchases-mckinsey-11788076917651.html)；[McKinsey 原始报告](https://www.mckinsey.com/capabilities/quantumblack/our-insights/the-state-of-ai)
