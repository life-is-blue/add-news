### 1. Claude Agent SDK参数注入可借恶意MCP配置绕过权限控制并执行命令

- **分类：** Coding Agent / MCP / SDK供应链
- **严重度：** 严重（CVE-2026-96620；CVSS v4.0 9.2，CVSS v3.1 9.8）
- **发布日期：** 2026-10-16（CVE与GitHub Advisory公开；修复版本此前已发布）
- **可信度：** 官方确认（Anthropic项目安全公告、修复提交与GitHub审核记录）
- **影响对象：** Python包 `claude-agent-sdk` 0.2.121之前版本；尤其是把用户可控值作为`resume`会话ID传入的服务、机器人和多租户Agent平台
- **发生了什么：** SDK过去将`resume`值未经充分校验地传给Claude CLI。攻击者若能控制该值，可用以连字符开头的内容注入额外CLI参数，并加入`--mcp-config`，定义一个启动时执行命令的stdio MCP服务器。命令在CLI初始化阶段运行，因而绕过SDK的工具权限和审批控制。利用并非对所有安装默认可达，前提是应用把不可信输入直接用于恢复会话。
- **为什么值得关注：** 这是“控制数据变成Agent启动参数”的典型边界失效。受害应用即使配置了严格的工具许可，恶意MCP进程仍可能在许可系统介入前获得Agent进程的文件、网络和凭据权限；多租户会话恢复接口尤其危险。
- **建议行动：** 立即升级至0.2.121或更高版本；排查所有`resume`和`session_id`来源，只接受服务端生成、格式固定且与当前租户绑定的标识。对Agent子进程实施最小权限、独立工作目录和网络出口限制，审查历史日志中异常的`--mcp-config`、短横线开头会话ID及非预期stdio子进程。若曾允许外部用户提交恢复ID，应按潜在命令执行事件轮换Agent可访问的令牌。
- **原始来源与补充来源：**
  - [Anthropic项目安全公告：GHSA-h4mw-j7qp-8mwm](https://github.com/anthropics/claude-agent-sdk-python/security/advisories/GHSA-h4mw-j7qp-8mwm)
  - [修复提交](https://github.com/anthropics/claude-agent-sdk-python/commit/347a1cb88d7652199399db1b7f914e0a459a6662)
  - [0.2.121发布记录](https://github.com/anthropics/claude-agent-sdk-python/releases/tag/v0.2.121)
  - [CVE-2026-96620](https://www.cve.org/CVERecord?id=CVE-2026-96620)

### 2. SGLang调试Dumper暴露未认证代码注入，当前披露版本仍无明确修复版

- **分类：** AI推理基础设施 / 远程代码执行
- **严重度：** 严重（CVE-2026-111391；CVSS v4.0 9.2）
- **发布日期：** 2026-10-16
- **可信度：** 多方确认（CVE记录、上游问题与受影响源码相互印证；截至本期上游未发布明确固定版本）
- **影响对象：** SGLang 0.5.10至0.5.22，且设置`DUMPER_SERVER_PORT`、使调试Dumper端点可被攻击者访问的推理集群
- **发生了什么：** `_evaluate_filter()`使用受限`eval()`处理调试过滤表达式，但攻击者可通过`re.search.__globals__`逃逸限制。未认证请求可向`/dumper/configure`提交恶意过滤器，并在下一次模型forward时于scheduler进程中执行Python代码。漏洞需要Dumper服务被启用并可达；截至本期未见可信的在野利用报告，也未见上游发布明确修复版本。
- **为什么值得关注：** SGLang常运行在高价值GPU节点，scheduler可能访问模型文件、对象存储凭据和集群控制面。一个原本为调试用途的端口若被服务发现、容器端口映射或错误的Kubernetes Service暴露，就可能把推理工作负载变成横向移动入口。
- **建议行动：** 立即关闭`DUMPER_SERVER_PORT`或把端点仅绑定到本机并由网络策略阻断；扫描Kubernetes Service、Ingress、安全组和容器端口映射。无法停用时应隔离节点、移除云凭据并限制文件系统写权限；持续跟踪上游修复，在厂商发布固定版本后优先升级。检查Dumper配置请求、异常filter表达式、scheduler子进程和GPU节点对外连接。
- **原始来源与补充来源：**
  - [CVE-2026-111391](https://www.cve.org/CVERecord?id=CVE-2026-111391)
  - [SGLang上游问题#44188](https://github.com/sgl-project/sglang/issues/44188)
  - [受影响源码位置（0.5.22）](https://github.com/sgl-project/sglang/blob/v0.5.22/python/sglang/srt/debug_utils/dumper.py#L1309-L1320)
  - [VulnCheck原始技术公告](https://www.vulncheck.com/advisories/sglang-0.5.10-through-0.5.22-code-injection-via-debug-dumper-filter)

### 3. 【72小时扩展】Apache Airflow SSH/SFTP Provider默认不校验主机密钥

- **分类：** CI/CD与数据工作流 / 凭据窃取 / 不安全默认配置
- **严重度：** 中等（Apache官方评级；CVE-2026-94134，外部CVSS v3.1评分9.1）
- **发布日期：** 2026-10-15
- **可信度：** 官方确认（Apache安全邮件与上游修复）
- **影响对象：** `apache-airflow-providers-ssh` 7.0.0之前版本和`apache-airflow-providers-sftp` 7.0.0之前版本；依赖默认SSH连接配置的Airflow任务
- **发生了什么：** Airflow的SSH Hook在未配置`host_key`、也未显式把`no_host_key_check`设为false时，默认接受任意服务器主机密钥。能处于worker与SSH/SFTP服务器之间的攻击者可冒充目标服务器，截获任务发送的密码、私钥派生认证流或数据。可延迟执行的SFTP路径存在相同默认行为，并由CVE-2026-94135单独跟踪；7.0.0修复相关默认值。
- **为什么值得关注：** Airflow广泛承载构建、发布、数据传输和运维自动化，连接中常包含生产凭据及敏感数据。问题不要求攻陷Airflow控制面，只需取得网络中间人位置；云网络、跨区域传输、DNS/BGP劫持或被控代理均可能提供这种位置。
- **建议行动：** 将SSH和SFTP Provider升级至7.0.0或更高；为每个连接固定可信`host_key`，显式设置`no_host_key_check=false`，不要依赖升级后的隐式默认值。盘点经SSH/SFTP传输的密钥和数据，检查主机密钥变更、异常目标IP及任务重试；高价值连接应使用独立短期凭据和网络级目标白名单。
- **原始来源与补充来源：**
  - [Apache安全公告邮件：CVE-2026-94134](https://lists.apache.org/thread/ksr1lztvd3zr74f8xd1hzch1ssl0l3lj)
  - [Apache Airflow修复PR #73419](https://github.com/apache/airflow/pull/73419)
  - [CVE-2026-94134](https://www.cve.org/CVERecord?id=CVE-2026-94134)
  - [CVE-2026-94135](https://www.cve.org/CVERecord?id=CVE-2026-94135)
