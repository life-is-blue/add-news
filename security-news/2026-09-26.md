## 1. Bitget确认约3.875亿美元资产被转至攻击者地址

- **分类**：重大资产盗窃、加密货币基础设施、后台系统入侵
- **严重度**：严重
- **发布日期**：2026-09-25至26
- **可信度**：官方确认（Bitget公告；外部安全机构参与调查）
- **影响对象**：Bitget交易所热钱包和温钱包、平台用户及相关区块链生态；Bitget Wallet和冷钱包据称未受影响
- **发生了什么**：Bitget于9月24日发现多个未授权转账，随后将确认的受影响资产从约3.516亿美元上调至约3.875亿美元。公司称攻击者攻破钱包基础设施中的关键后台系统，伪造交易数据并触发授权签名流程；底层漏洞已识别并修复，当前未发现进一步未授权转账。提款一度暂停，Mandiant和SlowMist参与调查。公司把攻击手法归因于疑似朝鲜组织，但该归因仍主要基于Bitget自身的IP行为和链上分析。
- **为什么值得关注**：事件不是简单私钥丢失，而是交易数据与签名授权链被操纵，说明即使密钥本身受到保护，签名前的数据完整性、审批逻辑和后台隔离仍可能成为单点失效。损失数字在调查中快速上调，也提醒外界不要把初报规模视为最终结论。
- **建议行动**：
  1. 交易所和托管机构应对“交易生成—风控—签名—广播”全过程实施独立数据校验、多人审批和金额/地址异常阻断。
  2. 将热钱包限额与平台总资产严格隔离，为高额和跨链转账设置延迟、独立签名域及人工复核。
  3. Bitget用户仅通过官方渠道确认提款恢复状态，警惕以退款、补偿或资产验证为名的钓鱼。
  4. 暂不把朝鲜归因视为独立确认；等待完整根因报告及第三方取证结论。

## 2. Kiteworks罕见建议全球客户临时关闭服务器

- **分类**：安全文件传输、潜在零日威胁、供应链与集中式平台风险
- **严重度**：高（预防性警报；尚无确认入侵）
- **发布日期**：2026-09-25至26
- **可信度**：官方确认“收到可信威胁情报并建议停机”；潜在零日和实际利用均未确认
- **影响对象**：自托管或企业部署的Kiteworks安全文件共享、传输和通信系统，特别是政府、金融及处理敏感文件的组织
- **发生了什么**：Kiteworks表示，联邦情报机构告知某威胁行为者可能在周末攻击部分客户系统，因此建议全球客户在指定六小时窗口关闭服务器，即使系统不直接暴露于互联网也应执行。公司同时强调，该措施是预防性的，目前不知道有Kiteworks系统被攻破；已知漏洞均已在9.5.1中修复。客服提及“潜在零日攻击”，但公司、执法机构和独立研究者尚未提供CVE、技术细节或已利用证据。
- **为什么值得关注**：让客户主动停止安全文件传输服务是极不寻常的风险处置，说明情报可信度或潜在影响较高。此类平台集中保存合同、财务、法律和政府资料，一旦被批量利用，可能形成类似历史上MOVEit、GoAnywhere和Accellion的集中数据窃取事件。
- **建议行动**：
  1. Kiteworks客户应执行厂商停机和恢复指引，并确认至少运行9.5.1；保存停机前后的系统、身份和网络日志。
  2. 检查异常管理员、文件下载、API调用、服务账户使用、出站连接和新建持久化机制。
  3. 暂时限制管理接口、API和文件传输入口至明确允许的网络；为服务账户和管理员启用独立凭据轮换。
  4. 不把“零日已在野利用”或“平台已被攻破”写入事件结论，等待Kiteworks或政府机构后续公告。

## 3. Microsoft SharePoint代码注入漏洞确认遭利用【72小时扩展】

- **分类**：在野漏洞、协作平台、企业内网入口
- **严重度**：高（CVE-2026-65660）
- **发布日期**：2026-09-24（主动利用警报；补丁于8月发布）
- **可信度**：官方确认（加拿大网络安全中心；Microsoft补丁）
- **影响对象**：尚未安装2026年8月安全更新的本地Microsoft SharePoint Server部署
- **发生了什么**：加拿大网络安全中心确认，CVE-2026-65660正在被主动利用。该漏洞涉及代码生成控制不当，具备相应访问条件的攻击者可在SharePoint服务器上执行代码。Microsoft已在8月累计更新中提供修复，但早期较弱的风险认知可能导致部分组织未及时升级。
- **为什么值得关注**：SharePoint通常保存内部文档、身份信息和业务流程，并与Active Directory及Microsoft生态深度连接。服务器失陷可成为窃取机密、植入Web Shell和向域环境横向移动的支点；“补丁已发布数周”并不意味着现实暴露已经下降。
- **建议行动**：
  1. 立即核对所有本地SharePoint Server的8月及后续安全更新，优先处理互联网可达实例。
  2. 搜索异常.aspx文件、内存加载行为、未知应用池子进程、计划任务和异常PowerShell/.NET活动。
  3. 检查服务账户、应用池身份和高权限会话是否异常使用；发现入侵迹象时轮换相关域凭据和密钥。
  4. SharePoint Online由微软维护，不应与本地SharePoint Server受影响范围混为一谈。
- **原始来源与补充来源**：
  - [加拿大网络安全中心：CVE-2026-65660主动利用警报](https://www.cyber.gc.ca/fr/alertes-avis/al26-023-vulnerabilite-touchant-microsoft-sharepoint-server-cve-2026-65660)
  - [Microsoft：SharePoint Server 2019八月安全更新KB5002894](https://support.microsoft.com/en-us/servicing/office/hotfix/august/5002894)
  - [CVE记录：CVE-2026-65660](https://www.cve.org/CVERecord?id=CVE-2026-65660)

## 4. Carbonato利用AI智能体控制并横向扩散Docker主机【72小时扩展】

- **分类**：AI智能体滥用、容器安全、僵尸网络与凭据窃取
- **严重度**：高
- **发布日期**：2026-09-22至24
- **可信度**：初步披露（ThreatDown原始技术研究；媒体独立复述）
- **影响对象**：在TCP 2375端口暴露未认证Docker API的主机，以及主机内保存的AI API密钥、SSH凭据、访问令牌和数据库凭据
- **发生了什么**：ThreatDown从一个未认证Docker Registry取得59个仓库、234个镜像标签和4.3GB数据，重建出名为Carbonato的攻击工具链。恶意程序通过开放的Docker API启动特权容器、挂载宿主机文件系统、建立反向SSH和多种持久化，并每五分钟扫描相邻网络。攻击者随后安装未经修改的开源Hermes Agent，只替换其SOUL.md角色指令，由名为GH0ST的智能体通过Telegram接收自然语言任务、生成并执行命令，优先搜集14家提供商的AI API密钥及其他凭据。
- **为什么值得关注**：这不是“AI生成恶意代码”的概念演示，而是把通用开源智能体作为入侵后的交互式操作层。攻击者无需为每个环境预写完整脚本，智能体可根据命令输出决定下一步，从而降低异构主机上的操作成本；根本入口仍是未认证Docker API，因此传统最小暴露和凭据隔离仍然有效。
- **建议行动**：
  1. 立即关闭公网和非必要网段上的Docker TCP 2375；确需远程管理时使用TLS双向认证、VPN和网络允许名单。
  2. 搜索GH0ST角色文件、CARBONATO_API_KEY、异常Telegram流量、反向SSH及指向AS262145的连接。
  3. 检查特权容器、宿主机挂载、cron、systemd timer、rc.local和OpenRC持久化；发现指标时从可信镜像重建主机。
  4. 轮换宿主机和容器中的AI API密钥、SSH密钥、云令牌及数据库凭据，避免只删除恶意容器。
- **原始来源与补充来源**：
  - [ThreatDown原始研究：Carbonato AI智能体僵尸网络](https://www.threatdown.com/blog/carbonato/)
  - [BleepingComputer：Carbonato攻击链概览](https://www.bleepingcomputer.com/news/security/new-carbonato-malware-uses-ai-agents-to-hijack-exposed-docker-hosts/)
