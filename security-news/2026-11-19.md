# 每日安全与科技泄露简报｜2026-11-19

> 时间范围：优先覆盖北京时间 2026-11-18 20:30 至 2026-11-19 20:30；第 4 条因主题相关性高扩展至过去 72 小时并明确标注。  
> 筛选原则：优先采用政府响应机构、厂商通告、CVE/补丁和受影响机构确认；不将匿名爆料或攻击者单方面主张写成事实。

## 今日要点

- **CISA 将 LiteLLM、Apache Axis、REDCap 和 Synology DSM/BSM 漏洞列入 KEV**，意味着已有在野利用证据；其中 LiteLLM 把 AI 网关的自定义代码测试接口变成了代码执行入口。
- **NGINX 一次修复多项内存安全问题**，HTTP/2、HTTP/3、解析器和邮件代理均可能成为入口；部分条件下可实现远程代码执行。
- **欧盟委员会首次公开确认一次使用 AI 工具的网络攻击**，部分数字服务仍未完全恢复，但目前没有证据表明委员会全体员工数据遭泄露。
- **Siemens Mendix Studio Pro 的 MCP Server 存在远程暴露和浏览器跨站请求风险**，体现“本地开发助手服务”若缺少边界控制会直接扩大开发终端攻击面。

## 1. CISA 新增 4 个已在野利用漏洞，LiteLLM AI 网关沙箱逃逸在列

- **分类**：在野漏洞 / AI 基础设施 / 企业软件供应链
- **严重度**：严重
- **发布日期**：2026-11-18
- **可信度**：官方确认
- **影响对象**：
  - BerriAI LiteLLM（CVE-2026-40217）
  - Apache Axis 1.x（CVE-2026-90436）
  - Vanderbilt University REDCap（CVE-2026-90817）
  - Synology DiskStation Manager / BeeStation OS（CVE-2024-10441）
- **发生了什么**：CISA 基于在野利用证据将上述 4 个漏洞加入 Known Exploited Vulnerabilities（KEV）目录。LiteLLM 漏洞位于 `/guardrails/test_custom_code` 自定义代码测试端点，攻击者可逃逸手工实现的 Python 沙箱并在代理进程中执行任意代码；官方 GitHub 安全公告列出的修复版本为 1.83.11 及以上。Apache Axis 漏洞可通过特制 SOAP Fault 触发不安全反射，在类路径存在可用类时实现未认证代码执行，而 Axis 1.x 已停止支持。REDCap 漏洞涉及公共调查上下文和数据导入逻辑，知道有效调查哈希的未认证攻击者可能在服务器执行代码。Synology 漏洞涉及系统插件守护进程的输出编码/转义错误，可导致远程代码执行。
- **为什么值得关注**：四项漏洞都进入 KEV，风险优先级高于仅有概念验证的普通高危漏洞。LiteLLM 常处在多个模型供应商、API 密钥和内部工具之间，代理进程一旦被接管，影响可能横跨模型凭据、请求数据和后端网络。Axis 与 REDCap 又常嵌入遗留企业软件和研究/医疗环境，资产发现难度较高。
- **建议行动**：
  1. 立即识别互联网或不可信网络可达的 LiteLLM、Axis、REDCap、DSM/BSM 实例，并按 KEV 优先级处置。
  2. LiteLLM 升级至 1.83.11 或更高版本；在完成升级前，限制管理端点和 `test_custom_code` 接口，仅允许受控管理网络访问，并轮换可能暴露给代理进程的模型/API 凭据。
  3. Axis 1.x 应迁移至受支持技术栈；若业务软件内嵌 Axis，向供应商确认补丁、临时缓解及取证要求。
  4. REDCap 管理方应按供应商社区公告升级并检查公共调查入口、异常导入请求和服务器进程；Synology 用户应安装适用更新并审计外部暴露。
  5. 对可能遭利用的资产执行取证排查，而不只做版本升级；CISA 对部分条目给出的联邦修复期限为 11 月 21 日，LiteLLM 为 12 月 2 日。
- **原始来源与补充来源**：
  - [CISA：Known Exploited Vulnerabilities Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
  - [GitHub Advisory Database：CVE-2026-40217 / LiteLLM](https://github.com/advisories/GHSA-wxxx-gvqv-xp7p)
  - [CVE.org：CVE-2026-40217](https://www.cve.org/CVERecord?id=CVE-2026-40217)
  - [Apache 公告：CVE-2026-90436](https://lists.apache.org/thread/8slf0j9gz35z56t0glt5h0ncwlbn4bdz)
  - [NVD：CVE-2026-90817](https://nvd.nist.gov/vuln/detail/CVE-2026-90817)

## 2. NGINX 修复 HTTP/2、HTTP/3、解析器等多项内存安全漏洞

- **分类**：软件供应链 / Web 基础设施 / 重大安全更新
- **严重度**：严重
- **发布日期**：2026-11-18
- **可信度**：官方确认；尚无官方确认的在野利用
- **影响对象**：使用受影响 NGINX Open Source、NGINX Plus，以及内嵌相关版本的 Ingress Controller、网关、WAF 或商业产品的组织；实际暴露取决于 HTTP/2、HTTP/3、resolver、mail proxy、TLS 1.3 等配置。
- **发生了什么**：NGINX 发布 1.30.7 stable 和 1.31.9 mainline，修复多项安全问题，包括 HTTP/2 流控内存破坏 CVE-2026-123007、HTTP/2 use-after-free CVE-2026-123633、HTTP/3 use-after-free CVE-2026-121810、resolver use-after-free CVE-2026-123634、邮件代理 use-after-free CVE-2026-113425，以及 TLS 1.3 请求体处理、别名路径和 stream 模块相关问题。F5 对 CVE-2026-123007 的 CVSS v4.0 评分为 9.2；特定条件下攻击者可使 worker 崩溃、破坏内存或远程执行代码。CERT-EU 表示研究人员已成功演示 CVE-2026-123007，但尚无在野利用报告。
- **为什么值得关注**：NGINX 广泛承担反向代理、Kubernetes Ingress 和 API 入口角色。即使代码执行仅获得 worker 权限，也可能访问上游凭据、内部服务、请求内容和挂载密钥。仅检查“前端负载均衡器是否安全”不足以判断后端 NGINX 是否暴露，容器镜像和发行版回补版本也可能与上游版本号不同。
- **建议行动**：
  1. 升级至 NGINX Open Source 1.30.7、1.31.9 或发行版明确标记为已回补的版本；NGINX Plus 按 F5 公告升级至相应修复版本。
  2. 盘点所有入口、边车、网关和产品内嵌 NGINX，核对实际运行镜像摘要与进程，而不是只看代码仓库中的声明版本。
  3. 根据配置逐项评估 HTTP/2、HTTP/3、resolver、mail proxy 和 TLS 1.3 暴露；若无法立即更新，可按厂商建议暂时关闭相关协议或模块，但单一缓解不能覆盖全部漏洞。
  4. 更新后确认旧 worker、Pod 和实例已被替换，并监控异常 worker 崩溃、核心转储和来自边缘服务的可疑内网连接。
- **原始来源与补充来源**：
  - [NGINX：Security Advisories](https://nginx.org/en/security_advisories.html)
  - [NGINX：1.30.7 / 1.31.9 发布信息](https://nginx.org/news.html)
  - [F5：2026-11-18 Out-of-band Security Notification](https://my.f5.com/s/article/K000164058)
  - [F5：CVE-2026-123007 公告](https://my.f5.com/manage/s/article/K000163926)
  - [CERT-EU：Critical vulnerabilities in NGINX](https://cert.europa.eu/publications/security-advisories/2026-022/)

## 3. 欧盟委员会确认遭 AI 辅助网络攻击，部分数字工具仍未完全恢复

- **分类**：AI 辅助攻击 / 政府机构 / 重大网络事件
- **严重度**：高
- **发布日期**：2026-11-19（事件于 2026-10-22 被发现）
- **可信度**：官方确认，技术细节仍属初步披露
- **影响对象**：欧洲委员会的部分数字工具和应用；具体系统、攻击入口、所用 AI 工具及受影响数据范围尚未公开。
- **发生了什么**：欧洲委员会发言人 Thomas Regnier 公开确认，委员会在 10 月遭遇使用 AI 工具的网络攻击，并于 10 月 22 日发现事件。机构随后启动调查并采取预防措施，临时下线多个应用，多数已恢复，但仍有部分工具离线。委员会目前表示，没有发现影响“委员会全体员工”的数据泄露证据。官方没有披露攻击者身份，也没有确认媒体所称的大规模个人数据泄露。
- **为什么值得关注**：这是欧盟首次公开确认一次针对其自身系统的 AI 辅助攻击。它说明 AI 在真实攻击中的价值可能首先体现为漏洞发现、自动化探测和操作扩展，而不是完全自主攻击。与此同时，官方尚未给出可复核的技术报告，因此不能由“使用 AI”推导出攻击规模、模型身份或自动化程度。
- **建议行动**：
  1. 政府与大型企业将高频自动化探测、异常并发请求和快速路径切换纳入检测规则，并保留足够的 API、身份和应用遥测用于还原 AI 加速的攻击链。
  2. 对关键应用实施最小权限、网络分段、强身份验证和速率限制，避免攻击自动化速度转化为横向移动速度。
  3. 关注欧洲委员会/CERT-EU 后续技术说明；在官方证据公布前，不采信关于攻击者、模型来源或泄露规模的匿名说法。
- **原始来源与补充来源**：
  - [Associated Press：A cyberattack using artificial intelligence targeted the EU](https://apnews.com/article/79705095e8141cd650196dbff1cf3c70)
  - [Reuters：EU Commission targeted in cyberattack](https://www.reuters.com/legal/litigation/eu-commission-targeted-cyberattack-politico-reports-2026-11-19/)

## 4. Mendix Studio Pro MCP Server 可被远程访问或遭浏览器 CSRF（扩展至 72 小时）

- **分类**：MCP / Coding Agent 与开发工具 / 本地服务安全
- **严重度**：高
- **发布日期**：2026-11-10；官方映射更新 2026-11-16，CISA 工控通告于 11 月 17 日发布
- **可信度**：官方确认
- **影响对象**：Mendix Studio Pro 11 的受影响版本，尤其是将 MCP Server 的 7782 端口暴露到外部网络，或在开发浏览器中缺少 Private Network Access 防护的工作站。
- **发生了什么**：Siemens 公告披露 Mendix Studio Pro MCP Server 的两项漏洞。CVE-2026-112136 因 HTTP listener 未严格绑定回环接口，可能允许具备网络访问能力的攻击者远程与 MCP Server 交互，CVSS v4.0 为 9.2；CVE-2026-112137 因未正确验证 Content-Type 和 Origin，可让恶意网页诱导开发者浏览器向本地 MCP Server 发出未经授权的请求，执行非预期操作。受影响的 11.15.x 应升级至 11.16.0 或更高版本，11.12.6 应升级至 11.12.7 或更高版本。
- **为什么值得关注**：MCP Server 连接开发环境和可执行工具，本地服务的网络绑定、Origin 校验和浏览器私网访问控制因此成为安全边界。此类漏洞并不依赖提示注入；传统的端口暴露和 CSRF 就足以把“本地开发助手”变成远程工具执行入口。
- **建议行动**：
  1. 按 Siemens 公告升级至已修复版本，并核实端口 7782 未对非受信网络开放。
  2. 如确需远程访问，使用经过身份验证的 VPN 或 SSH 隧道，不要直接建立入站防火墙例外。
  3. 在开发者浏览器启用 Private Network Access 防护；限制不可信站点访问本地网络，并监控 MCP 工具调用和异常本地请求。
  4. 将 MCP/Agent 本地监听端口、Origin/CORS 校验、认证和工具权限加入开发终端基线检查。
- **原始来源与补充来源**：
  - [Siemens ProductCERT：SSA-710379](https://cert-portal.siemens.com/productcert/html/ssa-710379.html)
  - [CISA ICS Advisory：Siemens Mendix Studio Pro](https://www.cisa.gov/news-events/ics-advisories/icsa-26-321-02)
