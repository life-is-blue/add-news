> **筛选原则：** 优先采用厂商安全公告、监管文件与受影响机构声明；对数据类型、影响范围和攻击方式仅采用已确认信息。

## 今日要点

### 1. AWS Advanced Go Wrapper 可在 Aurora PostgreSQL 连接时造成数据库权限提升

- **分类：** 云数据库 / 开源依赖 / 权限提升
- **严重度：** 高
- **发布日期：** 2026-11-13（北京时间；AWS 于11月12日 PST 发布）
- **可信度：** 官方确认（AWS Security Bulletin）
- **影响对象：** 使用 `awssql/v2` 2.0.0 至 2.0.2 连接 Amazon Aurora PostgreSQL 的应用；数据库搜索路径中存在可被低权限用户创建函数的 Schema 时风险最高
- **事实摘要：** CVE-2026-126793 源于 AWS Advanced Go Wrapper 的 Aurora PostgreSQL 方言检测。已认证数据库用户如果能在另一用户 `search_path` 中的 Schema 创建函数，可能在该用户通过受影响 Wrapper 连接时，将权限提升至该用户，甚至获得 `rds_superuser` 成员权限。受影响版本为 2.0.0—2.0.2，2.0.3 已修复。AWS 未报告在野利用。
- **值得关注的原因：** 漏洞利用发生在正常数据库连接与自动检测过程中，调用方无需主动执行攻击者函数。若高权限服务账号连接，低权限数据库用户可借搜索路径与对象解析规则放大权限。
- **建议行动：**
  1. 将 `github.com/awslabs/aws-advanced-go-wrapper/awssql/v2` 升级至 2.0.3 或更高版本。
  2. 审计 Aurora PostgreSQL 中 `public` 及高权限账户 `search_path` 内所有 Schema 的 `CREATE` 权限和未知函数。
  3. 无法立即升级时执行 `REVOKE CREATE ON SCHEMA public FROM PUBLIC;`，仅向受信任主体授予相关 Schema 创建权限。
  4. 检查异常函数创建、对象所有者变更及 `rds_superuser` 权限活动，并轮换可能被高权限会话访问的秘密。
- **原始链接：**
  - [AWS 安全公告 2026-182-AWS](https://aws.amazon.com/security/security-bulletins/2026-182-aws/)
  - [CVE-2026-126793](https://www.cve.org/CVERecord?id=CVE-2026-126793)

### 2. AWS SDK for pandas 默认 EMR 日志桶可被外部账户预占并读取日志

- **分类：** 云供应链 / 默认配置 / 日志泄露
- **严重度：** 高
- **发布日期：** 2026-11-13（北京时间；AWS 于11月12日 PST 发布）
- **可信度：** 官方确认（AWS Security Bulletin）
- **影响对象：** 使用 `awswrangler` 1.1.0 至 3.17.x 创建 Amazon EMR 集群、且未显式指定日志位置的用户
- **事实摘要：** CVE-2026-127119 涉及 AWS SDK for pandas 的 EMR 模块。未指定日志位置时，旧版本使用可预测的默认 S3 桶名 `aws-logs-{account}-{region}`，却未验证该桶是否属于调用方账户。远程攻击者若先注册相同桶名，可能读取被上传的 EMR 集群日志，包括作业步骤输出。3.18.0 已加入桶所有权验证；AWS 未披露已确认的实际利用。
- **值得关注的原因：** EMR 日志可能包含数据路径、查询、作业参数、错误堆栈和意外写入的凭据。问题发生在可信 SDK 的默认行为中，容易绕过代码审查对显式外传目标的检查。
- **建议行动：**
  1. 将 `awswrangler` 升级至 3.18.0 或更高版本。
  2. 盘点所有区域的默认 EMR 日志桶，确认所有者属于本账户；若名称已被外部账户占用，立即改用显式自有桶。
  3. 检查 CloudTrail、EMR 配置和作业历史，确认是否曾向非本账户桶写入日志。
  4. 对可能外泄的作业参数、临时令牌或数据位置进行影响评估，并避免在日志中输出秘密。
- **原始链接：**
  - [AWS 安全公告 2026-181-AWS](https://aws.amazon.com/security/security-bulletins/2026-181-aws/)
  - [CVE-2026-127119](https://www.cve.org/CVERecord?id=CVE-2026-127119)

### 3. Caixa Vida e Previdência 确认约760万活跃客户登记资料被复制

- **分类：** 重大数据泄露 / 金融与保险 / 个人信息
- **严重度：** 严重
- **发布日期：** 2026-11-12（过去24小时）
- **可信度：** 官方确认（Caixa Seguridade 市场公告；巴西国家通讯社交叉核验）
- **影响对象：** 巴西 Caixa Vida e Previdência 的全部约760万活跃客户及数量尚未披露的前客户
- **事实摘要：** Caixa Seguridade 表示，其参股公司 Caixa Vida e Previdência 于11月6日发现未授权访问，攻击者将现有和前客户登记数据库中的资料复制到技术环境之外。已确认涉及姓名和 CPF 纳税人号码，部分记录还包含地址、电话、电子邮件和出生日期。公司称目前没有迹象表明保单金额、养老金余额、银行资料、密码等金融或认证数据被攻破，并已于11月11日通知巴西数据保护机构 ANPD 和其他主管机关。
- **值得关注的原因：** 姓名与 CPF 结合联系方式和出生日期，足以显著提高身份冒充、贷款/保险诈骗和精准钓鱼的可信度。即使密码和银行数据未泄露，长期身份标识仍难以更换。
- **建议行动：**
  1. 受影响客户应警惕利用姓名、CPF、保单或养老金话术实施的电话、短信和邮件诈骗。
  2. 通过官方渠道核验所有账户、付款和资料变更请求，不向来电者提供密码、验证码或银行信息。
  3. 机构应监测异常开户、受益人变更、账户恢复和大批量客户资料查询，并加强人工复核。
  4. 关注公司及 ANPD 后续披露，以确认前客户数量、攻击入口和数据是否被进一步传播。
- **原始链接：**
  - [Caixa Seguridade 投资者关系公告入口](https://www.ri.caixaseguridade.com.br/)
  - [Agência Brasil 对公司公告的报道](https://agenciabrasil.ebc.com.br/economia/noticia/2026-11/caixa-seguridade-informa-ataque-cibernetico-e-vazamento-de-dados)

### 4. TSMC 确认部分现任与前员工资料通过外部云服务环境泄露

- **分类：** 科技公司 / 第三方云供应链 / 员工数据泄露
- **严重度：** 高
- **发布日期：** 2026-11-12（过去24小时）
- **可信度：** 官方确认（TSMC 向美国 SEC 提交 Form 6-K）
- **影响对象：** 部分 TSMC 现任和前员工；受影响人数和具体字段尚未公开
- **事实摘要：** TSMC 在监管文件中确认，部分现任和前员工资料未经授权出现在外部网站。公司核验后认为，这些资料与一家云服务供应商系统中保存的数据相符；目前没有证据表明 TSMC 自身系统遭入侵。TSMC 明确表示事件与公司运营或客户相关数据无关，并已通知受影响人员，同时与云供应商、调查机关和第三方安全机构共同调查。
- **值得关注的原因：** 半导体企业员工资料可被用于定向钓鱼、招聘冒充和供应链社交工程。事件也表明，关键科技企业的风险边界延伸至外部云服务商，但现有证据不支持推断芯片设计、源代码、客户资料或制造数据已泄露。
- **建议行动：**
  1. 受影响员工应提高对招聘、福利、工资、云盘共享和公司登录主题钓鱼的警惕，启用抗钓鱼 MFA。
  2. TSMC 相关合作伙伴应通过既有渠道核验员工身份、付款和文件共享请求。
  3. 企业应盘点云供应商保存的员工资料，实施字段最小化、保留期限、客户管理密钥和可审计导出控制。
  4. 关注 TSMC 后续监管文件；在字段与人数确认前不要采用攻击者对数据规模或内容的未经证实主张。
- **原始链接：**
  - [TSMC 向 SEC 提交的 Form 6-K](https://www.sec.gov/Archives/edgar/data/1046179/000104617926000800/a20261112statementregardin.htm)

## 科技产品与商业机密泄露观察

本期确认一项科技公司数据泄露：TSMC 部分现任与前员工资料经外部云服务环境泄露。但 TSMC 明确表示该事件与公司运营和客户数据无关，现有证据也未显示芯片设计、未发布产品资料、源代码、模型参数或内部路线图被访问。过去24小时内未发现 Apple、OpenAI、Anthropic、Google、Microsoft 等公司符合确认门槛的新产品或商业机密泄露事件。

## 结论

本期两项 AWS 漏洞都来自“可信默认行为”：数据库 Wrapper 的方言检测可能触发权限提升，EMR SDK 的默认日志位置可能把数据写入攻击者预占的桶。企业应同时升级依赖并审查旧配置留下的权限与数据流。Caixa 与 TSMC 事件则共同说明，身份与员工资料泄露即使不包含密码或核心业务数据，也会形成长期社交工程风险。
