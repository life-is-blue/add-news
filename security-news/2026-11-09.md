## 今日要点

### 1. npm 包 `@ethersphere/bee-js@13.3.0` 被植入跨平台窃密与持久化代码

- **分类：** 软件供应链 / npm / 开发者终端
- **严重度：** 严重
- **发布日期：** 2026-11-09（过去24小时）
- **可信度：** 高（GitHub Advisory、OSV 与原始研究相互印证）
- **影响对象：** 安装或运行了 `@ethersphere/bee-js@13.3.0` 的开发者、CI/CD 主机及使用 Swarm Desktop 的用户
- **事实摘要：** 版本 13.3.0 于 11 月 9 日 00:09 UTC 发布，安装钩子会下载并执行攻击者控制的 JavaScript。研究显示，载荷会在 Linux、macOS 和 Windows 上建立持久化，搜索 Swarm Desktop 钱包相关文件并向 `api.frameworkmetrics[.]xyz` 外传数据。GitHub Advisory 将该版本标为恶意包，并明确指出：只要安装或运行过该版本，就应视主机已完全失陷。当前没有可视为安全修复的后续版本；攻击基础设施随后改为返回诱饵或 404，并不能证明已执行过安装脚本的主机安全。
- **值得关注的原因：** 这是典型的“安装即执行”供应链攻击；开发者工作站和 CI 运行器通常同时持有源代码、发布令牌、云凭据与钱包材料，单个依赖版本即可跨越多个信任边界。
- **建议行动：**
  1. 立即在锁文件、制品、镜像和缓存中检索并隔离 `@ethersphere/bee-js@13.3.0`，暂停相关流水线。
  2. 不要只卸载软件包；重建受影响主机，并从干净设备轮换 npm、GitHub、云平台、SSH、签名及钱包相关密钥。
  3. 检查安装日志、进程与出站 DNS/HTTP 记录中是否出现 `frameworkmetrics[.]xyz`，同时审计未知持久化项。
  4. 对依赖安装启用版本锁定、安装脚本审查/禁用策略和短期凭据，避免 CI 使用长期高权限令牌。
- **原始链接：**
  - [StepSecurity 原始分析](https://www.stepsecurity.io/blog/ethersphere-bee-js-13-3-0-compromise)
  - [GitHub Security Advisory：GHSA-hh7j-5m3j-23pf](https://github.com/advisories/GHSA-hh7j-5m3j-23pf)
  - [OSV：MAL-2026-18773](https://osv.dev/vulnerability/MAL-2026-18773)

### 2. OpenSSH 在特定 musl/无 PAM 配置下可绕过密码认证

- **分类：** 在野利用前置风险 / 身份认证 / Linux 基础设施
- **严重度：** 严重
- **发布日期：** 2026-11-07（72小时扩展；官方修复版本发布）
- **可信度：** 高（Alpine 官方公告、CVE 与 GitHub Advisory 相互印证）
- **影响对象：** 使用 musl libc、未启用 PAM、运行 OpenSSH 10.6p2 之前版本且开启密码认证的 Linux 系统；Alpine Linux 是主要受影响场景
- **事实摘要：** CVE-2026-123158 可在一组特定条件同时满足时绕过 SSH 密码认证：目标账户的密码字段为 `*`，系统存在至少一个使用 `$5$` 或 `$6$` 哈希的本地账户，且攻击者提交 257—1024 字节密码。攻击无需知道目标密码，一次尝试即可登录。Alpine 已在 3.21.10、3.22.8、3.23.8 和 3.24.4 中修复；官方同时强调更新后必须重启 `sshd`。截至本简报未见官方确认的在野利用证据。
- **值得关注的原因：** 漏洞直击互联网暴露的远程管理入口，且“账户被锁定/密码字段为星号”通常会被管理员误认为天然不可登录；容器、网络设备和轻量 Linux 环境中 musl 与无 PAM 组合并不少见。
- **建议行动：**
  1. 立即升级到 Alpine 已修复版本或 OpenSSH 10.6p2 及之后版本，并重启 `sshd`。
  2. 无法立刻升级时设置 `PasswordAuthentication no`，重启服务，并只保留受控的密钥认证。
  3. 盘点 `/etc/shadow`、`sshd_config`、PAM 状态及公网暴露面；核查近期 SSH 登录、`authorized_keys`、`doas/sudo` 与系统文件变更。
  4. 若无法排除异常登录，应按主机失陷处置，隔离并轮换该主机可访问的所有凭据。
- **原始链接：**
  - [Alpine 官方安全公告](https://www.alpinelinux.org/posts/2026-11-05-openssh-password-authentication-bypass/)
  - [Alpine 修复版本公告](https://www.alpinelinux.org/posts/alpine-3.21.10-3.22.8-3.23.8-3.24.4-released/)
  - [GitHub Security Advisory：GHSA-4fcc-vm97-gx3x](https://github.com/advisories/GHSA-4fcc-vm97-gx3x)
  - [Red Hat CVE-2026-123158](https://access.redhat.com/security/cve/cve-2026-123158)

### 3. D-Link DGS-3130-30TS B1 披露多项暂无补丁的 DDP/固件漏洞

- **分类：** 网络设备 / 零日漏洞 / 企业基础设施
- **严重度：** 高
- **发布日期：** 2026-11-06（72小时扩展）
- **可信度：** 高（D-Link 官方临时安全公告；研究者已向厂商演示受控利用）
- **影响对象：** D-Link DGS-3130-30TS、硬件修订版 B1 的部署；尤其是管理或发现协议可被不可信网络访问的交换机
- **事实摘要：** D-Link 在协调披露后发布临时公告，确认该型号的 D-Link Discovery Protocol（DDP）和固件安全存在多项漏洞。厂商称研究者已演示受控利用，潜在后果包括泄露设备信息、执行未经授权的管理操作、修改配置及造成服务中断。利用需要能够访问受影响网络；截至本简报尚无正式补丁、CVE 编号或官方确认的在野利用证据，公告状态仍为“Partial”。
- **值得关注的原因：** 交换机位于企业网络的信任骨干，未经授权的配置变更可能导致流量重定向、监听或大范围中断；“需要网络访问”不等于低风险，因为访客网、被入侵终端或错误分段都可能提供攻击路径。
- **建议行动：**
  1. 精确盘点 DGS-3130-30TS B1，订阅厂商公告并准备补丁发布后的优先变更窗口。
  2. 将管理平面与用户/访客网络隔离，只允许受控管理站访问；关闭非必要的 DDP/发现功能及远程管理入口。
  3. 对配置变更、管理员登录、设备重启及异常二层流量启用告警，并导出当前配置与日志作为基线。
  4. 在补丁可用前，不要把边界 ACL 或“仅内网可达”视为唯一防线；结合 NAC、管理 VLAN 和最小权限控制。
- **原始链接：**
  - [D-Link 官方安全公告 SAP10523](https://supportannouncement.us.dlink.com/security/publication.aspx?name=SAP10523)
  - [BleepingComputer 对官方公告的交叉核验](https://www.bleepingcomputer.com/news/security/d-link-warns-of-multiple-zero-days-in-dgs-3130-series-switches/)
