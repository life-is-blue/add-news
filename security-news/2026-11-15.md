## 今日要点

### 1. Cursor 确认 Fireworks AI 泄露的访问密钥引发数据访问，并最终导致 Claude Code 扩展被投毒

- **分类：** Coding Agent / 插件供应链 / 凭据泄露 / 源代码泄露
- **严重度：** 严重
- **发布日期：** 2026-11-13（72小时扩展窗口）
- **可信度：** 官方确认（Cursor 与 Fireworks AI 安全公告）
- **影响对象：** Cursor 非隐私模式的少量历史 Coding Agent 会话；部分 Cursor 内部 SaaS、归档非生产源代码和支持数据；2026年10月29日从 Cursor VS Code 扩展市场请求特定 Claude Code 版本的用户
- **事实摘要：** Cursor 调查确认，攻击者首先取得 Cursor 发给 Fireworks AI 的访问密钥，并从双方共享的只读存储桶复制了主要来自2025年的少量非隐私模式 Coding Agent 轨迹。其中未被脱敏的凭据影响不到0.01%的客户，攻击者随后借这些凭据进入 Cursor 使用的部分 SaaS，访问归档的非生产源代码仓库、有限支持邮件和会话摘要等资料。10月29日，攻击者又利用从内部系统数据中取得的凭据，直接向 Cursor 扩展市场缓存放入恶意的 `Anthropic.claude-code` 2.1.312 和 2.1.313；最多约5,000名请求这些特定缓存版本的用户可能收到恶意构建，暴露约11小时。Cursor 强调这不是 Anthropic 产品漏洞，Open VSX 原始市场也未被投毒。
- **值得关注的原因：** 这是从 AI 模型/推理供应商密钥、训练数据桶、会话中残留秘密、内部 SaaS 到插件分发缓存的完整供应链攻击链。它说明 Coding Agent 轨迹本身会成为“二次秘密仓库”，而扩展市场的缓存和镜像也必须具备与正式发布系统相当的签名、来源验证和隔离。
- **建议行动：**
  1. 曾在10月29日从 Cursor 市场安装或更新 Claude Code 2.1.312/2.1.313 的用户，应按 Cursor 指引执行 IOC 检查和清理；仅卸载扩展不足以消除可能的持久化。
  2. 轮换在 Agent 对话、支持工单、日志或代码片段中出现过的 API 密钥、SSH 密钥和云凭据，并检查异常使用记录。
  3. 企业应强制 Coding Agent 隐私/不留存模式，部署提交前与会话出口秘密扫描，并限制第三方模型供应商对历史轨迹的访问期限和范围。
  4. 对扩展市场实施发布者强认证、端到端签名验证、不可变制品哈希和缓存来源校验；将镜像与缓存视为生产软件供应链。
- **原始链接：**

  - [Cursor：恶意 Claude Code 扩展初始安全通知](https://cursor.com/blog/anthropic-claude-code-extension-security-incident)
  - [Fireworks AI：安全公告](https://fireworks.ai/security/bulletins)

### 2. IBM ContextForge MCP Gateway 集中修复凭据覆盖、身份传播和多项授权边界漏洞

- **分类：** MCP / AI 智能体基础设施 / 身份与凭据 / SSRF
- **严重度：** 高
- **发布日期：** 2026-11-12—2026-11-13（72小时扩展窗口）
- **可信度：** 官方确认（IBM Security Bulletin）
- **影响对象：** 部署 IBM ContextForge MCP Gateway 1.0.0—1.1.0 的组织；部分漏洞影响范围截至1.0.11
- **事实摘要：** IBM 发布多项 ContextForge MCP Gateway 公告。最高风险的 CVE-2026-110279（CVSS 8.1）允许已认证用户通过 `X-Upstream-Authorization` 覆盖网关管理的上游 OAuth、Bearer 或 Basic 凭据，绕过按用户权限和审计归属；CVE-2026-110278（CVSS 7.4）可能因身份传播设置未正确执行而把用户ID、邮件、组和团队信息发送给本不应接收它的第三方 MCP 服务器，并存在签名重放风险。IBM 同期还修复了 OAuth 令牌交换缓存授权绕过、动态客户端注册 SSRF、配置导入访问控制和拒绝服务等问题。1.1.1 修复前两项高风险漏洞，其他公告要求至少升级到1.1.0。
- **值得关注的原因：** MCP 网关同时充当身份代理、秘密托管者和网络出口。一处 Header 处理或缓存键错误，就可能把“低权限 Agent 调用”转换为“使用另一凭据访问上游工具”，并破坏审计可信度；身份传播错误还会把最小披露策略变成跨供应商数据泄露。
- **建议行动：**
  1. 优先将 ContextForge MCP Gateway 升级至1.1.1或更高版本，并逐项核对 IBM 公告所列最低修复版本。
  2. 升级前在反向代理移除所有进入 MCP 端点的 `X-Upstream-Authorization`，并将 MCP 端点限制在可信网络。
  3. 暂停不必要的身份传播；如无法升级，设置 `IDENTITY_PROPAGATION_ENABLED=false`。
  4. 禁用或严格限制 OAuth Dynamic Client Registration，配置 `DCR_ALLOWED_ISSUERS`，审计异常上游目标、凭据替换和跨用户令牌复用。
  5. 对每个 MCP 工具建立独立服务身份和最小权限，避免网关持有可横向访问全部上游系统的共享高权限凭据。
- **原始链接：**
  - [IBM：CVE-2026-110279 凭据覆盖漏洞](https://www.ibm.com/support/pages/node/7296490)
  - [IBM：CVE-2026-110278 身份信息暴露漏洞](https://www.ibm.com/support/pages/security-bulletin-ibm-contextforge-mcp-gateway-affected-information-exposure-vulnerability)
  - [IBM：CVE-2026-110195 OAuth 令牌缓存授权绕过](https://www.ibm.com/support/pages/node/7296695)
  - [IBM：CVE-2026-110194 动态客户端注册 SSRF](https://www.ibm.com/support/pages/node/7296696)

### 3. CISA 将 Check Point Gaia 提权漏洞与 UnrealIRCd 命令注入漏洞列入 KEV

- **分类：** 在野漏洞 / 网络边界设备 / 通信基础设施
- **严重度：** 严重
- **发布日期：** 2026-11-13（72小时扩展窗口）
- **可信度：** 官方确认（CISA KEV；厂商公告交叉核验）
- **影响对象：** 运行受影响 Check Point Gaia 的防火墙、管理与日志服务器、Security Gateway 和可扩展平台；运行多节点互联 UnrealIRCd 的 IRC 网络
- **事实摘要：** CISA 基于已确认在野利用新增两项 KEV。CVE-2026-123039（CVSS 7.8）源于 Check Point Gaia DynamicCLI 以 root 运行却监听全局可写本地套接字，已取得本地访问的攻击者可将命令提升为 root；Check Point 表示已观察到该漏洞与 PHP2Shell 初始访问组成攻击链，部分事件出现破坏性活动。CVE-2026-114713 允许普通 UnrealIRCd 用户在至少两台互联服务器的网络中注入以服务器权限执行的命令，项目称其为十五年来最严重的漏洞并确认已遭利用。CISA 为 CVE-2026-123039 给出的联邦修复截止日为11月16日。
- **值得关注的原因：** 两项漏洞都把低权限或已有立足点迅速升级为基础设施级控制权。Check Point 位于网络边界，若与已知远程入口串联会直接危及内网；UnrealIRCd 的跨服务器信任会把单个普通连接的输入传播为网络级管理命令。
- **建议行动：**
  1. Check Point 客户立即安装对应版本的最新 Jumbo Hotfix，并按厂商 IOC 检查10月30日起的异常 DynamicCLI、Web 接口和 root 活动。
  2. 无法立即修补 Check Point 时，按厂商步骤停止并禁止 `dynamic_server` 重启，同时限制 Gaia Portal/Clish 访问。
  3. UnrealIRCd 升级到6.2.7.1或更高版本，或应用官方热补丁；升级前先部署官方 `SPAMFILTER` 临时缓解。
  4. 对互联 IRC 节点检查异常服务器命令、KILL/GLINE、权限变更和IP地址泄露，并重置可能已被攻击者取得的管理员凭据。
- **原始链接：**
  - [CISA 已知在野利用漏洞目录](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
  - [Check Point：主动利用与攻击链公告](https://blog.checkpoint.com/security/security-advisory-active-exploitation-of-php2shell-and-local-privilege-escalation/)
  - [Check Point：CVE-2026-123039 修复说明](https://support.checkpoint.com/results/sk/sk1000362)
  - [UnrealIRCd 6.2.7.1 与热补丁公告](https://forums.unrealircd.org/viewtopic.php?t=9487)

### 4. 德国 Stadtwerke Achim 网络攻击导致核心IT、客户门户和结算流程持续中断

- **分类：** 关键基础设施 / 公用事业 / 运营中断
- **严重度：** 高
- **发布日期：** 2026-11-13 更新（72小时扩展窗口；事件于11月8日发现）
- **可信度：** 官方确认（Stadtwerke Achim 公告）
- **影响对象：** 德国 Achim 地区电力、燃气和区域供热客户；该公用事业公司的客户门户、邮件、计量与结算流程
- **事实摘要：** Stadtwerke Achim 表示，其监控系统于11月8日发现一起“有针对性、专业实施的犯罪网络攻击”，随后断开外部连接并隔离受影响系统。11月13日更新确认，中央IT故障仍使客户门户和邮件不可用，并造成电表更换预约、11月能源扣款、可再生能源与热电联产补贴支付延迟。公司称供电、供气和区域供热始终未受影响，目前没有可靠迹象显示客户或合作伙伴系统受到波及；攻击入口、攻击者、是否勒索软件以及数据是否外泄仍在取证调查。
- **值得关注的原因：** 即便工业控制与能源供应保持隔离，企业IT被破坏仍能中断计量、结算、付款和客户服务，形成持续的业务与现金流影响。这是关键基础设施“生产连续但业务运营失灵”的典型风险。
- **建议行动：**
  1. 公用事业单位应验证企业IT与OT的身份、网络和备份隔离，确保IT域失陷不能获取控制网凭据或管理接口。
  2. 为计量、结算、补贴支付和客户沟通准备离线或人工替代流程，并定期演练。
  3. Stadtwerke Achim 客户应仅通过官网和已知电话号码核验付款、账户或补贴信息，防范利用服务中断实施的钓鱼和催款诈骗。
  4. 关注后续取证与数据保护通知；在官方确认前，不将本事件归类为勒索软件或数据泄露。
- **原始链接：**

## 科技产品与商业机密泄露观察

本期确认一项与科技公司内部资料相关的事件：Cursor 官方确认，攻击者访问了部分归档的非生产源代码仓库、Coding Agent 会话摘要及有限支持数据。现有证据不表明 Cursor 生产代码仓库、正式发布系统或签名密钥被访问，也不表明 Anthropic 自身系统或 Claude Code 产品存在漏洞。

过去72小时内，未发现 Apple、OpenAI、Anthropic、Google、Microsoft 等公司达到确认门槛的未发布产品资料、模型参数、内部路线图或供应商/员工泄密新事件；匿名爆料与无原始证据的产品传闻未收录。

## 结论

本期四项事件呈现同一条风险链：AI/开发基础设施正把供应商访问密钥、Agent 历史轨迹、MCP 身份代理和插件分发缓存连接成高价值攻击面。企业不能只修补终端插件或单个CVE，还需要控制秘密在会话、支持系统和供应商数据集中的传播，并对网关身份转换、缓存及制品来源建立可验证的边界。与此同时，Stadtwerke Achim 事件说明关键基础设施的业务IT恢复能力，与OT隔离同样决定实际社会影响。
