## 1. CISA 新增 4 个 KEV：vCenter 认证绕过已确认在野利用

- **分类**：在野漏洞 / 企业基础设施 / 供应链
- **严重度**：严重
- **发布日期**：2026-11-20
- **可信度**：官方确认
- **影响对象**：
  - VMware vCenter（CVE-2026-123890）
  - Cisco Expressway Series（CVE-2026-76466）
  - SAP NetWeaver Enterprise Portal（CVE-2025-42884）
  - Apache Roller（CVE-2026-129448）
- **发生了什么**：CISA 基于在野利用证据将 4 项漏洞加入 Known Exploited Vulnerabilities（KEV）目录。CVE-2026-123890 是昨日简报已报道的 vCenter Directory Service 认证绕过，本次新增信息是 CISA 已确认其被实际利用。Cisco Expressway 漏洞涉及硬编码凭据，具备网络访问和特定持久 Cookie 的未认证攻击者可能在集群设备上以 root 权限执行命令。SAP NetWeaver Enterprise Portal 漏洞可通过注入 JNDI 环境属性或恶意 JNDI URL 访问非预期提供者，读取或修改服务器信息。Apache Roller 漏洞的具体处置应以 CISA KEV 和项目公告为准。
- **为什么值得关注**：KEV 状态改变了修复排序。vCenter 和 Expressway 都处于身份与管理控制平面，一旦失守可成为横向移动和持久化入口；SAP、Roller 则常存在于遗留业务或外部门户中，容易被资产清单遗漏。CISA 为这批漏洞设定了紧迫的联邦修复期限。
- **建议行动**：
  1. 将这 4 项漏洞置于最高修复队列，先处理互联网暴露、管理网可达和拥有高权限连接的实例。
  2. 对 vCenter 不仅安装 VMSA-2026-0009 更新，还要检查异常目录服务活动、管理员创建、API 调用、虚拟机导出和可疑持久化。
  3. Cisco Expressway 按厂商公告升级，并排查集群数据库服务、异常 root 命令和未知持久 Cookie。
  4. 对 SAP NetWeaver、Apache Roller 执行资产发现和日志取证；无法修复或已停服产品应隔离或迁移，而非仅依赖外围过滤。
- **原始来源与补充来源**：
  - [CISA：Known Exploited Vulnerabilities Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
  - [Broadcom：VMSA-2026-0009](https://support.broadcom.com/web/ecx/support-content-notification/-/external/content/SecurityAdvisories/VMSA-2026-0009--VMware-vCenter--Tools--and-SDDC-Manager-updates-address-multiple-vulnerabilities--CVE-2026-123890--CVE-2026-123891--CVE-2026-123892--CVE-2026-123893--CVE-2026-123894-/39495)
  - [Cisco：Security Advisories](https://sec.cloudapps.cisco.com/security/center/publicationListing.x)

## 2. Microsoft Agent Framework PyPI 包遭恶意发布并窃取云与 CI 凭据（扩展至 72 小时）

- **分类**：AI 智能体供应链 / PyPI / CI/CD 凭据泄露
- **严重度**：严重
- **发布日期**：2026-11-17；技术分析集中发布于 11 月 18 日
- **可信度**：多方确认（Microsoft 项目仓库、Elastic、JFrog、Wiz 的样本分析一致）
- **影响对象**：安装过 PyPI `agent-framework==1.26.1` 或 `1.26.2` 的开发者工作站、CI/CD Runner、容器镜像和内部 Python 镜像；.NET 包不在本事件已知影响范围内。
- **发生了什么**：Microsoft Agent Framework 的 PyPI 元包出现两个未授权恶意版本。1.26.1 于 11 月 17 日 20:35 UTC 上线，1.26.2 随后再次上传；两者已从 PyPI 移除，当前安全版本回到 1.26.0。恶意 wheel 添加 `.pth` 文件，Python 每次启动都会自动执行其中的导入逻辑，即使应用从未显式导入 `agent-framework`。研究人员确认载荷会搜集 Azure、Azure DevOps、GitHub Actions 等云与 CI 凭据，并向外部基础设施发送。
- **为什么值得关注**：这是高度相关的 Agent 框架软件供应链事件。元包通常会被自动更新工具、开发环境或流水线快速拉取，而 `.pth` 机制让载荷在解释器启动阶段执行，绕过“没有调用受影响库就不会触发”的常见假设。恶意版本虽然存活时间短，仍可能进入 pip/uv 缓存、内部镜像和构建产物。
- **建议行动**：
  1. 在锁文件、SBOM、pip/uv 缓存、内部镜像、容器层和 CI 日志中搜索 1.26.1 与 1.26.2；不要只检查当前 `pip list`。
  2. 若任一恶意版本曾安装，按主机已失陷处置：隔离并重建环境，轮换可访问的 Azure、Azure DevOps、GitHub、CI/CD、云服务和包发布凭据。
  3. 固定到已确认安全的 1.26.0 或项目后续明确发布的安全版本；清除缓存并重新生成依赖锁和镜像。
  4. 禁止依赖机器人自动合并新包版本；对高权限构建环境实施发布签名、来源证明、哈希锁定和短期凭据。
- **原始来源与补充来源**：
  - [Microsoft Agent Framework GitHub Issue #10411](https://github.com/microsoft/agent-framework/issues/10411)
  - [Elastic Security Labs：agent-framework PyPI compromise](https://www.elastic.co/security-labs/threat-command/we-caught-the-agent-framework-pypi-compromise-six-minutes-after-it-published)
  - [JFrog：Microsoft agent-framework Hijacked on PyPI](https://research.jfrog.com/post/agent-framework-hijack/)
  - [Wiz：Malicious version of Microsoft Agent Framework published to PyPI](https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi)

## 3. AWS：自主 AI 智能体发现并利用 MONAI Label 零日，取得大学服务器 root 权限

- **分类**：自主 AI 智能体攻击 / 零日漏洞 / 医疗影像软件
- **严重度**：严重
- **发布日期**：2026-11-20（攻击活动发生于 2026-09-08 至 09-10）
- **可信度**：原始安全研究；归因置信度另行标注
- **影响对象**：MONAI Label 0.8.5 及更早版本，尤其是默认关闭认证且暴露到不可信网络的实例；大学、医疗影像和 GPU 研究基础设施。
- **发生了什么**：Amazon Threat Intelligence 披露，一个公开暴露且无认证的 Cairn 自主渗透测试平台被威胁行为者用于攻击东亚多所大学。针对运行开源医疗影像 AI 应用 MONAI Label 的目标，智能体识别上传 API 的文件名参数并测试路径遍历，在约 11 分钟内实现任意文件写入；随后把 Python 反向 Shell 写入会在解释器启动时自动导入的 `sitecustomize.py`，再调用训练 API 触发新进程，以 root 权限建立反向连接。项目已发布 GHSA，确认 `PUT /datastore/image` 和标签上传路径存在目录穿越；修复代码已合并，但公告当时尚无包含修复的正式版本。
- **为什么值得关注**：这是从“AI 辅助攻击”跨入“智能体自主发现零日并完成利用链”的具体案例。系统给定“获得 Shell”这一目标后，智能体自行枚举、验证、写入载荷并触发执行，显著压缩了传统披露与防御响应时间。AWS 对中国关联行为者的判断为中等置信度，不能等同于官方归因。
- **建议行动**：
  1. 立即将 MONAI Label 从互联网和不可信网络隔离；启用认证，且不要向不可信用户授予 `ANNOTATOR` 角色。
  2. 以非特权用户运行服务，将写权限限制在数据目录；在正式修复版发布后尽快升级。
  3. 排查异常上传参数、目录穿越字符串、`sitecustomize.py` 变化、训练 API 异常调用和对外反向连接。
  4. 大学与研究机构应自动化响应高置信度扫描与利用信号，因为自主智能体可在人工告警分诊完成前完成攻击链。
- **原始来源与补充来源**：
  - [AWS Security Blog：Chinese-nexus actor’s Cairn AI agents found a zero-day](https://aws.amazon.com/blogs/security/chinese-nexus-actors-cairn-ai-agents-found-a-zero-day-on-their-own/)
  - [MONAI Label GHSA：Path traversal allows arbitrary file write](https://github.com/Project-MONAI/MONAILabel/security/advisories/GHSA-qc22-rmgc-vg94)
  - [GitHub Advisory Database：CVE-2026-133968](https://github.com/advisories/GHSA-2f43-rwqm-6h67)

## 4. Ruby 修复 7 个 Regexp 与字符串大小写转换漏洞，多项已有 RCE PoC（扩展至 72 小时）

- **分类**：语言运行时 / 软件供应链 / 重大安全更新
- **严重度**：严重
- **发布日期**：2026-11-19 UTC
- **可信度**：官方确认
- **影响对象**：Ruby 3.3.13 及更早版本、3.4.0–3.4.12、4.0.0–4.0.9；Ruby 3.2 及更早版本已停止支持且不会获得这些修复。
- **发生了什么**：Ruby 项目披露正则表达式引擎和字符串大小写转换中的 7 个内存安全漏洞，包括堆缓冲区溢出、double free、整数溢出和越界读取。项目明确表示，部分漏洞已有能够在某些场景触发远程代码执行的概念验证，并发布 Ruby 3.3.14、3.4.13 和 4.0.10。受影响面取决于应用是否处理攻击者可控的正则模式或特制字符串。
- **为什么值得关注**：Ruby 广泛用于 Web 应用、自动化、CI/CD 工具和开发平台。运行时级内存漏洞会穿透上层框架边界；即使业务代码没有显式构造复杂正则，依赖库也可能对用户输入做大小写转换或正则编译。EOL 分支不会收到修复，增加了遗留系统风险。
- **建议行动**：
  1. 升级至 Ruby 4.0.10、3.4.13 或 3.3.14；EOL 版本迁移到受支持分支。
  2. 重新构建基础镜像、服务器、CI Runner 和部署包，确认实际运行进程已使用新解释器。
  3. 查找把用户输入作为正则模式、大小写转换数据或模板参数处理的路径，优先验证互联网暴露应用。
  4. 监控 Ruby 进程异常崩溃、堆错误和核心转储；不要把“PoC 尚未公开”视为可延迟修复的理由。
- **原始来源**：
  - [Ruby：Security advisories — Regexp and String case conversion](https://www.ruby-lang.org/en/news/2026/11/18/multiple-vulnerabilities-in-regexp-and-string/)
  - [Ruby 4.0.10 / 3.4.13 / 3.3.14 发布归档](https://www.ruby-lang.org/en/news/2026/11/)
