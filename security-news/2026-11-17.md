## 今日要点

### 1. PLAID 确认 KARTE 服务器漏洞被利用，连接密钥与客户导入数据外泄

- **分类：** SaaS / 供应链凭据 / 重大数据泄露 / 客户数据平台
- **严重度：** 严重
- **发布日期：** 2026-11-16（过去24小时）
- **可信度：** 官方确认（PLAID 事件公告与监管披露）
- **影响对象：** 使用日本客户体验平台 KARTE 的企业、KARTE账户持有人，以及数据被客户导入 KARTE 的终端用户
- **事实摘要：** PLAID 确认，攻击者于11月13日凌晨利用其服务器漏洞，窃取系统和数据库连接凭据，从数据库读取数据，并利用取得的凭据接管公司账户、访问管理控制台。已确认外泄内容包括79,249个KARTE账户邮箱、KARTE与外部服务集成使用的Secret Key和Access Token，以及部分客户通过“关联表”功能导入的数据；后两类记录数量和具体字段仍在调查，导入数据可能包含个人信息。公司已停止KARTE全部服务、使被窃凭据失效并阻断攻击来源，称封锁后未发现新的系统访问，但服务恢复时间仍未确定。
- **值得关注的原因：** 这不只是单一SaaS数据泄露。外泄的集成凭据可能成为进入客户CRM、营销、数据仓库或其他第三方服务的二次攻击通道；导入表的数据结构又由各客户自行决定，最终影响可能跨越多个组织和数据类型。
- **建议行动：**
  1. 所有使用KARTE外部集成的企业应立即在凭据签发方撤销并重新创建Secret Key、Access Token和相关服务账户密钥；仅从KARTE配置中删除密钥不足以使其失效。
  2. 从11月13日前后开始检查集成目标的异常登录、批量读取、配置修改和非预期数据写入，并撤销可疑会话。
  3. 盘点上传至KARTE关联表的字段，按实际数据类型评估通知、监管和身份欺诈风险；不要在官方调查完成前假定只泄露邮箱。
  4. 警惕发送到已泄露邮箱的PLAID/KARTE主题钓鱼，不通过邮件链接输入凭据或验证码。
- **原始链接：**

  - [PLAID 投资者关系公告入口](https://plaid.co.jp/en/ir/news/)

### 2. ScreenConnect 攻击工具尝试从受控终端反向感染技术人员工作站

- **分类：** 远程管理 / MSP供应链 / 在野攻击 / 横向移动
- **严重度：** 严重
- **发布日期：** 2026-11-17（北京时间；ConnectWise 于11月16日20:00 UTC更新）
- **可信度：** 官方确认（ConnectWise Trust Center与安全补丁公告）
- **影响对象：** 启用了指定第三方RMM扩展的ScreenConnect本地部署；运行低于26.6.5版本技术人员客户端的云端与本地部署
- **事实摘要：** ConnectWise 完成对近期ScreenConnect活动的调查，并表示第三方研究人员仍观察到针对未禁用相关扩展、未完成更新的本地部署的攻击。攻击者在取得初始访问后部署工具包，试图从受控客户终端向连接中的技术人员工作站传播；该传播技术会利用CVE-2026-84869相关的客户端文件传输/执行条件。官方验证26.6.5及以上客户端可阻止这种传播方式。研究人员还报告攻击者静默安装额外ScreenConnect客户端、下载后续脚本，以及RMM+ 1.0.31/1.0.32在未配置访问密钥时可能接受空密钥。ConnectWise强调，升级和禁用扩展不能清除已建立的持久化。
- **值得关注的原因：** MSP和远程支持工具天然连接大量客户终端与高权限技术人员设备。“从被管理端反向感染管理端”会颠倒传统信任方向，一台客户终端可能成为进入技术人员工作站乃至更多客户环境的跳板。
- **建议行动：**
  1. 立即禁用并保持禁用 Labtech Plus、RMM Plus、RMM+、RMM Plus Password Link 和 RMM+ Password Link，尤其是ConnectWise无法代为操作的本地部署。
  2. 逐台验证所有技术人员客户端实际运行26.6.5或更高版本；只升级服务器或查看控制台版本不能证明客户端已更新。
  3. 注销活动会话，检查未知ScreenConnect客户端安装、静默下载命令、额外脚本、空访问密钥配置和异常技术人员登录。
  4. 发现可疑活动时用独立EDR/取证工具评估终端，不依赖ScreenConnect自身记录，并轮换远程管理与客户环境凭据。
- **原始链接：**
  - [ConnectWise：ScreenConnect调查与处置更新](https://www.connectwise.com/company/trust/advisories)
  - [ConnectWise：CVE-2026-84869 / ScreenConnect 26.6.5安全补丁](https://www.connectwise.com/company/trust/security-bulletins/2026-09-08-screenconnect-bulletin)

### 3. CERT/CC 披露macOS路径规范化碰撞，影响Terraform、Deno、libarchive与Python打包流程

- **分类：** 软件供应链 / CI/CD / 开发工具 / macOS
- **严重度：** 高
- **发布日期：** 2026-11-16（过去24小时）
- **可信度：** 官方协调披露（CERT/CC；多个项目GHSA与补丁交叉核验）
- **影响对象：** 在macOS APFS/HFS+上处理不可信仓库、压缩包或文件名的CI/CD、打包、归档和运行时环境；涉及HashiCorp go-slug、Deno、libarchive、setuptools及其他采用不一致路径比较的工具
- **事实摘要：** CERT/CC VU#604762指出，多款应用用原始字节比较文件路径，而macOS文件系统会把不同Unicode规范化或大小写折叠形式解析为同一路径。攻击者可使用如“ß”与“ss”等替代拼写绕过排除规则或路径锁，进而覆盖进程有权写入的文件、逃逸Deno读写/执行拒绝列表、让Terraform上传本应被 `.terraformignore` 排除的敏感文件，或把被 `MANIFEST.in` 排除的内容打入Python源码包。协调披露涉及CVE-2026-14978、CVE-2026-49401、CVE-2026-45110和CVE-2026-59890等；CERT/CC明确指出这是应用路径处理缺陷，并非Apple APFS本身的漏洞。
- **值得关注的原因：** 这类缺陷直接击中开发流水线的“安全排除”假设。即使代码审查没有看到 `../` 路径遍历，恶意仓库或压缩包仍可能通过Unicode碰撞包含秘密、覆盖配置或修改后续构建步骤，影响制品完整性。
- **建议行动：**
  1. 更新受影响工具至项目公布的修复版本；已明确的最低版本包括Deno 2.7.14、setuptools 83.0.0和go-slug 0.16.7，libarchive及其他组件按各自厂商公告升级。
  2. 对来自外部仓库、PR、依赖包和归档文件的文件名执行Unicode规范化后再做允许/拒绝比较，并拒绝规范化后碰撞的多路径输入。
  3. 在一次性、低权限、无长期秘密的运行器中处理不可信制品；对Terraform上传内容和Python sdist发布包增加独立秘密扫描。
  4. 检查近期构建中异常Unicode文件名、排除规则失效、受保护文件被覆盖和制品中意外包含的配置/凭据。
- **原始链接：**
  - [CERT/CC VU#604762](https://kb.cert.org/vuls/id/604762)
  - [Deno GHSA-8xpq-cjcf-3wh9](https://github.com/denoland/deno/security/advisories/GHSA-8xpq-cjcf-3wh9)
  - [setuptools GHSA-h35f-9h28-mq5c](https://github.com/pypa/setuptools/security/advisories/GHSA-h35f-9h28-mq5c)
  - [HashiCorp go-slug GHSA-92x3-5h48-mfhx](https://github.com/hashicorp/go-slug/security/advisories/GHSA-92x3-5h48-mfhx)

## 科技产品与商业机密泄露观察

过去24小时内，未发现Apple、OpenAI、Anthropic、Google、Microsoft等公司达到确认门槛的未发布产品资料、源代码、模型参数、内部路线图或员工/供应商商业机密泄露新事件。

KARTE事件确认外泄企业集成凭据和客户导入数据，但PLAID尚未公布其中是否包含具体客户的未发布产品资料或源代码；本简报不把这种可能性写成已确认事实。匿名传闻和无原始证据的泄露主张未收录。

## 结论

本期三项事件分别暴露了SaaS集成密钥、远程管理信任链和文件路径语义三类容易被低估的边界。共同点是：表面上的“一个凭据”“一次远程会话”或“一个文件名”都可能跨越多个客户、工具和流水线。修补版本之外，企业还需要撤销下游凭据、验证所有客户端、检查既有持久化，并对规范化后的真实资源执行安全判断。
