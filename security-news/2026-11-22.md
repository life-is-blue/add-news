## 1. Together AI：Coding Agent 泄露仓库凭据，攻击者下载客户提示词样本

- **分类**：AI Coding Agent / 凭据泄露 / 客户数据泄露
- **严重度**：严重
- **发布日期**：2026-11-21
- **可信度**：官方确认；具体受影响客户与敏感数据范围仍在调查
- **影响对象**：2026 年 6 月和 7 月通过 Together AI Serverless Inference 向 MiniMax M3、GLM-5.2、Kimi K2.6 提交过请求的部分客户，重点涉及 6 月 24 日、7 月 4 日、7 月 8 日和 7 月 14 日的样本。
- **发生了什么**：Together AI 表示，其在常规测试中将经授权收集的提示词样本保存于私有 Hugging Face 仓库。开发公开的 `xorl` 仓库时，一个 AI Coding Agent 将可访问该私有仓库的凭据提交到了公开代码库。自动扫描发现后虽然回滚了提交，但未授权方已取得凭据并下载提示词样本，还在样本中搜索并测试其他服务凭据；其中 5 个被测试的凭据是 Dragos 安全实验的金丝雀凭据。Together AI 称尚未发现本事件之外的额外提示词泄露，正继续审查是否包含个人信息或其他客户数据。
- **为什么值得关注**：这是 Coding Agent 把“生成代码”风险直接转化为真实数据泄露的厂商确认案例。回滚公开提交不能撤销已经被抓取的秘密；一旦训练、测试或推理数据被保存在可由开发凭据访问的仓库，代码助手的误提交就可能跨越开发与客户数据边界。攻击者继续从提示词中寻找二次凭据，也说明提示词泄露可能演变为供应链或横向入侵。
- **建议行动**：
  1. Together AI 客户检查 Azure Service/厂商通知与账户设置；处理敏感提示词的账户启用 Zero Data Retention（ZDR），并联系 `security@together.ai` 确认是否受影响。
  2. 若曾在相关日期提交密钥、令牌、内部 URL、客户记录或专有代码，按可能泄露处理：轮换凭据、审查访问日志，并通知数据所有者。
  3. 对 Coding Agent 实施最小权限、短期或无密钥凭据；将秘密扫描放在本地提交、推送与 PR 三个阶段，且检测后立即吊销而不只是删除提交。
  4. 将客户数据存储与公开开发仓库的执行环境、身份和网络路径隔离，禁止 Agent 自动读取生产样本或长期密钥。
- **原始来源**：
  - [Together AI：Security event — Prompt leakage for requests in June and July of 2026](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026)

## 2. Microsoft Entra Connect Health API 漏洞已被利用，租户元数据遭读取

- **分类**：云身份平台 / 数据泄露 / 已利用漏洞
- **严重度**：高
- **发布日期**：2026-11-21
- **可信度**：官方向受影响客户确认；Microsoft 亦向媒体确认修复和通知
- **影响对象**：收到 Azure Service Health 通知（Tracking ID `YZRN-MK0`）的 Microsoft Entra Connect Health 客户与托管服务提供商。
- **发生了什么**：Microsoft 在 11 月 9 日发现 Entra Connect Health API 漏洞，称该问题自 7 月 23 日引入。公司在 11 月 19 日完成服务端修复，11 月 20 日确认攻击者曾对部分租户进行未授权的只读访问。暴露字段包括技术联系人和管理员邮箱、Tenant ID、显示名、初始域名、地区、Entra 许可层级、目录同步状态及时间戳、Connect Health 接入状态，以及一个已过期且不再使用的旧证书。Microsoft 称未发现配置被修改，也未发现密码、哈希、认证令牌、有效密钥、Azure 订阅信息或本地 Active Directory 拓扑泄露；受影响租户数量和攻击者身份尚未公开。
- **为什么值得关注**：泄露内容虽不包含有效认证秘密，却足以帮助攻击者精准识别高权限管理员、租户域名和混合身份同步状态，从而制作高度可信的钓鱼、帮助台冒充或后续入侵剧本。对于 MSP，单一通知可能对应多个下游租户，影响评估不能只停留在一个组织账户。
- **建议行动**：
  1. 直接登录 Azure Portal 查看 Service Health，不通过邮件链接判断是否受影响；保存通知和时间线用于事件记录。
  2. 提醒全局管理员、技术联系人、SOC 和帮助台警惕引用真实租户信息的钓鱼或身份验证请求。
  3. 为所有高权限角色强制抗钓鱼 MFA，并使用 Privileged Identity Management（PIM）进行按需激活。
  4. 审查 Entra 审计日志、登录日志、Azure Activity Log 和 Connect Health 配置，重点查找 7 月 23 日后异常行为；Microsoft 的只读脚本只能显示当前可返回字段，不能还原历史泄露内容。
- **原始来源与补充来源**：
  - [Microsoft：Azure Service Health 客户通知（受影响租户内可见，Tracking ID YZRN-MK0）](https://portal.azure.com/#view/Microsoft_Azure_Health/AzureHealthBrowseBlade/~/serviceIssues)
  - [Microsoft Learn：Entra Connect 与 Connect Health 安全改进](https://learn.microsoft.com/en-us/entra/identity/hybrid/connect/security-updates-pks)
  - [BleepingComputer：Microsoft Entra Connect Health flaw exploited to steal tenant data](https://www.bleepingcomputer.com/news/security/microsoft-entra-connect-health-flaw-exploited-to-steal-tenant-data/)

## 3. Elecbrakes 联网拖车制动器可被近距离攻击者控制（扩展至 72 小时）

- **分类**：工业控制系统 / 车联网 / 物理安全
- **严重度**：严重（最高 CVSS v3.1 9.6）
- **发布日期**：2026-11-19
- **可信度**：官方确认；未发现已知公开在野利用
- **影响对象**：Elecbrakes EB2 3.0.4.2.0 及更早版本、VM1 早于 1.3.4.2.1 的版本，以及全部 ELBC2000 版本；主要部署于澳大利亚和新西兰。
- **发生了什么**：CISA 发布 ICSA-26-323-02，披露三项漏洞：CVE-2026-124281 可在缺少充分保护的情况下更新固件；CVE-2026-125273 涉及重放或认证绕过；CVE-2026-96805 允许处于蓝牙通信范围内的未认证攻击者注入命令。成功利用可让攻击者控制拖车制动、改变制动条件、修改固件，或关闭制动灯等关键安全功能。Elecbrakes 已为 EB2 发布 3.0.4.4.3、为 VM1 发布 1.3.4.2.1，可通过官方应用升级；旧款 ELBC2000 暂无修复。
- **为什么值得关注**：这是网络漏洞直接影响道路制动的高后果案例。攻击距离受蓝牙范围限制，但车辆停放、维修、车队基地或公开场所都可能提供接近机会；固件修改还可能形成持续风险。遗留型号无补丁意味着资产识别、替换和物理控制与软件升级同等重要。
- **建议行动**：
  1. 通过官方 Elecbrakes 应用把 EB2 升级至 3.0.4.4.3、VM1 升级至 1.3.4.2.1，并核验升级后的设备版本。
  2. 盘点仍在使用的 ELBC2000；在厂商提供修复前评估停用或替换，并加强车辆停放、维修和近距离接触控制。
  3. 在出车前执行制动器和制动灯功能检查；出现异常制动力、未知固件变化或连接行为时，停止使用并保留设备进行取证。
  4. 车队运营方把联网制动控制器纳入 OT/IoT 资产清单、补丁管理和供应商风险流程，而不是仅作为普通车辆配件管理。
- **原始来源**：
  - [CISA：ICSA-26-323-02 — Elecbrakes](https://www.cisa.gov/news-events/ics-advisories/icsa-26-323-02)
