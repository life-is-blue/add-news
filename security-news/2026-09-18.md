今日精选5条。最重要的新风险集中在AI开发工具的信任边界：Plugin4Shell可绕过插件提交哈希锁定，影响Claude Code、Codex、GitHub Copilot和Gemini CLI；另一项授权研究则证明，AI辅助攻击已能把第三方论坛漏洞、会话令牌和开发资源访问串成完整路径。与此同时，Cisco ISE满分漏洞已被确认在野利用，Docker用于隔离Coding Agent的沙箱曾存在主机文件越界访问问题，Gyazo披露了涉及数千万账户与数亿图片元数据的重大泄露。

## 1. Plugin4Shell绕过插件版本锁定，影响四类主流AI编程智能体

- **分类**：Coding Agent、插件与软件供应链安全
- **严重度**：严重
- **发布日期**：2026-09-17（2026-09-18广泛披露）
- **可信度**：初步披露（原始研究；厂商修复状态已部分确认）
- **影响对象**：Claude Code、OpenAI Codex、GitHub Copilot、Gemini CLI用户及插件市场运营方
- **发生了什么**：AIR Security披露名为Plugin4Shell的零点击攻击链。研究显示，这些工具在安装市场中已用提交哈希“锁定”的插件时，没有验证最终取得的代码确实对应目标Git对象；恶意仓库维护者可创建名称仿照提交哈希的分支，使智能体取得并自动安装被替换的代码。研究方称Claude Code 2.1.179和Codex 0.146.0已修复，GitHub Copilot尚无修复，Google表示不会为正在退役的Gemini CLI修补。
- **为什么值得关注**：提交哈希通常被视为不可变供应链锚点。若客户端只把字符串当作可解析引用而不验证对象身份，市场审核和“固定版本”都会失去意义；插件随后以开发者权限运行，可触及代码、密钥、终端和仓库。
- **建议行动**：
  1. 立即升级Claude Code至2.1.179或更高版本、Codex至0.146.0或更高版本。
  2. 对尚未修复的客户端暂停自动安装第三方插件，或仅允许内部镜像和白名单仓库。
  3. 在安装端校验解析后的完整提交OID、签名及内容摘要，而非只信任引用名称。
  4. 审计近期插件安装、更新记录以及插件进程访问过的密钥和仓库令牌。
- **原始来源与补充来源**：
  - [AIR Security：Plugin4Shell原始研究](https://www.air.security/)
  - [The Hacker News：四类AI编程智能体的插件固定版本可被替换](https://thehackernews.com/)
  - [Help Net Security：零点击RCE影响四类主流AI Coding Agent](https://www.helpnetsecurity.com/)

## 2. 授权研究人员借助Claude打通OpenAI账户与开发资源访问路径

- **分类**：AI辅助漏洞利用与开发平台安全
- **严重度**：高
- **发布日期**：2026-09-18
- **可信度**：多方确认（OpenAI赏金处置；FT、Guardian等独立报道）
- **影响对象**：OpenAI社区论坛、ChatGPT/Codex账户、使用第三方论坛或共享身份令牌的开发组织
- **发生了什么**：Hacktron AI研究人员在OpenAI漏洞赏金计划范围内，使用Anthropic Claude及OpenAI模型辅助发现和验证OpenAI社区论坛相关漏洞。攻击链能够劫持认证令牌并访问一名OpenAI员工的ChatGPT账户，还通过GitHub访问证明了对内部开发资源的权限；研究人员提交了无害PR作为证据，没有读取专有源代码。OpenAI支付6,500美元赏金、修复漏洞、收紧权限并撤销相关令牌。
- **为什么值得关注**：这不是一次犯罪入侵，而是受控的授权验证；但它证明小型团队可以借助AI显著压缩从漏洞发现、利用代码生成到跨系统权限验证的时间。第三方社区平台与主产品、代码仓库共享身份或令牌时，外围系统会成为通向核心研发环境的入口。
- **建议行动**：
  1. 隔离论坛、支持平台与生产ChatGPT/Coding Agent身份域，禁止高权限令牌跨系统复用。
  2. 将社区平台、SSO回调和OAuth令牌纳入与核心产品相同等级的攻击面管理。
  3. 对开发平台使用短期、细粒度令牌，并监控异常PR、令牌跨地域使用和会话升级。
- **原始来源与补充来源**：
  - [Financial Times：研究人员使用Anthropic模型验证OpenAI攻击链](https://www.ft.com/content/c4aa118e-a258-48bc-b50e-28e453a95db8)
  - [The Guardian：OpenAI在赏金计划下确认并修复相关漏洞](https://www.theguardian.com/technology/2026/sep/18/openai-hacked-anthropic-claude-chatbot)
  - [The Wall Street Journal：攻击链与内部资源访问范围](https://www.wsj.com/tech/ai/hackers-used-anthropics-claude-to-break-into-openai-b40ba883)

## 3. Cisco ISE认证绕过漏洞被CISA确认在野利用

- **分类**：在野漏洞、身份与网络访问控制
- **严重度**：严重（CVSS 10.0）
- **发布日期**：2026-09-16至17
- **可信度**：官方确认（Cisco公告、CISA KEV）
- **影响对象**：部署Cisco Identity Services Engine（ISE）及相关身份访问控制组件的企业与政府机构
- **发生了什么**：Cisco披露CVE-2026-76460，其API错误使用特权接口，可使未经认证的远程攻击者绕过身份验证并获得未授权访问。CISA随后将其加入已知被利用漏洞目录，确认现实攻击证据。
- **为什么值得关注**：ISE通常位于企业网络准入和身份策略控制平面；成功绕过认证不仅影响单一应用，还可能帮助攻击者操纵访问策略、扩大内网权限或隐藏后续活动。
- **建议行动**：
  1. 按Cisco公告立即升级至修复版本，不要仅依赖外围WAF。
  2. 限制ISE管理/API接口仅允许专用管理网、VPN或跳板机访问。
  3. 排查异常API调用、新增管理账户、策略变化及未知来源的高权限会话。
- **原始来源与补充来源**：
  - [Cisco安全公告：CVE-2026-76460](https://sec.cloudapps.cisco.com/)
  - [CISA Known Exploited Vulnerabilities Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
  - [NIST NVD：CVE-2026-76460](https://nvd.nist.gov/vuln/detail/CVE-2026-76460)

## 4. Docker Sandboxes漏洞可让Coding Agent越出项目目录访问macOS主机文件【72小时扩展】

- **分类**：Coding Agent沙箱与本地主机安全
- **严重度**：严重
- **发布日期**：2026-09-15
- **可信度**：官方确认（Docker安全公告）
- **影响对象**：在macOS上使用Docker Sandboxes 0.28.0至0.42.0之前版本运行AI Coding Agent的开发者
- **发生了什么**：CVE-2026-77179源于Docker Sandboxes所用virtio-fs主机服务的符号链接处理问题。沙箱内恶意代码可越过共享项目目录，以启动虚拟机的宿主账户权限读取或修改macOS其他文件。漏洞已在0.42.0修复；截至披露时没有已知在野利用。
- **为什么值得关注**：Docker Sandboxes的核心价值正是把可能执行不可信代码的Agent限制在项目范围内。该漏洞直接破坏这一安全假设；被提示注入的Agent或其安装的恶意依赖可能接触SSH密钥、云凭据、其他代码仓库和个人文件。
- **建议行动**：
  1. 将Docker Sandboxes升级至0.42.0以上，建议直接使用当前版本。
  2. 对高风险Agent任务使用无主机工作区挂载模式，按需复制文件。
  3. 轮换可能被旧版沙箱读取的开发密钥，并审计异常文件访问和仓库操作。
- **原始来源与补充来源**：
  - [Docker安全公告与更新记录](https://docs.docker.com/security/security-announcements/)
  - [CVE记录：CVE-2026-77179](https://www.cve.org/CVERecord?id=CVE-2026-77179)

## 5. Gyazo泄露约2,362万用户记录及4.9亿条图片元数据【72小时扩展】

- **分类**：重大数据泄露
- **严重度**：高
- **发布日期**：2026-09-16
- **可信度**：官方确认（运营方Helpfeel公告，经安全媒体核验）
- **影响对象**：Gyazo全部用户，尤其是重复使用密码或保存过敏感截图的用户
- **发生了什么**：Gyazo运营方Helpfeel披露，攻击者利用图片上传服务器漏洞执行任意命令并访问数据库。约2,362万条用户记录（包括邮箱和密码哈希）以及约4.9亿条图片元数据受到影响；部分元数据包含构成图片链接的ID，可能导致原本不应公开的图片被访问。公司已暂时禁用部分旧图片访问。
- **为什么值得关注**：截图服务常被用于共享内部控制台、调试信息、票据、身份文件和一次性密钥。即使图片元数据不等同于所有图片内容泄露，可重建链接的ID仍可能把“不可猜测链接”变成可枚举或可访问数据。
- **建议行动**：
  1. 所有Gyazo用户立即更改密码，并同步更换其他服务上的相同或相似密码。
  2. 清理历史敏感截图，轮换截图中曾出现的API密钥、令牌和凭据。
  3. 企业在CASB/DLP与代码扫描中搜索Gyazo链接，评估内部资料外泄范围。
- **原始来源与补充来源**：
  - [The Hacker News：Gyazo泄露规模与攻击路径](https://thehackernews.com/)
  - [Gyazo官方网站](https://gyazo.com/)
