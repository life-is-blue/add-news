## 1. XCPE 后门在 130 万台机顶盒中形成供应链僵尸网络

- **分类**：硬件与固件供应链 / IoT 僵尸网络 / 住宅代理
- **严重度**：严重
- **发布日期**：2026-11-02
- **可信度**：多方确认（Google Threat Intelligence Group、Plume、TrendAI、Lumen、HUMAN Security、Synthient 及日本警察厅联合调查与处置）
- **影响对象**：全球 200 多个国家中使用 Videostrong 生产或供货的 Android TV 机顶盒用户、网络服务商，以及被这些设备代理流量攻击的第三方
- **发生了什么**：Google 与行业伙伴拆除 XCPE 后门及其控制基础设施。该后门被预装在多种品牌和型号的机顶盒固件中，以系统权限运行；即使用户卸载，设备重启后仍可从固件分区自动恢复。Google 高置信度判断 Videostrong Technology 有意开发、部署并运营该网络，通过向犯罪合作方出售设备访问权和下发恶意模块牟利。模块被用于广告欺诈、把家庭网络变成住宅代理、数据外传和继续安装恶意软件。Google 表示，XCPE 直接控制超过 130 万台设备；同时关闭十余个附属恶意软件家族的控制域名，预计还可切断至少 1,000 万台被感染设备的访问链路。Google 已终止与 Videostrong 的合作并禁止其及关联方继续生产带预装 Google 应用的认证设备。
- **为什么值得关注**：恶意代码在设备交付前就进入固件，用户重置或卸载应用无法可靠清除；家庭和企业出口 IP 会被滥用为住宅代理，使攻击流量看似来自可信网络。此事也表明传统兼容性认证不足以发现首启后动态加载、具有多租户商业化能力的供应链后门。
- **建议行动**：
  1. 运营商和企业应以 Google、Plume 等公布的域名、进程名和网络特征排查 Android 机顶盒，重点识别 `x.cpe`、`com.oemservice` 及异常代理流量。
  2. 对无法获得可信固件或厂商安全支持的设备停止使用并更换；仅恢复出厂设置不能消除固件分区中的持久化后门。
  3. 将消费级机顶盒隔离在独立 VLAN，禁止访问企业、办公和管理网络，并限制其出站端口和目的地。
  4. OEM、渠道商和采购方应验证固件构建来源、首启后下载行为、系统权限服务和更新签名，不能只依赖应用层扫描。
  5. 若家庭或企业公网 IP 曾出现代理滥用、广告欺诈或异常登录，应轮换相关会话与凭据，并向网络服务商查询受影响型号。
- **原始来源**：
  - [Google Threat Intelligence：Shutting the Door on the XCPE Botnet](https://cloud.google.com/blog/topics/threat-intelligence/shutting-the-door-on-the-xcpe-botnet/)
  - [Plume Security Labs：How Plume and Google shut down the X.CPE botnet](https://www.plume.com/newsroom/a-letter-to-our-partners)
  - [Trend Micro：Industry Takedown of Botnet Hidden in More Than 1.3 Million TV Set-Top Boxes](https://newsroom.trendmicro.com/2026-11-02-Industry-Takedown-of-Botnet-Hidden-in-More-Than-1-3-Million-TV-Set-Top-Boxes-across-200-Countries)

## 2. Mercado Bitcoin 遭跨链盗币，约 4,900 万美元资产被转走

- **分类**：加密货币平台安全 / 资产盗窃 / 事件响应
- **严重度**：严重
- **发布日期**：2026-11-02
- **可信度**：多方确认（Mercado Bitcoin 确认网络安全事件；Chainalysis 披露链上追踪与冻结结果；具体初始入侵路径仍未公开）
- **影响对象**：Mercado Bitcoin 平台、其热钱包与跨链资产管理流程，以及依赖该平台存取款的客户
- **发生了什么**：11 月 2 日凌晨，攻击者分批从 Mercado Bitcoin 控制的资产中转走约 4,900 万美元，涉及 17 条区块链，主要包括 Bitcoin 和 Ethereum，也覆盖 Base、Tron、Polygon 等网络。平台一度暂停存取款，并表示客户账户和个人数据未受影响。Chainalysis 称其与 Mercado Bitcoin、执法部门、稳定币发行方及行业伙伴协作，已冻结近 1,000 万美元被盗资产；其中最初数小时内冻结约 400 万美元稳定币。攻击者如何取得交易权限、是否涉及私钥、签名基础设施或内部账户，尚未由平台公开。
- **为什么值得关注**：跨 17 条链同时扫取资产说明攻击者可能掌握了比单一钱包更广的控制权限或自动化资产管理入口。冻结稳定币的窗口非常短，事件再次显示交易所必须在分钟级完成链上标记、发行方联络和执法协作；平台恢复服务并不等于签名环境已经恢复可信。
- **建议行动**：
  1. Mercado Bitcoin 客户应仅通过官方状态页确认存取款恢复情况，核对余额、地址白名单、API 密钥和近期会话，警惕冒充赔付或账户验证的钓鱼信息。
  2. 交易平台应隔离并重建受影响的签名与密钥管理环境，轮换 API、云和内部服务凭据，并在恢复前验证钱包生成、交易审批和发布管线完整性。
  3. 将单链和跨链资金转移纳入统一限额、延迟与异常检测；对短时间覆盖多链、多资产的批量转账触发自动冻结和人工复核。
  4. 预先建立与稳定币发行方、链上分析公司、托管机构和执法部门的 24×7 联络机制，并保存可立即共享的地址与交易清单。
  5. 在根因复盘发布前，不把“客户未受损”解释为没有数据或凭据暴露；继续监测后续横向移动、内部账户滥用和勒索信息。

## 3. AWS Serverless MCP Server 路径遍历可把任意 JSON 文件带入 Agent 上下文

- **分类**：MCP / Coding Agent / 路径遍历与本地文件暴露
- **严重度**：中（CVE-2026-116635，CVSS 6.1；启用写入时具有完整性影响）
- **发布日期**：2026-11-02
- **可信度**：官方安全公告（AWS Labs 协调披露并发布修复；未发现已在野利用证据）
- **影响对象**：使用 `awslabs.aws-serverless-mcp-server` 0.2.1 之前版本的开发者和自动化环境，特别是让 Agent 处理不可信项目名称或第三方输入的场景
- **发生了什么**：AWS Serverless MCP Server 的部署状态组件使用项目名称构造文件路径，却未充分限制相对路径和绝对路径。能够影响 MCP Agent 输入的第三方可在项目名称中提供目录遍历片段或绝对路径；若目标以有效 JSON 文件结尾，Agent 会读取目录外文件并把内容带入上下文。若服务器以 `--enable-write` 启动，还可用部署元数据覆盖目录外现有 JSON 文件。受影响版本为 0.2.1 之前，0.2.1 已修复，官方称没有可用的临时绕过方案。
- **为什么值得关注**：漏洞的直接评分为中等，但在 Coding Agent 或自动化部署环境中，JSON 文件可能包含云配置、部署状态、服务账户信息、包管理凭据或项目元数据。文件一旦进入模型上下文，还可能通过日志、外部工具调用或模型服务传出；提示注入能够把“项目名”这类看似低风险字段变成文件读取能力。
- **建议行动**：
  1. 立即升级 `awslabs.aws-serverless-mcp-server` 至 **0.2.1 或更高版本**，并同步修补所有 fork 和派生实现。
  2. 在完成升级前停用该 MCP Server；官方明确表示没有临时绕过方案。
  3. 审查历史 Agent 会话和工具调用中的项目名称，查找 `../`、绝对路径、异常 JSON 文件名及目录外读写痕迹。
  4. 若启用了 `--enable-write`，校验部署状态、云配置和项目 JSON 文件的完整性，并从可信版本库或备份恢复可疑文件。
  5. 将 MCP Server 运行在低权限、最小挂载、无长期秘密的隔离环境中；对不可信文本生成的文件路径实施服务器端规范化和目录边界校验。
- **原始来源**：
  - [AWS Labs GitHub Advisory：GHSA-r6mm-377j-qg8m](https://github.com/awslabs/mcp/security/advisories/GHSA-r6mm-377j-qg8m)
  - [PyPI：awslabs.aws-serverless-mcp-server](https://pypi.org/project/awslabs.aws-serverless-mcp-server/)
