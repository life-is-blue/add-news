## 1. VMware vCenter 认证绕过漏洞 CVE-2026-123890，官方无临时变通方案

- **分类**：重大安全更新 / 虚拟化与云基础设施
- **严重度**：严重（CVSS 3.1：9.8）
- **发布日期**：2026-11-19；2026-11-20 更新
- **可信度**：官方确认
- **影响对象**：VMware vCenter Server，以及使用相关 vCenter 组件的 VMware Cloud Foundation、VMware vSphere Foundation、Telco Cloud Platform/Infrastructure 环境。
- **发生了什么**：Broadcom 在 VMSA-2026-0009 中披露 CVE-2026-123890。漏洞位于 VMware Directory Service，拥有到 vCenter 网络访问路径的攻击者可能绕过认证并获得未经授权的系统访问。通告同时修复 VMware Tools 与 SDDC Manager 的其他漏洞。Broadcom 表示这些问题由私下渠道报告，已发布更新，CVE-2026-123890 没有官方变通方案；截至本简报截稿，厂商未声称存在在野利用。
- **为什么值得关注**：vCenter 是虚拟化环境的高权限控制平面，通常掌握宿主机、虚拟机、模板、备份和管理凭据。认证绕过即使不能直接等同于完全接管，也可能迅速扩大到横向移动、虚拟机操作或敏感配置访问。很多组织还允许备份、监控和运维平台访问 vCenter，暴露面不仅限于管理员工作站。
- **建议行动**：
  1. 按 VMSA-2026-0009 升级所有受影响 vCenter/Cloud Foundation 组件；因无变通方案，不应仅依赖 WAF 或密码轮换。
  2. 在完成升级前，将 vCenter 管理接口限制在专用管理网和跳板机，清理不必要的第三方网络路径。
  3. 审计异常登录、目录服务活动、新增管理员、API 调用、虚拟机快照/导出和 SSO 配置变化。
  4. 检查备份、监控与自动化账户的最小权限，并准备在发现异常时轮换管理凭据和证书。
- **原始来源**：
  - [Broadcom：VMSA-2026-0009](https://support.broadcom.com/web/ecx/support-content-notification/-/external/content/SecurityAdvisories/VMSA-2026-0009--VMware-vCenter--Tools--and-SDDC-Manager-updates-address-multiple-vulnerabilities--CVE-2026-123890--CVE-2026-123891--CVE-2026-123892--CVE-2026-123893--CVE-2026-123894-/39495)
  - [CVE.org：CVE-2026-123890](https://www.cve.org/CVERecord?id=CVE-2026-123890)

## 2. JPMorgan Chase、Visa、Mastercard 确认第三方供应商遭攻击并暴露客户营销数据

- **分类**：重大数据泄露 / 第三方供应链 / 金融行业
- **严重度**：高
- **发布日期**：2026-11-19（北京时间 11 月 20 日）
- **可信度**：多方确认；攻击者声称的完整规模未经独立验证
- **影响对象**：部分 JPMorgan Chase 客户与员工，以及 Visa、Mastercard 特定市场或权益计划中的部分持卡人。
- **发生了什么**：JPMorgan Chase 表示，为其提供服务的第三方遭网络攻击，攻击者访问的营销数据可能包括客户姓名和邮箱，公司将直接通知受影响客户。AP 报道受影响账户为数千个，部分记录包含电话号码。Visa 表示事件涉及亚太地区第三方服务商，其自身系统未受影响，卡号等支付数据不在已知影响范围。Mastercard 表示第三方服务商暴露了少量特定权益计划持卡人的邮箱，不影响支付网络或银行卡使用。三家公司均将此事件与本周早些时候的软件故障/服务中断区分开来。
- **为什么值得关注**：营销和权益运营供应商常持有跨机构、跨地区的客户联系数据，却未必接受与支付处理商同等级别的安全治理。姓名、邮箱、电话和品牌关系足以支持高度可信的钓鱼、客服冒充和账户恢复诈骗，即使卡号没有泄露。
- **建议行动**：
  1. 受通知客户应警惕冒充银行、卡组织或权益计划的邮件、短信和来电，不通过消息内链接登录账户。
  2. 金融机构应盘点营销、会员权益与活动管理供应商的数据字段、保留期限和导出权限，删除非必要副本。
  3. 对受影响数据集建立定向反欺诈规则，监控邮箱/电话变更、账户恢复和异常客服操作。
  4. 将攻击者公布的数据量和所谓完整样本视为未验证主张；以公司通知和监管披露为准。
- **原始来源与补充来源**：
  - [Reuters：JPMorgan, Visa, Mastercard say third-party vendors targeted](https://www.reuters.com/legal/government/jpmorgan-says-third-party-vendors-targeted-cyberattack-2026-11-19/)
  - [Associated Press：A cyberattack leaks thousands of Chase customer emails](https://apnews.com/article/chase-data-leak-cyberattack-8470d475450721b66858bdace47091c0)

## 3. 日本数字厅 GSS 文件共享服务可能泄露政府文件和个人信息

- **分类**：政府数据泄露 / 云与文件共享服务
- **严重度**：高
- **发布日期**：2026-11-20
- **可信度**：官方确认，泄露范围仍在调查
- **影响对象**：使用日本 Government Solution Service（GSS）文件共享服务的政府机构及其外部合作方；相关文件中的个人信息主体。
- **发生了什么**：日本数字厅表示，11 月 12 日发现并非合法共享对象的人员可能访问了 GSS 文件共享服务中的文件。初步调查确认 7 月 30 日至 11 月 12 日期间存在相关访问，数字厅已于 11 月 12 日停止服务并切断外部通信。该服务用于政府机构用户之间及与外部承包商共享会议资料等大文件，因此部分被上传文件可能已泄露，并可能包含个人信息。数字厅已向个人信息保护委员会报告，并与警方及外部专家调查；目前未确认由此造成的二次损害。
- **为什么值得关注**：这是政府共享平台的访问控制事件，潜在暴露持续数月。共享服务往往聚合跨部门资料和外部合作方数据，一旦授权对象判断或共享链接控制失效，影响可能跨越单一系统和单一机构。当前官方仅确认“可能泄露”，尚未公布文件数量、内容敏感级别或根因。
- **建议行动**：
  1. GSS 使用机构和供应商保存 7 月 30 日至 11 月 12 日的共享、下载、登录与通知记录，等待数字厅确认受影响清单。
  2. 复核外部共享对象、链接有效期、下载权限和敏感文件分类；对可能暴露的凭据、密钥或内部地址立即失效和轮换。
  3. 对可能涉及的人员开展定向钓鱼预警，但不要在官方确认前假定所有 GSS 文件均已外泄。
  4. 文件共享平台应实施逐文件可见性、异常批量访问告警、强身份验证和可追溯的外部协作审批。
- **原始来源**：
  - [日本数字厅：GSS 文件共享服务中文件可能泄露的公告（日文）](https://www.digital.go.jp/press/a966ee61-478c-4194-8f13-f97599fae986)

## 4. JetBrains Junie CLI 文件工具可越过项目目录修改本机文件

- **分类**：Coding Agent / 开发终端安全
- **严重度**：高（CVSS 3.1：7.5）
- **发布日期**：2026-11-19
- **可信度**：官方确认
- **影响对象**：JetBrains Junie CLI 26.6.29 之前的版本。
- **发生了什么**：JetBrains 分配的 CVE-2026-133195 显示，Junie CLI 旧版的 Agent 文件工具可以修改项目目录之外的文件。问题在 26.6.29 中修复。CVE 评分向量表明利用复杂度较高且需要用户交互；截至截稿未发现官方确认的在野利用。
- **为什么值得关注**：项目目录通常被视为 Coding Agent 的主要工作边界。若文件工具能越界写入，恶意仓库内容、提示注入或错误的模型操作可能影响 shell 配置、SSH 配置、其他代码库、凭据文件或启动项。风险来自 Agent 工具执行层，而非单纯的模型输出质量。
- **建议行动**：
  1. 将 Junie CLI 升级至 26.6.29 或更高版本，并核实团队镜像、开发容器和 CI runner 中的实际版本。
  2. 在低权限用户、容器或受限工作区运行 Coding Agent，避免让其继承整个主目录和长期有效的云/代码托管凭据。
  3. 对项目外文件写入、shell 配置变化、SSH/Git 凭据访问和新增启动项建立审计。
  4. 将不可信仓库中的说明文件、Issue、测试数据和生成内容视为潜在提示注入输入；高影响文件操作需人工确认。
- **原始来源**：
  - [JetBrains：Fixed security issues](https://www.jetbrains.com/privacy-security/issues-fixed/)
  - [CVE.org：CVE-2026-133195](https://www.cve.org/CVERecord?id=CVE-2026-133195)
