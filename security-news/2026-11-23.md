## 1. OpenRouter 下架3家推理供应商，125个端点失去ZDR资格

- **分类：** AI 推理供应链 / 提示词数据安全 / 第三方风险
- **严重度：** 严重
- **发布日期：** 2026-11-22
- **可信度：** 官方确认；部分供应商和具体受影响规模尚未公开
- **影响对象：** 通过 OpenRouter 使用第三方推理供应商、尤其依赖 Zero Data Retention（ZDR）策略处理敏感提示词的客户。
- **事实摘要：** OpenRouter 表示，Dragos 以约200万条包含唯一链接和金丝雀凭据的提示词测试推理服务后，发现部分供应商存在数据被获取或数据政策未被遵守的证据。OpenRouter 的调查没有发现自身平台遭入侵，但其已下架3家供应商、取消125个端点的ZDR资格，并通知可能受影响的客户。公司正在验证请求和响应的真实网络路径，检查是否被转发给未披露的第三方，并要求供应商通过验证后才能恢复ZDR资格。官方公告列出 Together、Novita、Phala 等供应商事件，但并未公开确认被下架的3家与研究中发现问题的3家完全相同。
- **值得关注的原因：** 模型路由器的“ZDR”承诺依赖整条推理链，而不只是入口平台。请求可能被再次转发、采样或保存在下游环境中，客户看到的合规标签未必等于真实数据路径。提示词内若包含代码、凭据或客户资料，泄露可直接转化为二次入侵。
- **建议行动：**
  1. OpenRouter 客户检查官方通知、活动日志和实际使用端点，确认受影响时间段及提供商。
  2. 对曾发送到失去ZDR资格端点的敏感提示词进行内容审查，轮换其中出现的密钥、令牌和连接字符串。
  3. 对高敏感工作负载固定经过验证的单一供应商或使用隔离部署，不依赖动态最低价路由。
  4. 采购和合规团队要求提供端到端子处理方清单、实际数据路径、保留策略和可验证删除机制。
- **原始来源与补充来源：**
  - [OpenRouter：Data Processing Incidents on Inference Providers](https://openrouter.ai/blog/announcements/data-processing-incidents-on-inference-providers/)
  - [Dragos：Three breaches, endless leaks — Your AI supply chain needs canaries](https://www.dragos.com/blog/three-breaches-endless-leaks-your-ai-supply-chain-needs-canaries)
  - [Together AI：Prompt leakage security event](https://www.together.ai/blog/security-event-prompt-leakage-for-requests-in-june-and-july-of-2026)

## 2. 韩国电力公司确认约152万人敏感个人与金融数据外泄

- **分类：** 重大数据泄露 / 能源关键基础设施 / 个人与金融数据
- **严重度：** 严重
- **发布日期：** 2026-11-22；监管调查于11月23日确认启动
- **可信度：** 官方确认（KEPCO 与韩国个人信息保护委员会）；入侵方式仍在调查
- **影响对象：** 650,487 名 KEPCO ON 客户，以及电子采购系统 SRM 中的 869,761 名企业代表、韩国电力员工和合作企业员工。
- **事实摘要：** 韩国电力公司（KEPCO）确认，外部攻击者从 KEPCO ON 客户服务平台和 SRM 电子采购系统窃取约152万人的资料。KEPCO ON 暴露字段包括姓名、居民或外国人登记号、电话、地址、银行与账户信息、银行卡号及账单数据；SRM 数据包括企业代表身份和联系资料，以及 KEPCO 与合作企业员工的姓名、单位、员工编号和联系方式。公司在收到攻击者邮件并核验样本后阻断外部 IP、暂停相关服务并通知客户。韩国个人信息保护委员会已启动现场和文件调查；根因与攻击路径尚未公布。
- **值得关注的原因：** 数据组合同时包含法定身份证明、银行账户、银行卡和能源账单信息，足以支持身份盗用、精准诈骗和金融欺诈。事件还发生在国有能源企业，采购系统数据可被用于冒充供应商或针对合作企业发动后续攻击。
- **建议行动：**
  1. 收到通知的个人联系银行或发卡机构评估换卡、交易监控和账户保护，不通过短信或邮件中的链接操作。
  2. KEPCO 供应商加强付款指令、账户变更和采购邮件的双渠道核验。
  3. 监控以电费、退款、欠费、采购合同或身份确认名义发送的钓鱼与电话诈骗。
  4. 相关企业检查与 SRM 共用的邮箱、员工编号和身份信息是否被用于密码重置或社交工程。
- **原始来源与补充来源：**
  - [韩联社：KEPCO reports data breach affecting 1.52 million people](https://en.yna.co.kr/view/AEN20261122002700315)
  - [韩国个人信息保护委员会调查报道（ChosunBiz）](https://biz.chosun.com/en/en-it/2026/11/23/LFLR3EWIVRH7TJZBZCURDQ5VBQ/)

## 3. Rackspace Spot 凭据泄露导致 Kubernetes Secret 可被读取（扩展至72小时）

- **分类：** 云平台 / Kubernetes / 凭据泄露 / 软件供应链
- **严重度：** 严重
- **发布日期：** 2026-11-21 至 11月22日公开；攻击发生于11月17日
- **可信度：** Rackspace 向受影响客户确认；公开范围依据客户通知
- **影响对象：** 收到 Rackspace Spot 安全通知的客户组织及其 Kubernetes 集群、自动化工具和关联服务。
- **事实摘要：** Rackspace 表示，未授权方使用泄露凭据访问 Spot 平台部分区域，并在部分客户组织中以合法用户身份创建 Pod、读取 Kubernetes Secret、列出节点和卷。攻击者还可能读取受影响用户持有的 Spot API Token 与刷新令牌。Rackspace 已撤销相关 Token 和会话、删除未授权 Pod、轮换密钥并加强访问控制；公司尚未公开完整受影响客户数量或泄露凭据来源。
- **值得关注的原因：** Kubernetes Secret 往往包含数据库、云服务、代码仓库、容器注册表和第三方 API 的凭据。读取集群 Secret 会把单一云平台事件扩展为多个下游系统的潜在入侵，删除恶意 Pod 并不能撤销已经被复制的秘密。
- **建议行动：**
  1. 受影响客户重新签发 Spot API Token、自动化刷新令牌并下载新的 kubeconfig。
  2. 轮换集群中所有可被读取的 Secret，而不只处理 Rackspace 凭据。
  3. 从11月17日起审查 Pod 创建、Secret 读取、节点/卷枚举和异常出站连接。
  4. 检查数据库、注册表、Git 仓库、对象存储及第三方服务日志，确认被泄露凭据是否已被使用。
- **原始来源：**
  - [BleepingComputer：Rackspace Spot breach exposed Kubernetes secrets](https://www.bleepingcomputer.com/news/security/rackspace-spot-breach-let-hackers-access-customer-kubernetes-secrets/)
  - [Rackspace Spot：Release Notes](https://spot.rackspace.com/docs/changelog)

## 4. Cleverbridge 确认支付卡数据被复制，通知显示包含 CVV/CVC（扩展至72小时）

- **分类：** 支付供应链 / 重大数据泄露 / 电子商务
- **严重度：** 严重
- **发布日期：** 2026-11-22 公开；11月20日开始通知
- **可信度：** 官方确认支付卡数据被复制；具体字段由受影响个人通知补充
- **影响对象：** 通过 Cleverbridge 结账平台向软件或 SaaS 厂商购买产品的部分客户；具体商户和人数尚未公开。
- **事实摘要：** Cleverbridge 表示，其11月4日发现未授权活动并短暂下线系统，后续调查确认第三方复制了平台保存的支付卡数据。公司自11月20日起通知受影响个人，并已联系监管机构、执法部门、卡组织和支付合作伙伴。公开事件页未列出全部字段，但个别通知明确包括卡号、有效期和 CVV/CVC，且称姓名、联系与账单资料未被复制。公司尚未披露攻击入口、驻留时间、影响人数及 CVV 为何可被访问。
- **值得关注的原因：** 卡号、有效期和安全码的组合会带来即时无卡支付欺诈风险。Cleverbridge 为大量软件品牌提供结账与订阅服务，受害者看到的商户品牌可能不同，容易忽视底层支付服务商通知。
- **建议行动：**
  1. 收到通知者立即联系发卡机构，评估换卡并开启实时交易提醒。
  2. 审查11月4日前后的无卡支付和小额测试交易，发现异常立即争议。
  3. 软件厂商核对 Cleverbridge 提供的受影响客户清单，并使用自身可信渠道通知用户，防止事件主题钓鱼。
  4. 支付供应商复核 PCI DSS 下的 CVV 禁止存储、日志和调试数据处理，确认安全码是否进入非预期存储。
- **原始来源与补充来源：**
  - [Cleverbridge：Security Incident Information](https://www.cleverbridge.com/security-incident/)
  - [BleepingComputer：Cleverbridge breach exposed card numbers and CVVs](https://www.bleepingcomputer.com/news/security/cleverbridge-warns-hackers-stole-credit-card-numbers-cvvs-in-data-breach/)

## 5. GL.iNet 云管理漏洞被利用，路由器与 KVM 设备被植入恶意软件（扩展至72小时）

- **分类：** 在野利用 / 云远程管理 / 网络设备 / 供应链
- **严重度：** 严重
- **发布日期：** 2026-11-20；官方公告11月21日更新
- **可信度：** 官方确认；完整影响范围仍在调查
- **影响对象：** 使用 GL.iNet GoodCloud 远程管理的部分路由器和 KVM 设备，以及连接到受影响 KVM 的计算机。
- **事实摘要：** GL.iNet 确认，未授权方利用其云远程管理服务漏洞访问部分客户设备并安装恶意软件。公司已修复云端漏洞、对受影响设备采取纠正措施，并表示将直接通知相关客户。官方仍在调查受影响设备范围及攻击是否波及连接到 KVM 的计算机，并准备发布包含额外保护的固件。公开技术分析还发现部分设备上的后门或反向 Shell，但厂商尚未确认所有样本均来自同一攻击链。
- **值得关注的原因：** 云管理平台拥有跨设备控制能力，平台漏洞可跳过客户网络边界直接触达路由器和 KVM。KVM 又连接服务器或工作站的键盘、显示和鼠标通道，设备被接管可能扩大到所管理主机。
- **建议行动：**
  1. 收到通知或怀疑受影响的 KVM 用户按厂商指导执行硬件恢复出厂设置并重新配置，不只重启设备。
  2. 检查连接计算机上的陌生账户、程序、浏览器扩展、启动项和异常网络连接。
  3. 路由器用户安装厂商后续稳定固件，重置云账号密码和 API Token，并复核端口转发、DNS、VPN 与管理员配置。
  4. 企业将云管路由器/KVM 纳入资产、固件和事件响应清单，并限制管理面与生产网络的信任关系。
- **原始来源与补充来源：**
  - [GL.iNet：Security Notice 2026-11-20](https://www.gl-inet.com/en-eu/blogs/blog/glinet-security-notice-2026-11-20)
  - [GL.iNet 官方论坛：Router and KVM Security Incident](https://forum.gl-inet.com/t/gl-inet-security-notice-2026-11-20/73056)
  - [BleepingComputer：GL.iNet cloud flaw exploited to deploy malware](https://www.bleepingcomputer.com/news/security/hackers-exploit-glinet-cloud-flaw-to-infect-routers-kvm-devices/)
