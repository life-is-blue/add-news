### 1. Visual Studio与SSMS Copilot路径校验绕过可被间接提示注入升级为RCE

- **分类：** Coding Agent / MCP / 开发终端安全
- **严重度：** 高（CVE-2026-103572，CVSS 8.8）
- **发布日期：** 2026-10-13
- **可信度：** 官方确认并有原始研究验证（Microsoft补丁、研究人员完整技术披露）
- **影响对象：** 使用Copilot的Visual Studio 2022 17.14早于17.14.42、Visual Studio 2026 18.10早于18.10.4，以及共享易受影响Copilot组件的SQL Server Management Studio环境
- **发生了什么：** Visual Studio与SSMS中的Copilot使用字符串比较保护设置和MCP配置文件，不允许智能体直接修改。研究人员发现，在文件名末尾增加一个点可绕过检查，而Windows写盘时会移除尾随点，最终仍覆盖受保护配置。攻击者可把指令植入仓库、数据库内容或其他Copilot会读取的数据，经间接提示注入诱导智能体写入恶意配置并执行任意命令。Microsoft已在10月安全更新中加入路径规范化修复；公开来源未报告在野利用。
- **为什么值得关注：** 这不是单纯的“模型被诱导说错话”，而是Agent安全确认机制与Windows文件系统语义不一致，使外部不可信内容能够跨越工具权限边界。开发终端通常同时持有源码、数据库、云凭据和发布令牌，失陷后可直接转化为供应链攻击。
- **建议行动：** 将Visual Studio 2022更新至17.14.42或更高版本、Visual Studio 2026更新至18.10.4或更高版本，并更新SSMS。审计近期对`.mcp.json`、`settings*.json`及尾随点/空格文件名的写入，检查Copilot触发的子进程和网络连接。限制Coding Agent修改配置、执行命令及读取密钥目录，来自仓库、Issue、数据库和网页的内容一律按不可信输入处理。
- **原始来源与补充来源：**
  - [Microsoft：CVE-2026-103572](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-103572)
  - [Embrace The Red：Visual Studio Copilot与SSMS RCE原始研究](https://embracethered.com/blog/posts/2026/visual-studio-copilot-remote-code-execution/)
  - [NVD：CVE-2026-103572](https://nvd.nist.gov/vuln/detail/CVE-2026-103572)

### 2. Ivanti Connect Secure零日已遭有限在野利用，可未认证执行任意命令

- **分类：** 在野利用 / 边界设备 / 远程访问
- **严重度：** 高（CVE-2026-104935，CVSS 8.6；CISA KEV）
- **发布日期：** 2026-10-13
- **可信度：** 官方确认（Ivanti确认有限利用，CISA列入KEV，NHS与MS-ISAC发布预警）
- **影响对象：** Ivanti Connect Secure 25.1.1.1及更早版本、25.1.2.2及更早版本、22.8R2.4及更早版本中的受影响分支；具体例外与目标版本须按厂商矩阵核对
- **发生了什么：** CVE-2026-104935是身份伪造导致的认证绕过，远程未认证攻击者可在低复杂度、无需用户交互的情况下于Connect Secure设备执行任意命令。Ivanti在披露时已掌握有限在野利用，并正直接协助受害组织；CISA随后将其列入已知被利用漏洞目录。边界VPN一旦被接管，攻击者可窃取会话与凭据、建立持久化并进入内网。
- **为什么值得关注：** Connect Secure位于组织身份入口和网络边界，传统EDR往往无法完整覆盖设备本身。修补只能关闭入口，不能自动移除修补前植入的WebShell、账户或会话；此前同类Ivanti事件也显示，攻击者会长期利用边界设备作为隐蔽落点。
- **建议行动：** 立即按Ivanti公告升级至对应修复版本，并优先隔离无法及时修补的公网设备。运行厂商完整性检查工具，审查管理员变更、异常会话、计划任务、文件系统与外联；发现异常时不要仅原地升级，应按厂商流程重置或重建设备。轮换设备管理员、LDAP/RADIUS、SAML、API及可能经设备暴露的下游凭据，并终止现有远程访问会话。

### 3. Windows Shell零日绕过Mark of the Web，Microsoft确认已遭在野利用

- **分类：** 在野漏洞 / 终端安全 / 社会工程
- **严重度：** 高（CVE-2026-96951，CVSS 8.8）
- **发布日期：** 2026-10-13
- **可信度：** 官方确认（Microsoft标记“Exploitation Detected”，10月安全更新已修复）
- **影响对象：** 未安装2026年10月安全更新的受支持Windows终端和服务器；通过邮件、浏览器、聊天或压缩包接收外部文件的用户风险更高
- **发生了什么：** Microsoft修复Windows Shell中的命令注入/安全功能绕过漏洞CVE-2026-96951。攻击者可构造恶意文件或诱导用户访问攻击者控制的内容，使Windows未正确应用Mark of the Web，从而绕过“此文件来自互联网”等安全警告及相关保护。利用仍需要用户打开文件或访问恶意内容，但Microsoft已确认攻击发生在野外。
- **为什么值得关注：** Mark of the Web是Office、SmartScreen及多类终端控制判断外部内容风险的重要信号。绕过后，恶意载荷更容易表现得像本地可信文件，并与脚本、快捷方式、压缩包或后续提权链组合，降低社会工程攻击的可见度。
- **建议行动：** 优先部署2026年10月Windows安全更新，尤其是开发者、财务、人力资源和运维终端。确认邮件网关、浏览器和解压工具不会主动丢弃来源标记；在补丁覆盖前加强对下载目录、临时目录、脚本解释器和`explorer.exe`派生异常进程的监控。对已出现可疑文件执行的设备开展取证，而非只删除载荷。
