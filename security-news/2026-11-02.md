## 1. 欧洲多国超市冷链设备遭网络攻击，联网 OT 风险转化为食品与运营损失

- **分类**：关键基础设施 / 零售冷链 OT / 网络物理攻击
- **严重度**：高
- **发布日期**：2026-11-02
- **可信度**：多方确认（多家零售商、制冷服务商及瑞典国家网络安全中心分别确认事件；攻击者身份、统一入侵路径和总体损失仍未确定）
- **影响对象**：比利时、卢森堡、瑞典和爱沙尼亚的超市门店，以及使用可远程管理冷藏、冷冻和 HVAC 控制器的零售与食品供应链企业
- **发生了什么**：Ahold Delhaize、Colruyt、ICA 和 Coop 报告门店冷藏或冷冻系统在 11 月 2 日凌晨出现异常升温。比利时制冷服务商称，部分设备的蒸发器被切换到除霜模式；瑞典一家 ICA 门店表示温度被设到 50°C。瑞典国家网络安全中心正在调查多起相关事件，并称近期已发现大量暴露且需要更新或修补的 OT 设备。爱沙尼亚亦有供应商确认一家超市的设备被设为 50°C。事件发生在法国数百家超市冷链设备上月遭控制、造成食品损失乃至火灾之后，但目前没有证据确认两批事件由同一攻击者实施。
- **为什么值得关注**：联网制冷设备的失陷不只造成 IT 中断，还会直接破坏食品安全、库存和消防风险控制。相似现象跨多个国家和零售品牌出现，说明远程运维接口、共享供应商或同类设备暴露可能形成系统性风险；在归因和统一入口尚未查明前，不能把它当作单店故障。
- **建议行动**：
  1. 立即盘点互联网可达的冷链、HVAC、楼宇和门店控制器，关闭不必要的公网管理面，并通过受控 VPN、跳板机和强 MFA 限制远程运维。
  2. 与制冷设备及托管服务供应商核对固件、补丁、默认凭据、远程访问账户和第三方维护通道，优先处理已停止支持或无法记录审计日志的设备。
  3. 对除霜模式、温度设定值、控制器重启和批量配置变化建立独立告警；将温度传感器与控制网络分离，避免攻击者同时篡改控制和监测。
  4. 准备手动控制、断网运行、库存转移和食品报废预案，并确保门店人员能在控制平台失效时快速识别异常。
  5. 保留控制器日志、供应商远程会话和网络流量，检查是否存在跨门店的相同账户、IP、命令或时间模式。
- **原始来源**：
  - [Reuters：European supermarkets hit by new fridge cyber attack](https://www.reuters.com/business/retail-consumer/temperature-soars-swedish-grocery-store-freezers-one-store-blames-hackers-2026-11-02/)

## 2. Prefab UI 生成代码可逃逸沙箱并经 MCP 工具读写宿主机

- **分类**：AI 智能体安全 / MCP / 生成代码沙箱逃逸
- **严重度**：严重（CVE-2026-120338，CVSS 10.0；已修复）
- **发布日期**：2026-11-01
- **可信度**：原始安全研究与厂商修复确认（JFrog 技术分析、GitHub 安全公告和修复提交；未发现已在野利用证据）
- **影响对象**：使用 prefab-ui 0.14.0 至 0.20.x、启用 Generative UI、安装 Deno，并允许不可信客户端调用 `generate_prefab_ui` MCP 工具的 FastMCP 服务
- **发生了什么**：Prefab UI 将模型或调用者提供的 Python 代码放入 Pyodide，并在 Deno 子进程中执行，但进程启动时授予了不受限制的文件读取、写入和网络权限，同时把 Deno API 暴露在 JavaScript 全局对象上。Python 可经 Pyodide 的 `js` 代理直接调用 Deno API，读取或修改宿主机文件。研究人员还通过写入虚拟环境的 `.pth` 文件，使后续 Python 进程执行植入代码。FastMCP 的 `GenerativeUI` provider 会把 MCP 工具参数直接传入该沙箱；若服务未配置认证，任何可达客户端均可触发。0.21.0 在接受生成代码前撤销文件和网络权限。
- **为什么值得关注**：该漏洞击穿了“模型生成代码在只读沙箱中运行”的核心信任边界。MCP 工具权限一旦与宿主机权限混合，提示注入、恶意客户端或被污染的上游内容就可能从 UI 生成升级为服务器文件窃取、持久化和远程代码执行。
- **建议行动**：
  1. 将 prefab-ui 升级到 **0.21.0 或更高版本**，并确认运行时实际加载的是修复后的依赖，而非锁文件或镜像缓存中的旧版本。
  2. 升级前停止向不可信客户端注册 `GenerativeUI`，撤下公网可达的 `generate_prefab_ui` 工具，或在网关层实施强认证和细粒度工具授权。
  3. 排查使用 0.14.0–0.20.x 的服务是否读取敏感文件、向异常地址联网，或在虚拟环境 `site-packages` 中出现陌生 `.pth` 文件。
  4. 让生成代码运行在独立低权限容器或微型虚机中，使用只读根文件系统、最小挂载、无默认网络和短生命周期凭据；不要仅依赖语言级沙箱。
  5. 将 MCP 工具输入、调用主体、文件访问和网络请求纳入统一审计，并对模型生成代码执行设置人工批准或策略门控。
- **原始来源**：
  - [JFrog Security Research：CVE-2026-120338 技术分析](https://research.jfrog.com/vulnerabilities/prefab-ui-is-vulnerable-to-remote-code-execution-via-a-pyodide-js-bridge-to-deno-cve-2026-120338-jfsa-2026-001699278/)
  - [PrefectHQ GitHub Security Advisory：GHSA-595q-jv4r-q7j9](https://github.com/PrefectHQ/prefab/security/advisories/GHSA-595q-jv4r-q7j9)
  - [Prefab UI 0.21.0 发布](https://github.com/PrefectHQ/prefab/releases/tag/v0.21.0)

## 3. Beta9 卷路径遍历可暴露 AI 计算 worker 宿主机与其他租户数据

- **分类**：AI 计算平台 / 多租户隔离 / 容器与卷挂载
- **严重度**：严重（CVE-2026-120308，CVSS 9.9；已修复）
- **发布日期**：2026-11-01
- **可信度**：原始安全研究与修复提交确认（JFrog PoC 和项目补丁；PoC 未在生产多租户集群执行，未发现已在野利用证据）
- **影响对象**：自托管 Beta9 gateway 低于 0.1.776 且 worker 低于 0.1.756 的部署，尤其是允许多个工作区运行函数、端点或任务队列的平台
- **发生了什么**：Beta9 在构造卷的宿主机路径时，将共享卷根目录、工作区名称和调用者可控的卷标识直接拼接，却未验证该卷是否归当前工作区所有，也未阻止父目录遍历。持有任意工作区令牌的租户可提交由 `../` 组成的卷标识，使 worker 将宿主机根目录以默认读写方式挂入沙箱。研究 PoC 读取了 worker 的主机名和解析器配置，并显示同一文件系统上可见其他租户卷。修复版 gateway 会验证卷归属和标识，worker 也会在启动旧 stub 时重新检查路径，因此两个组件都必须升级。
- **为什么值得关注**：AI 函数平台通常集中存放模型、数据集、缓存、云凭据和其他租户任务。卷挂载校验缺陷可把单一低权限租户令牌升级为宿主机文件访问，并可能横向读取或篡改同机租户数据；这正是多租户 AI 执行基础设施最关键的隔离边界之一。
- **建议行动**：
  1. 同时升级 Beta9 **gateway 至 0.1.776 或更高版本、worker 至 0.1.756 或更高版本**；只升级一端不足以覆盖旧 gateway 或已保存 stub。
  2. 在升级完成前暂停不可信租户的新部署和卷挂载，限制工作区令牌签发，并尽可能将租户分配到独立 worker 池。
  3. 搜索异常卷标识、包含路径分隔符或父目录片段的 stub、指向宿主机根目录的 bind mount，以及容器内访问 `/etc`、`/root`、`/run` 等路径的记录。
  4. 假设可能暴露的 worker 本地秘密和同机租户凭据需要轮换；检查云实例身份、容器运行时套接字、部署密钥和模型仓库令牌。
  5. 对平台的卷 ID、工作区归属和最终规范化路径实施服务器端校验，并在挂载前确认目标仍位于允许的租户目录内。
- **原始来源**：
  - [JFrog Security Research：CVE-2026-120308 技术分析](https://research.jfrog.com/vulnerabilities/beta9-is-vulnerable-to-host-filesystem-exposure-via-volume-path-traversal-cve-2026-120308/)
