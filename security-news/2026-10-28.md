## 今日要点

- 官方 MCP Python SDK 集中披露三项边界缺陷，分别涉及跨服务令牌混用、跨源重定向泄露自定义凭据，以及由服务端 Schema 触发客户端 SSRF/本地文件探测。
- CISA 将 Brotli/Node2Shell 列入 KEV，意味着此前的“严重但待验证”风险已升级为确认存在在野利用。
- Adobe Commerce 与 Magento 的关键文件上传漏洞也进入 KEV；旧补丁已发布，但仍有实例未完成处置。

## 1. 官方 MCP Python SDK 三项缺陷暴露认证、重定向和 Schema 信任边界

- **分类**：MCP / AI 智能体工具链安全
- **严重度**：高（单项 CVSS 5.9–6.8；组合使用或高权限 Agent 环境中影响上升）
- **发布日期**：2026-10-28（北京时间；CVE/GitHub Advisory 于 10 月 27 日 UTC 发布）
- **可信度**：官方确认（项目安全公告、GitHub Reviewed Advisories 与修复版本）
- **影响对象**：使用 Python 包 `mcp` 1.8/1.10 至 1.29.1、或 2.0.0 至 2.1.1 的 MCP 客户端与服务器；具体受影响起始版本因漏洞而异
- **发生了什么**：
  - **CVE-2026-116684**：服务器端 Bearer 认证默认无法确认令牌是否签发给当前资源服务器。在同一授权服务器为多个服务发令牌、且自定义验证器未校验 `aud` 时，其他服务的有效令牌可能被 MCP 服务器接受。
  - **CVE-2026-116685**：Streamable HTTP、SSE 及 OAuth 客户端请求会跟随跨源重定向，可能把 `X-API-Key` 等自定义标头，以及 307/308 场景中的请求体转发至另一来源。单独的 `Authorization` 标头会由底层库丢弃，不在此泄露范围内。
  - **CVE-2026-116686**：客户端验证服务端提供的工具 `outputSchema` 时，会解析外部 `$ref`。恶意或被攻陷的 MCP 服务器可让客户端从自身网络位置访问 HTTP/HTTPS 地址、探测 `file://` 本地文件，或用无超时的同步请求阻塞整个事件循环。
  - 三项问题均在 **mcp 1.30.0** 与 **2.2.0** 修复；但 CVE-2026-116684 升级后仍需显式启用资源校验并正确返回令牌 audience。
- **为什么值得关注**：MCP 将远端工具描述、认证数据和本地 Agent 运行环境连接在一起。三项缺陷共同说明，不能把“服务器返回的 Schema”“看似正常的重定向”或“由同一身份提供方签发的令牌”自动视为可信。运行在开发机或云内网的 Coding Agent 可能因此暴露 API 密钥、访问内部地址或被阻断。
- **建议行动**：
  1. 将 `mcp` 升级至 1.30.0/2.2.0 或更高版本，并重新构建锁文件、容器和部署产物。
  2. 对服务器端认证启用 `validate_token_resource=True`，设置正确的 `resource_server_url`，并让 `verify_token()` 返回 `AccessToken.resource`；仅升级包并不会自动开启该校验。
  3. 盘点 MCP 客户端是否曾跟随跨域重定向；若目标域不受控，轮换自定义标头、OAuth 客户端密钥及相关 API 凭据。
  4. 限制 Agent 进程访问云元数据、环回和内网地址；只允许本地 `#` 引用的 JSON Schema，阻断外部 `$ref`。
- **原始来源**：
  - [CVE-2026-116684 / GHSA-w4fh-qvv9-3v23](https://github.com/advisories/GHSA-w4fh-qvv9-3v23)
  - [CVE-2026-116685 / GHSA-5h93-6whr-6q8j](https://github.com/advisories/GHSA-5h93-6whr-6q8j)
  - [CVE-2026-116686 / GHSA-rwrf-2pqf-9j8j](https://github.com/advisories/GHSA-rwrf-2pqf-9j8j)
  - [MCP Python SDK 1.30.0](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v1.30.0)
  - [MCP Python SDK 2.2.0](https://github.com/modelcontextprotocol/python-sdk/releases/tag/v2.2.0)

## 2. CISA 确认 Brotli Node2Shell（CVE-2026-111497）存在在野利用

- **分类**：在野漏洞 / 开源基础组件与软件供应链
- **严重度**：严重
- **发布日期**：2026-10-28（北京时间；CISA 于 10 月 27 日加入 KEV）
- **可信度**：官方确认（CISA KEV、上游与生态补丁）
- **影响对象**：使用易受攻击 Brotli 解码器的 Node.js、Python、Bun、Envoy、.NET 及其他 HTTP 客户端/服务器和容器镜像
- **发生了什么**：CISA 将 **CVE-2026-111497** 加入已知被利用漏洞目录。该缺陷源于 Brotli 流式解码器对错误返回值处理不当，可由恶意压缩流触发相邻状态内存破坏，造成崩溃、内存信息泄露，部分环境下可实现远程代码执行。该问题最初从 Node.js 场景暴露，但影响的是被多个生态复用的 Brotli 实现。美国联邦民事机构的处置期限为 11 月 10 日。
- **为什么值得关注**：这是 10 月 24 日已报道“广泛生态影响”的实质状态升级：CISA 已确认在野利用。由于漏洞可能通过传入压缩请求或应用主动抓取的恶意压缩响应触发，资产范围不仅是公开 Web 服务器，也包括爬虫、代理、Webhook 处理器和会主动访问 URL 的 Agent 工具。
- **建议行动**：
  1. 升级至 Google Brotli 1.0.10/1.1.1/1.2.1、Node.js 22.23.4/24.22.1/26.12.1、Python Brotli 1.2.1、brotlicffi 1.2.1.0 或供应商更新版本。
  2. 修补后重启进程，并重建、重新部署包含易受攻击原生库的容器镜像；仅更新宿主机包不足以修复静态或镜像内副本。
  3. 无法立即修补时，在代理层禁用或拒绝不可信的 Brotli 编码流，并限制应用向任意 URL 发起请求。
  4. 检查处理压缩数据的服务是否出现异常崩溃、内存错误、未知子进程或可疑外联。
- **原始来源**：
  - [CISA Known Exploited Vulnerabilities Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
  - [NVD：CVE-2026-111497](https://nvd.nist.gov/vuln/detail/CVE-2026-111497)
  - [BleepingComputer：CISA warns of hackers now exploiting critical Node2Shell flaw](https://www.bleepingcomputer.com/news/security/cisa-warns-of-hackers-now-exploiting-critical-node2shell-flaw/)

## 3. Adobe Commerce 与 Magento 文件上传漏洞进入 CISA KEV

- **分类**：在野漏洞 / 电商与开发平台
- **严重度**：严重（Adobe CVSS 9.6；NVD 9.3）
- **发布日期**：2026-10-28（北京时间；CISA 于 10 月 27 日加入 KEV）
- **可信度**：官方确认（CISA KEV、Adobe 安全公告、NVD）
- **影响对象**：未应用 APSB26-73 修复的 Adobe Commerce、Adobe Commerce B2B、Magento Open Source 与 Adobe Commerce Events
- **发生了什么**：CISA 将 **CVE-2026-48356** 加入 KEV。该漏洞属于危险文件类型的不受限制上传；攻击者无需预先认证，但需要诱使受害者访问恶意 URL 或与被攻陷页面交互，随后可在当前用户上下文执行任意代码，并可能取得更高权限或控制会话。Adobe 已在 APSB26-73 中提供修复，CISA 为美国联邦民事机构设定的处置期限为 11 月 10 日。
- **为什么值得关注**：Commerce/Magento 常连接订单、客户身份、支付外围系统、Webhook 与后台管理员会话。即使漏洞需要用户交互，一旦攻击链针对管理员或高权限运营人员，后果可扩展至代码执行、客户数据访问和支付页面篡改。
- **建议行动**：
  1. 依照 APSB26-73 核对具体产品线和版本，立即部署 Adobe 对应补丁或更新至供应商标记的安全版本。
  2. 搜索异常上传文件、可执行脚本、新增管理员、未知集成/Webhook、内容安全策略变化和支付页面代码修改。
  3. 强制后台管理员重新认证，轮换高权限会话及集成凭据，并限制管理端从公网直接访问。
  4. 对补丁前暴露的站点进行入侵排查，不把“已升级”视为已排除历史失陷。
- **原始来源**：
  - [Adobe：APSB26-73 Security update available for Adobe Commerce](https://www.adobe.com/trust/security/products/commerce/apsb26-73)
  - [CISA Known Exploited Vulnerabilities Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
  - [NVD：CVE-2026-48356](https://nvd.nist.gov/vuln/detail/CVE-2026-48356)
