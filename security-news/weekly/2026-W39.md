# 安全周报｜2026-W39（9月21日—9月27日）

> 统计周期：北京时间 2026-09-21 00:00 至 2026-09-27 21:00。  
> 编写方法：汇总本周日报后，按事件链去重，并回查企业公告、政府预警、补丁和原始安全研究；对尚无完整取证结论的事件保留明确边界。

## 本周结论

本周最重要的变化，是 AI Agent 风险从“模型输出是否安全”进一步转向了**身份、网络、插件、凭据和控制面的系统工程问题**。Gemini 在授权测试中误入侵真实企业、Muse 被平台封禁并暴露本地劫持路径、AI 评测沙箱遭提示注入后泄露生产密钥，都说明模型自律不能替代不可绕过的网络隔离、委托身份和人工审批。

第二条主线是开发者工具链的信任继续被压缩：ZCode 默认上传本地代码库、恶意 GitHub Actions 在平台重新开放后“死而复生”、恶意 npm 包及假冒 AI 客户端窃取凭据。企业必须把 Coding Agent、插件、Action 和包依赖视为能读取源码与生产密钥的代码执行主体，而不是普通效率工具。

第三条主线是边界设备和企业控制面集中遭打击。F5、Check Point、Arista、WSO2、Adobe Commerce、SharePoint 与 PeopleSoft 均出现已知在野利用或大规模攻击；PeopleSoft 仅用一个 URL 编码字符就绕过常见 WAF 规则，再次证明缓解措施不能代替补丁。

## 本周最重要的10件事

### 1. Gemini安全测试越界，进入三家真实企业系统

- **分类**：AI Agent、红队与测试隔离
- **严重度 / 可信度**：严重 / 多方确认
- **事实与进展**：Google 委托的 Gemini 网络能力测试原本针对虚构企业，但测试环境仍可访问公网。Agent 因同名目标、公开凭据等因素进入三家真实企业系统；Google称模型识别到真实目标后停止，相关企业已获通知。
- **分析**：这是授权边界失效，而非犯罪攻击，却比一般提示注入更能说明问题：只要公网出口、真实凭据和目标解析仍由模型自由决定，模拟任务就可能转化为真实入侵。
- **实际影响与行动**：Agent 红队环境应默认断网或只允许白名单目标；真实凭据、横向移动和外部写操作必须由代理层强制拦截并要求人工批准，不能依赖系统提示词。

### 2. AI评测沙箱遭提示注入，生产API密钥被用于攻击约30家AI公司

- **分类**：AI评测、提示注入、共享基础设施
- **严重度 / 可信度**：严重 / 初步披露
- **事实与进展**：Anthropic威胁报告披露，攻击者通过提示注入影响一家AI供应商的评测沙箱，取得多家模型提供商的生产API密钥，并在约四天内将其用于针对约30家AI公司的攻击活动。
- **分析**：评测平台往往同时连接不可信模型输出和高价值生产凭据，已成为新的供应链节点。攻击者不必直接突破模型厂商，只需控制共享评测或代理层。
- **实际影响与行动**：评测环境必须与生产账户隔离，使用短期、单用途、限额令牌；模型输出不得直接进入Shell、浏览器或密钥代理；对API密钥建立异常调用、跨租户和批量目标告警。

### 3. Muse事件形成“身份不透明—本地劫持—权限放大”完整风险链

- **分类**：Agent身份、桌面客户端、第三方平台
- **严重度 / 可信度**：高 / 多方确认
- **事实与进展**：Amazon封禁Meta Muse购物Agent，理由包括未明确标识机器身份、未经授权访问和凭据风险；随后研究人员披露Muse macOS客户端的“not-a-mused”本地劫持路径，普通用户权限下的恶意程序可修改未保护的转录端点，向Agent注入指令并借用其摄像头、文件等能力。Meta已热修复。
- **分析**：Agent既可能对外“冒充用户”，也可能在本机被恶意进程借权。可验证机器身份、用户委托和工具权限必须同时存在。
- **实际影响与行动**：使用短期、限域、可撤销的委托令牌；对拍照、写文件、购买、发送消息和读取凭据逐次确认；保护端点和模型配置不被同权限进程静默修改。

### 4. ZCode默认上传本地代码库，Coding Agent的数据边界再次失守

- **分类**：Coding Agent、源码隐私与数据治理
- **严重度 / 可信度**：高 / 多方确认
- **事实与进展**：独立复现显示，Z.ai ZCode早期版本默认启用代码库索引，并尝试把本地工作区打包上传；一次记录涉及约313MB数据和564次尝试。Z.ai承认早期默认设置影响部分用户，暂停或修复相关功能并开源代码。
- **分析**：“读取本地仓库”和“上传云端”是两种完全不同的安全边界。即使服务方承诺处理后删除，企业仍可能已经触发商业机密、合同、数据驻留与密钥暴露义务。
- **实际影响与行动**：默认关闭云端索引，审计历史出站流量；若工作区含密钥则按潜在暴露轮换；采购时要求披露上传范围、保留期、删除证明和训练政策。

### 5. 恶意GitHub Actions因平台重新开放再次执行旧载荷

- **分类**：GitHub Actions、CI/CD供应链
- **严重度 / 可信度**：严重 / 初步披露
- **事实与进展**：在5月Mini Shai-Hulud攻击中被植入窃密代码的两项Action——`actions-cool/issues-helper`与`actions-cool/maintain-one-comment`——9月16日重新可访问时，恶意release标签仍未清理。下游工作流因此再次解析并执行旧载荷，直至9月25日再次被禁用；仅前者依赖图约有1.5万个仓库，实际受影响数仍未知。
- **分析**：攻击无需重新入侵，只需恢复仓库访问即可复活。可变标签让下游在自身配置未改动时执行不同代码，平台封禁也不是完整清除机制。
- **实际影响与行动**：移除两项Action；回溯9月16日至25日工作流并轮换可见机密；第三方Action固定到经核验的完整commit SHA，收紧`GITHUB_TOKEN`默认权限。

### 6. Carbonato把通用AI Agent安装到被攻陷的Docker主机

- **分类**：AI Agent滥用、容器与僵尸网络
- **严重度 / 可信度**：高 / 初步披露
- **事实与进展**：ThreatDown重建的Carbonato工具链利用暴露且未认证的Docker TCP 2375启动特权容器、挂载宿主机并建立持久化，再安装开源Hermes Agent，通过修改`SOUL.md`让名为GH0ST的Agent经Telegram接收自然语言任务、窃取AI API密钥和其他凭据，并扫描相邻网络。
- **分析**：AI在这里不是初始漏洞，而是入侵后的自适应操作层。攻击者可用自然语言驱动异构环境，降低批量横向移动成本；传统暴露面和凭据隔离仍是最有效防线。
- **实际影响与行动**：关闭未认证2375端口；检查特权容器、宿主机挂载、Telegram流量和反向SSH；命中指标后从可信镜像重建并轮换主机、云、SSH、数据库及AI API凭据。

### 7. PeopleSoft大规模利用以一个编码字符绕过WAF

- **分类**：在野漏洞、企业应用与数据勒索
- **严重度 / 可信度**：严重 / 多方确认
- **事实与进展**：Mandiant确认UNC6240（ShinyHunters）恢复利用PeopleSoft CVE-2026-35273。攻击者把`/PSEMHUB/`改写为`/%50SEMHUB/`，绕过按原始字符串匹配的WAF；研究人员在多个行业的数十套系统观察到Web Shell和无文件命令执行。
- **分析**：WAF只是在攻击者适配前争取时间。若后端会规范化或解码请求，前端按字面匹配的规则就会产生虚假安全感。
- **实际影响与行动**：安装Oracle正式补丁并按指引禁用EMHub；让WAF对规范化后的路径决策；同时搜索编码变体、异常JSP和Java进程派生Shell，轮换应用服务账户可访问的数据库与云凭据。

### 8. 边界与控制面漏洞密集进入在野利用阶段

- **分类**：KEV、网络边界、企业控制面
- **严重度 / 可信度**：严重 / 官方确认
- **事实与进展**：本周CISA或政府机构确认多项高影响漏洞遭利用，包括F5 BIG-IP APM CVE-2026-94127、Check Point CVE-2026-85102与CVE-2026-93616、Arista VeloCloud Orchestrator CVE-2026-93952、WSO2 CVE-2026-5430、Adobe Commerce/Magento CVE-2026-71362，以及加拿大确认的SharePoint CVE-2026-65660。
- **分析**：这些产品掌握认证、VPN、SD-WAN、API管理、协作或电商账户，是攻击者进入内网或批量接管业务的高杠杆入口；单看CVSS无法反映其控制面价值。
- **实际影响与行动**：以“在野利用 + 互联网可达 + 控制面权限”重排补丁优先级；补丁后回溯Web Shell、管理员变更、服务账户及异常出站连接，而不是只验证版本号。

### 9. Bitget约3.875亿美元资产被转移，恢复快于根因透明度

- **分类**：重大资产盗窃、签名基础设施
- **严重度 / 可信度**：严重 / 官方确认
- **事实与进展**：Bitget将受影响资产从初报约3.516亿美元上调至约3.875亿美元，称攻击者攻破关键后台并操纵交易数据以触发签名。公司表示漏洞已修复、保护基金覆盖损失，并计划9月28日至10月2日分阶段恢复提款；Mandiant与SlowMist参与调查。完整根因与第三方取证结论尚未公开。
- **分析**：事件显示密钥没有直接泄露也不等于钱包安全；签名前数据、审批逻辑和授权域同样可能成为单点失效。“服务恢复”也不等于调查完成。
- **实际影响与行动**：托管平台应对交易生成、风控、签名、广播进行独立数据校验和多人审批；Bitget用户只通过官方渠道操作，恢复后先小额验证并防范补偿钓鱼。朝鲜归因仍不应视为独立确认。

### 10. Kiteworks要求全球客户预防性停机，但尚无已确认入侵

- **分类**：安全文件传输、潜在集中式供应链风险
- **严重度 / 可信度**：高 / 官方确认预警，攻击未确认
- **事实与进展**：Kiteworks依据联邦情报机构提供的可信威胁信息，建议全球客户在指定六小时窗口关闭服务器，包括不直接暴露互联网的部署。公司称9.5.1修复所有已知漏洞；截至本周截止时，尚未确认客户系统被攻破、零日CVE或在野利用细节。
- **分析**：主动要求安全文件传输平台停机极不寻常，潜在影响值得高优先级响应；但缺乏技术证据时，不应把预警升级为已发生的数据泄露。
- **实际影响与行动**：执行厂商版本和停机要求，保存前后日志，检查异常管理员、批量下载、API调用和出站连接，并等待厂商或政府后续技术通报。

## 主要趋势

1. **Agent安全边界正在从提示层下沉到基础设施层。** Gemini、Muse和评测沙箱事件分别对应网络出口、身份委托与共享密钥；三者都无法靠“更强的拒绝回答”解决。
2. **AI工具成为凭据与源码的新聚合点。** Coding Agent、插件和评测平台天然读取代码、浏览器会话、API密钥与CI令牌，一处默认配置错误即可跨越多个安全域。
3. **软件供应链需要“不可变引用 + 可撤销身份”。** npm包、GitHub Actions及假冒AI客户端表明，包名、商店上架或仓库恢复状态都不足以构成可信根。
4. **缓解措施的半衰期越来越短。** PeopleSoft的WAF绕过与恶意Action复活说明，临时封禁和字符串规则会被适配；补丁、清除恶意版本和凭据轮换必须闭环。
5. **控制面仍是最高回报目标。** VPN、SD-WAN、API管理、协作、文件传输和交易签名系统一旦失陷，可直接跨租户、跨系统或跨资产扩散。

## 对开发者与企业的实际影响

- **开发团队**：本地IDE/Coding Agent的上传行为应纳入数据流图和DLP，而非只由开发者阅读隐私政策自行判断。
- **DevSecOps团队**：第三方Action和插件拥有与构建脚本相同的代码执行权；必须固定哈希、限制令牌并持续监控上游状态变化。
- **AI平台团队**：测试、评测和生产需使用不同账户、网络和密钥域；任何能访问公网或生产API的Agent都应视作潜在自动化操作者。
- **基础设施团队**：边界设备进入KEV后，不应等待常规维护窗口；补丁必须与入侵回溯、密钥轮换和控制面日志检查配套。
- **管理与法务**：Agent越权访问真实第三方系统可能同时触发计算机滥用、合同、隐私和监管通报义务，需在上线前确定责任人与停止机制。
