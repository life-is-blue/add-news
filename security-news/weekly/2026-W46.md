> **统计周期：** 2026-11-09—2026-11-15（北京时间，ISO 第46周）  
> **资料范围：** 已读取本周仓库内11月9日至13日及15日的日报；11月14日无独立日报，相关时段由11月15日报扩展至72小时补查。周报另回查厂商公告、CISA KEV、监管文件及本周后续更新。

## 一周结论

本周最重要的变化不是某个单独零日，而是 **AI/开发基础设施的多个信任层同时暴露**：供应商访问密钥可打开训练数据桶，Agent 会话中残留的秘密可成为横向移动起点，MCP 网关可能错误转换身份与凭据，不可信仓库配置可在“只读分析”阶段执行命令，扩展市场缓存则可能把一次内部凭据失陷放大到终端用户。

传统安全风险同样没有退场。Chrome、Outlook、邮件网关、防火墙和通信服务器均出现已在野利用漏洞；大型金融、政府、物流、半导体和公用事业机构则分别暴露出身份数据、第三方云、并购遗留系统和业务IT韧性问题。

### 1. Fireworks AI 事件升级为 Cursor 数据访问与 Claude Code 扩展投毒的完整供应链攻击链

- **严重度：** 严重
- **状态：** 官方确认；Cursor称事件已遏制，最后观察到的攻击活动发生于11月1日
- **核心事实：** Fireworks AI 于11月9日确认，有限客户的秘密、数据集及部分未完成模型权重遭访问。Cursor 于11月13日进一步披露：攻击者取得 Cursor 发给 Fireworks 的访问密钥，从共享存储桶复制非隐私模式 Coding Agent 历史轨迹；其中未脱敏凭据影响不到0.01%的客户，随后被用于进入部分 Cursor SaaS，访问归档非生产源代码、支持数据和会话摘要。10月29日，攻击者又利用取得的内部凭据向 Cursor 扩展市场缓存投放恶意 `Anthropic.claude-code` 2.1.312/2.1.313，最多约5,000名请求特定缓存版本的用户可能收到恶意构建。
- **边界说明：** Cursor 明确表示，Anthropic 没有发布恶意版本，这不是 Claude Code 产品漏洞；Open VSX、Cursor 正式发布系统、生产代码仓库和签名密钥未被确认遭入侵。
- **分析：** 事件把“AI供应商密钥—Agent轨迹—残留秘密—内部SaaS—插件缓存—开发者终端”连成一条真实攻击链。Agent 对话和训练轨迹不能再被视为低敏感日志。
- **行动：** 排查受影响 Claude Code 版本并执行官方 IOC/清理脚本；从干净设备轮换会话、工单和轨迹中出现过的凭据；对第三方推理/训练数据集实施期限、网络位置和客户级访问限制；为插件镜像与缓存增加端到端签名和来源验证。

### 2. MCP 安全问题从单点漏洞变为“身份、策略、仓库与网络出口”系统性失效

- **严重度：** 高至严重
- **状态：** 多家项目和厂商官方确认；未见这些具体漏洞被官方确认在野利用
- **核心事实：**
  - `fast-agent-mcp <=0.7.20` 的服务默认监听所有网卡且无认证，配合 `--shell` 可形成远程命令执行；0.7.21修复。
  - AWS API MCP Server 0.2.13—1.5.0 的操作名规范化错误可绕过 `denyList` / `elicitList`；1.5.1修复。
  - 官方 `mcp-server-git <2026.11.11` 可因恶意仓库的 `core.fsmonitor`、钩子、过滤器等配置，在看似只读的 Git 操作中执行命令。
  - AWS MCP Gateway Registry 出现低权限管理员提权和内网 SSRF；升级后仍需清理旧版写入的恶意组映射与上游地址。
  - IBM ContextForge MCP Gateway 出现上游凭据覆盖、身份信息错误传播、令牌缓存授权绕过和动态客户端注册 SSRF；高风险项需升级至1.1.1。
- **分析：** MCP 网关不只是“连接器”，而是身份代理、秘密托管者、策略执行点和网络出口。模型是否拒绝危险请求，与网关能否强制绑定调用者、凭据、目标和工具权限是两回事。
- **行动：** 把 MCP 服务纳入互联网暴露面扫描；默认仅绑定回环或管理网络；对每个工具使用独立短期身份；由 IAM、网络出口和审批系统强制权限，不依赖 denyList；在一次性无凭据沙箱中分析外部仓库。

### 3. GPUStack 认证绕过已被实际利用，可接管AI推理控制面和工作节点

- **严重度：** 严重（CVSS 9.8）
- **状态：** 项目公告与CISA KEV确认在野利用
- **核心事实：** CVE-2026-102895 将来源看似为回环地址的请求错误视为管理员。反向代理可能让所有外部请求都呈现为 `127.0.0.1`，攻击者还可伪造相关 Header。利用后可读取工作节点及云/模型供应商秘密、创建长期管理员密钥，并通过自定义推理后端在工作节点执行代码。2.2.0已修复，项目确认攻击者曾针对2.1.1创建自定义后端并运行反向 Shell。
- **分析：** AI推理控制面通常同时掌握GPU节点、模型仓库和云凭据；一次认证绕过可能同时造成控制面、数据面与计算节点失陷。
- **行动：** 立即升级至2.2.0以上；删除客户端提供的真实IP Header，只信任经过认证的代理；排查未知管理员密钥、自定义后端和反向Shell；轮换集群令牌、云密钥和模型供应商API密钥。
- **来源：**
  - [GPUStack 官方公告](https://github.com/gpustack/gpustack/security/advisories/GHSA-gj9m-f8ph-pmhr)
  - [CISA KEV 查询](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-102895)

## 主要趋势

### 1. Agent数据本身已成为凭据与供应链资产

Coding Agent轨迹、支持工单、评测环境变量和数据集可能同时包含代码、秘密、客户上下文与模型制品。安全控制不能只覆盖代码仓库，还必须覆盖会话存储、离线分析桶、支持系统和供应商共享数据。

### 2. MCP风险的核心是强制边界，而非模型行为

本周漏洞横跨默认网络监听、缺失认证、策略匹配、身份传播、凭据覆盖、缓存键、SSRF和仓库配置执行。共同结论是：模型拒绝、提示词规则和denyList都不能替代IAM、网络隔离、独立服务身份及不可绕过的审批。

### 3. “已打补丁”与“已完成处置”不是同一件事

恶意npm包、GPUStack、Barracuda、Check Point和Claude Code恶意扩展都可能在修复前建立持久化或泄露凭据。补丁之后仍需取证、重建、轮换和验证。

### 4. 关键业务影响常发生在核心生产系统之外

Stadtwerke Achim的能源供应未中断，但计量、结算和付款受阻；TSMC、Maersk和直布罗陀政府的事件也集中在供应商云、遗留系统或协作平台。资产分级必须同时考虑数据、身份和业务流程依赖。

## 对开发者与企业的实际影响

- **开发者终端：** 依赖安装、仓库分析和IDE扩展都可能在“编译之前”执行攻击者代码；工作站不应长期保存发布和生产凭据。
- **CI/CD：** 锁定版本、禁用非必要安装脚本、使用一次性运行器与短期令牌，优先级高于仅增加依赖扫描。
- **AI平台团队：** 为每个Agent、MCP Server和上游工具建立独立身份；会话与评测数据默认视为敏感日志并执行秘密扫描。
- **企业安全团队：** KEV资产需要“修补+取证”双轨处置；浏览器和邮件客户端补丁必须核查实际生效版本与重启状态。
- **采购与治理：** AI供应商、云供应商和并购遗留系统应纳入同一第三方数据流图，合同中明确数据保留、事件通报和客户级隔离要求。
- **关键基础设施：** 除OT隔离外，应演练企业IT失陷时的计量、结算、支付和公众沟通流程。
