# 每周安全周报｜2026-W47

> **周期：** 2026-11-16 至 2026-11-22（北京时间，ISO 第 47 周）  
> **方法：** 先复核本周七份日报，再核查厂商公告、CISA KEV/ICS、CVE/GHSA、项目发布页和后续进展。同一攻击链或同类控制缺陷合并分析，不把匿名归因、攻击者自报规模或未证实产品传闻写成事实。

## 本周判断

本周最值得关注的变化不是某个单一 CVE，而是**AI Agent 已同时出现在攻击者、开发者和基础设施三个位置**：

1. 攻击者用自主智能体在真实入侵中发现并利用零日；
2. 开发者使用的 Coding Agent 将长期凭据提交到公开仓库，造成客户提示词样本被下载；
3. Agent 框架、MCP Server 和 Coding Agent 文件工具自身成为供应链、远程调用和越界写入的攻击面。

传统安全问题并未因此消失。相反，Agent 通常连接代码、云凭据、模型 API、文件系统和执行工具，使软件包投毒、凭据泄露、路径边界错误与高权限控制面漏洞的后果被进一步放大。

## 本周最重要的 10 件事

### 1. Microsoft Agent Framework 的 PyPI 元包遭恶意发布

11 月 17 日，`agent-framework==1.26.1` 与 `1.26.2` 被未授权上传到 PyPI。恶意 wheel 通过 Python `.pth` 启动机制，在解释器每次启动时执行凭据窃取代码，即使应用没有显式导入该包。样本分析显示目标包括 Azure、Azure DevOps、GitHub Actions 等云与 CI 凭据。两个版本已从 PyPI 移除，当前公开安全版本回到 1.26.0，但缓存、内部镜像、锁文件和旧构建产物仍可能保留恶意制品；截至截稿，上传凭据如何失守尚无 Microsoft 最终说明。

**影响判断：** 这是本周最典型的“Agent 生态供应链”事件。元包、自动更新和高权限 CI 环境的组合，使短时恶意发布也可能产生长期残留。仅卸载包不足以完成处置，安装过的主机应按可能失陷处理。

**立即行动：** 搜索 1.26.1/1.26.2、清理缓存与内部镜像、重建环境并轮换可访问凭据；固定哈希和版本，要求发布来源证明。

### 2. Cairn 自主智能体在真实攻击中发现并利用 MONAI Label 零日

AWS 披露，攻击者把暴露在公网且无认证的 Cairn 平台用于针对东亚大学的入侵。智能体在约 11 分钟内识别 MONAI Label 上传接口的路径遍历并实现任意文件写入，随后通过 `sitecustomize.py` 与训练 API 触发 root 反向 Shell。项目公告确认 0.8.5 及更早版本受影响，漏洞已被在野利用。

**后续进展：** 修复代码已合并，但截至 11 月 22 日截稿，官方 PyPI 与 GitHub Releases 仍显示 0.8.5 为最新可安装版本，GHSA 也未列出正式修复版本。因此不能把“源码已修复”等同于“生产环境已有稳定升级包”。

**影响判断：** 这是“自主 Agent 压缩攻击时间”的具体证据。大学、医疗影像和 GPU 研究环境常把实验服务直接暴露并关闭认证，机器速度的扫描与利用会在人工告警分诊前完成攻击链。

**立即行动：** 从互联网隔离 MONAI Label、启用认证、以非特权用户运行，并检查异常上传、`sitecustomize.py`、训练 API 和外连；正式修复版发布后再验证升级路径。

### 3. Together AI：Coding Agent 误提交凭据，客户提示词样本被下载

Together AI 于 11 月 21 日确认，在公开 `xorl` 仓库开发过程中，一个 AI Coding Agent 提交了可访问私有 Hugging Face 仓库的凭据。自动扫描虽发现并回滚提交，但未授权方已取得凭据并下载部分 Serverless Inference 提示词样本，还在样本中搜索并测试其他服务凭据。样本主要来自 6 月和 7 月对 MiniMax M3、GLM-5.2、Kimi K2.6 的请求；具体客户数、提示词数以及是否包含个人信息仍在审查。

**影响判断：** 这起事件把 Agent 的“错误代码变更”升级为真实数据泄露。公开提交一旦被机器人抓取，删除或回滚不能撤销泄露；提示词中若包含密钥、专有代码或客户数据，还可能形成二次攻击链。

**立即行动：** 相关客户核查上述日期的提示词并轮换其中出现的秘密，启用 ZDR；开发团队应使用短期/无密钥身份，并在本地提交、推送、PR 三层扫描后自动吊销，而非只删除提交。

### 4. MCP 与 Coding Agent 的本地边界失效：Mendix、Junie 两起官方漏洞

Siemens 披露 Mendix Studio Pro MCP Server 的监听接口可能未严格绑定回环地址，且 Origin/Content-Type 校验不足，攻击者可通过网络访问或恶意网页诱导浏览器调用本地 MCP 工具。JetBrains 同期修复 Junie CLI 的项目目录边界绕过，旧版 Agent 文件工具可能修改项目目录以外的文件。

**影响判断：** MCP/Agent 风险不只来自提示注入。端口绑定、CSRF、文件路径和工具权限等传统应用安全控制，同样决定 Agent 是否能被远程驱动或越权写入 SSH 配置、Shell 启动项、其他仓库和凭据文件。

**立即行动：** Mendix 升级至官方修复分支并限制 7782 端口；Junie CLI 升级至 26.6.29 及以上；所有 Agent 在低权限、受限工作区运行，高影响操作要求人工确认。

### 5. CISA KEV 连续扩展：AI 网关与企业控制面均出现确认在野利用

11 月 18 日，CISA 将 LiteLLM、Apache Axis、REDCap 和 Synology DSM/BSM 漏洞加入 KEV。LiteLLM 的自定义代码测试端点可被用于逃逸 Python 沙箱并在代理进程执行代码。11 月 20 日，CISA 又将 VMware vCenter、Cisco Expressway、SAP NetWeaver 和 Apache Roller 漏洞列入 KEV；其中 vCenter 认证绕过从“厂商披露的高危漏洞”升级为“确认在野利用”。

**影响判断：** 这些产品横跨 AI 网关、虚拟化、远程访问、医疗研究和遗留企业应用，且多位于身份、管理或集成控制平面。补丁优先级应由 KEV 状态和实际可达性决定，而非只看 CVSS。

**立即行动：** 优先处置互联网暴露和管理网可达实例；LiteLLM 至少升级至 1.83.11，vCenter 按 VMSA-2026-0009 更新；对已暴露资产执行入侵排查和凭据轮换，不能只补版本。

### 6. Java4Shell 与 NGINX：通用运行时和入口组件出现高影响更新

CISA 要求立即修补 Oracle Java Base64 解码器漏洞 CVE-2026-114938。该漏洞可能造成未认证远程代码执行，且 Java 常被隐藏在容器、商业软件和设备内。NGINX 同期发布 1.30.7 和 1.31.9，修复 HTTP/2、HTTP/3、resolver、邮件代理等多项内存安全问题，部分条件下可能导致远程代码执行。

**影响判断：** 两者都属于“资产清单看不见、实际调用很广”的底层组件。云平台临时缓解、宿主机升级或代码仓库里的声明版本，都不能证明容器、Sidecar、商业产品和运行中进程已经安全。

**立即行动：** 以实际二进制、镜像摘要和进程为准盘点；更新后替换旧 Pod/worker；向第三方产品供应商确认内嵌 Java 与 NGINX 的修复状态。

### 7. ScreenConnect 出现“从客户终端反向感染技术人员工作站”的传播链

ConnectWise 调查确认，攻击者在取得初始访问后使用工具包，尝试从受控客户终端向连接中的技术人员工作站传播，并利用与 CVE-2026-84869 相关的客户端文件传输/执行条件。26.6.5 及以上客户端可阻断该传播方式，但升级与禁用扩展不能清除既有持久化。

**影响判断：** 远程管理平台的信任方向被反转：单个客户终端可能成为进入技术人员设备、MSP 以及更多客户环境的跳板。

**立即行动：** 禁用相关 RMM 扩展，逐台验证技术人员客户端版本，注销会话并检查额外 ScreenConnect 客户端、静默脚本、空访问密钥及异常登录。

### 8. Optimizely 与 PLAID：SaaS 管理权限成为下游攻击通道

Optimizely Web Experimentation 的注册流程缺陷被用于冒充客户管理员，并向部分客户网站下发支付卡窃取 JavaScript。日本客户体验平台 KARTE 则因服务器漏洞泄露 79,249 个账户邮箱、外部集成 Secret Key/Access Token 和部分客户导入数据，具体字段仍在调查。

**影响判断：** 两起事件共同说明，营销、实验和客户数据平台不是“低风险外围 SaaS”。它们能在浏览器中执行脚本，或持有连接 CRM、数据仓库和第三方服务的长期凭据，因此一个供应商事件可能跨越多个客户和数据域。

**立即行动：** 对前端第三方脚本实施 CSP、变更监控与敏感页面隔离；在凭据签发方撤销 SaaS 集成密钥，审计下游服务的异常读取和配置变更。

### 9. Microsoft Entra Connect Health 元数据遭未授权读取

Microsoft 确认 Entra Connect Health API 漏洞被利用，部分租户的技术联系人和管理员邮箱、Tenant ID、初始域名、许可层级、目录同步状态等元数据遭只读访问。公司已于 11 月 19 日完成服务端修复，未发现配置被修改，也未发现密码、令牌、有效密钥或本地 AD 拓扑泄露；受影响租户数尚未公布。

**影响判断：** 元数据不等于认证秘密，但可用于识别高权限人员、组织域名和混合身份状态，显著提高钓鱼、帮助台冒充和账户恢复诈骗的可信度。

**立即行动：** 受影响组织直接在 Azure Service Health 核验通知，强化管理员抗钓鱼 MFA/PIM，并审查 Entra 审计、登录与 Azure Activity 日志。

### 10. 关键基础设施：Equinor IT 攻击与 Elecbrakes 物理制动风险

挪威能源企业 Equinor 确认部分 IT 系统遭网络攻击；截至本周更新，生产未受影响、暂无数据被盗迹象，调查和恢复仍在继续。CISA 同期披露 Elecbrakes EB2、VM1、ELBC2000 的三项漏洞，近距离攻击者可能控制拖车制动、修改固件或关闭制动灯；EB2 与 VM1 已有固件更新，旧款 ELBC2000 尚无修复。

**影响判断：** 两起事件分别体现 IT/OT 边界和联网设备的物理后果。没有生产中断不等于没有横向风险；蓝牙攻击范围有限也不等于可以忽略车队基地、维修点和停放场景。

**立即行动：** 能源企业复核 IT/OT 分段与跨域身份；Elecbrakes 用户升级 EB2 至 3.0.4.4.3、VM1 至 1.3.4.2.1，并评估停用或替换 ELBC2000。

## 主要趋势

### 1. Agent 安全已经跨越模型层

本周事件覆盖恶意包、MCP 本地服务、文件工具边界、公开仓库凭据和自主攻击框架。真正的控制点是身份、文件系统、网络、工具权限和数据保留，而不是单纯依赖模型拒绝危险请求。

### 2. “被发现并删除”不等于风险消失

Together AI 的提交已回滚、Agent Framework 恶意版本已下架、ScreenConnect 扩展可禁用，但凭据可能已被复制，恶意包可能进入缓存，攻击者也可能已建立持久化。处置必须包含吊销、重建、取证和下游审计。

### 3. 高权限中间层持续成为放大器

LiteLLM、vCenter、ScreenConnect、Optimizely、KARTE 和 Entra Connect Health 都处在多个系统之间。一旦中间层失守，影响会沿模型 API、虚拟化、远程运维、浏览器脚本、数据集成或身份元数据扩散。

### 4. 稳定发行与源码修复之间存在危险空窗

MONAI Label 的修复已进入源码，但稳定安装包未同步确认；企业若只看仓库主分支可能误判已经安全。SBOM 和补丁流程必须记录“实际部署制品”，而不是只记录上游修复提交。

## 对开发者与企业的实际影响

- **开发者与 AI 团队：** Coding Agent 需要独立的短期身份、目录沙箱、出站控制和高风险操作审批；提示词与测试样本不能默认视为非敏感数据。
- **平台与 DevSecOps：** 锁文件、缓存、内部镜像、Runner 和容器层都必须进入供应链取证；仅检查当前依赖列表会漏掉已删除版本。
- **SOC 与事件响应：** Agent 驱动攻击可能在十余分钟内完成侦察、利用和持久化，应把高置信度检测的自动隔离与凭据吊销纳入预案。
- **企业架构与采购：** SaaS、MCP、RMM、AI 网关和第三方脚本应按高权限集成管理，合同中明确日志、凭据生命周期、事件通知和数据保留要求。
- **OT 与关键基础设施：** IT 未停产、攻击需近距离或厂商暂无在野报告，都不能替代资产隔离、补丁验证和物理安全控制。
