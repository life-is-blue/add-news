## 今日要点

### 1. 官方 MCP Git Server 可被恶意仓库配置触发任意命令执行

- **分类：** MCP / Coding Agent / 软件供应链
- **严重度：** 高
- **发布日期：** 2026-11-11（过去24小时）
- **可信度：** 官方确认（Model Context Protocol 项目安全公告）
- **影响对象：** 使用 `mcp-server-git` 2026.11.11 之前版本分析不可信或来源不明 Git 仓库的开发者、Coding Agent 和自动化环境
- **事实摘要：** GHSA-6hqx-gqrx-c5r2 显示，恶意仓库可通过自身 Git 配置（例如 `core.fsmonitor`）使 Git 在 MCP Server 执行看似只读的 `git_status` 等操作时启动外部程序，从而以 MCP 服务进程身份执行任意命令。风险不只来自 `core.fsmonitor`，还包括钩子、过滤器、合并/差异驱动、分页器及子模块相关配置。受影响版本为 `mcp-server-git < 2026.11.11`，修复版为 2026.11.11；修复版还拒绝使用无法可靠覆盖危险配置的 Git 2.31 之前版本。官方未报告在野利用。
- **值得关注的原因：** “只读仓库检查”通常被视为低风险，但 Git 配置本身可携带可执行行为。Coding Agent 自动克隆并分析外部仓库时，代码尚未构建或运行就可能触发主机级命令执行。
- **建议行动：**
  1. 将 `mcp-server-git` 升级至 2026.11.11 或更高版本，并确认底层 Git 版本不低于 2.31。
  2. 对分析外部仓库的 Agent 使用一次性容器、只读挂载、无长期凭据身份及默认拒绝的出站网络策略。
  3. 检查近期处理过的不可信仓库及其 `.git/config`、hooks、filter、merge、diff、pager、submodule 配置。
  4. 若旧版服务在持有代码仓库令牌、SSH 密钥或云凭据的主机上运行，应审查子进程、出站连接和凭据使用记录。
- **原始链接：**
  - [项目安全公告 GHSA-6hqx-gqrx-c5r2](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-6hqx-gqrx-c5r2)
  - [修复版本发布记录](https://github.com/modelcontextprotocol/servers/releases/tag/2026.11.11)

### 2. AWS MCP Gateway Registry 披露管理员提权与内网 SSRF 两项漏洞

- **分类：** MCP 基础设施 / 权限提升 / SSRF
- **严重度：** 高
- **发布日期：** 2026-11-12（北京时间；AWS 于11月11日 PST 发布）
- **可信度：** 官方确认（两份 AWS Security Bulletin）
- **影响对象：** 自行部署 `mcp-gateway-registry` 的组织；尤其是允许低权限账户访问管理 API 或允许用户注册/修改上游 MCP Server 的环境
- **事实摘要：** CVE-2026-100307 影响 1.0.9—1.24.7：`/api/servers/*` 管理端点只验证登录身份，却未执行角色或权限授权，低权限远程用户可提交恶意组导入请求，将自己的身份提供商组映射到注册表管理员，进而控制所有已注册网关资产；1.25.0 修复。CVE-2026-125926 影响 1.0.3—1.34.0：有权注册或修改 Server 的用户可设置恶意上游地址，让网关请求部署内网服务，部分情况下响应还会返回给攻击者；1.35.0 修复。AWS 强调升级不会自动清除旧版已写入的恶意组映射或上游配置。未见官方确认的在野利用。
- **值得关注的原因：** MCP Registry 集中管理工具发现、访问控制与代理。管理员提权可篡改整个工具目录；SSRF 则把网关变成访问内网与云元数据的跳板，两者都可能把单一低权限账户问题扩大为多 Agent、多工具的信任链失陷。
- **建议行动：**
  1. 统一升级至 `mcp-gateway-registry 1.35.0` 或更高版本，并同步修补 fork。
  2. 升级后审计 `mcp_scopes` 中的 `group_mappings`、`ui_permissions`，清除异常管理员映射并撤销可能泄露的凭据。
  3. 复核所有 Server/Agent 的新增、修改、启停和删除记录，重点检查上游 URL 是否指向内网、环回、链路本地或云元数据地址。
  4. 在出口代理层阻断敏感地址段，限制管理 API 仅供可信管理员访问，并为注册/修改上游引入独立审批。
- **原始链接：**
  - [AWS 2026-179：CVE-2026-100307](https://aws.amazon.com/security/security-bulletins/2026-179-aws/)
  - [AWS 2026-180：CVE-2026-125926](https://aws.amazon.com/security/security-bulletins/2026-180-aws/)

### 3. Maersk 确认一套并购遗留系统遭未授权访问并发生数据提取

- **分类：** 重大企业事件 / 物流关键链路 / 数据泄露
- **严重度：** 高
- **发布日期：** 2026-11-11（过去24小时）
- **可信度：** 官方确认（Maersk 公告；数据内容与影响仍在调查）
- **影响对象：** Maersk 一项此前收购业务的本地遗留系统及其中数据；目前没有证据表明其他 Maersk 系统、客户平台、API 或 EDI 集成受影响
- **事实摘要：** Maersk 确认，攻击者未授权访问并从一套本地遗留系统提取数据。公司已隔离事件并开展调查，目前判断没有敏感数据被披露，也未发现其他 Maersk 系统或客户、合作伙伴集成受影响，预计不会造成运营中断。官方尚未说明被提取的数据类型、数量、入侵时间或攻击方式；任何勒索团伙关于数据规模或赎金的单方面说法均不作为已确认事实。
- **值得关注的原因：** Maersk 是全球物流链的重要节点。即使事件被限制在遗留系统，已确认的数据提取仍可能带来供应商冒充、定向钓鱼和商业信息滥用风险，也再次说明并购遗留资产是长期攻击面。
- **建议行动：**
  1. Maersk 客户与合作伙伴应通过既有联系人核验任何声称与事件相关的邮件、付款或账户变更请求。
  2. 使用 API/EDI 集成的企业继续监测异常认证和数据交换，但在没有证据前不要假定集成接口已被攻破。
  3. 企业应把并购遗留系统纳入统一资产、身份、日志和数据分级治理，缩短独立旧环境的存续期。
  4. 关注 Maersk 后续公告；在数据类型确认前，避免传播攻击者未经验证的数据量或敏感性主张。
- **原始链接：**
  - [Maersk 官方事件公告](https://www.maersk.com/news/articles/2026/11/11/it-security-incident)

### 4. Chrome Extended Stable 一次修复72项漏洞，其中4项为严重级别

- **分类：** 浏览器 / 大规模安全更新 / 终端安全
- **严重度：** 严重
- **发布日期：** 2026-11-11（过去24小时）
- **可信度：** 官方确认（Chrome Releases）
- **影响对象：** Windows 和 macOS 上使用 Chrome Extended Stable 通道、版本低于 156.0.8078.100 的终端
- **事实摘要：** Google 将 Extended Stable 更新至 156.0.8078.100，包含72项安全修复，其中 CVE-2026-126879、CVE-2026-126885、CVE-2026-126895 和 CVE-2026-126911 被标为严重，另有大量高危漏洞。Google 暂时限制多数漏洞细节，公告未表示这些新列出的漏洞已被在野利用；因此不能把本次更新等同于新增零日攻击确认。
- **值得关注的原因：** Extended Stable 常用于企业环境，升级节奏较慢且终端规模大。一次集中修复72项问题意味着延迟部署会累积多类浏览器攻击面，严重漏洞尤其应优先处理。
- **建议行动：**
  1. 将 Extended Stable 更新至 156.0.8078.100 或更高版本并重启浏览器。
  2. 通过企业浏览器管理工具核查实际生效版本，而非只确认更新策略已下发。
  3. 优先更新可访问管理后台、源代码、财务和敏感 SaaS 的终端。
  4. 关注 Chromium 下游浏览器的独立公告；不要假设 Chrome Extended Stable 更新自动覆盖其他产品。
- **原始链接：**
  - [Chrome Extended Stable 官方公告](https://chromereleases.googleblog.com/2026/11/extended-stable-update-for-desktop_01570615041.html)

## 结论

本期最直接的开发者风险来自 `mcp-server-git`：不可信仓库的 Git 配置可在“只读”分析阶段触发命令执行。AWS 两项公告则说明，MCP 网关升级后仍需清理旧版留下的权限与上游配置，不能只看版本号。企业终端应同步完成 Chrome Extended Stable 更新；物流与供应链参与者则应防范借 Maersk 事件实施的冒充和钓鱼。
